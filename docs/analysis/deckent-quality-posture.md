## Quality-Risk Ranking (grounded in the numbers above)

1. **Full suite is not a usable gate (~60 pre-existing failures).** Verification policy is
   targeted-tests-only (documented, Sprint 257), so a regression in any of the other
   ~1,300 untouched files' subject areas can land unnoticed between hygiene batches.
   Largest systemic risk despite being only ~0.28% of 21,131 descriptors.
2. **13 unguarded local-state readers (~1.0% of test files).** Each can flip CI red on a
   fresh checkout (`test:ci-sim` reproduces); 4 of them also read `.brain/memory.db`. The
   guard pattern exists (81 `skipIf` uses) — adoption, not invention, is the gap.
3. **Live-env coupling in provider tests.** 50 files mention `ollama`, ≥10 reference a real
   endpoint/binary; 2 of the 5 documented failure clusters (provider-bootstrap, doctor
   diagnostics) are live-env class. Provider matrix growth (8-fleet, ADR-077/078) multiplies
   this surface.
4. **Stale-assertion drift outpaces maintenance.** 6 files still assert retired `gpt-5.5`
   apiIds after the 260-014 fix, plus the 32-descriptor error-registry-lint snapshot —
   catalog/registry churn keeps re-breaking assertions that encode point-in-time state.
5. **Thin E2E layer + flaky interactive CLI tests.** e2e + integration = 57 files (4.3%)
   versus 62.9% unit mass in 3 directories; meanwhile `commands.test.ts` (104 descriptors)
   carries known 10s readline timeouts, and 37 skipped tests (34 `it.skip` + 3
   `describe.skip`) quietly shrink the effective gate.
