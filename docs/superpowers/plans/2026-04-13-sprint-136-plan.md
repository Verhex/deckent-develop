## Task 4: Execution Launch + 3-Layer Monitoring Setup

**Amaç:** Sprint 136 execution'ını başlat + 3-layer monitoring aktif et.

**Files:**
- Read (real-time): `.tasks/task-136-NNN.hb`, `.tasks/task-136-NNN.result`, `.deckent/metrics.jsonl`
- Watch: `deckent_status` MCP resource

- [ ] **Step 1: Layer 1 — Verifier background loop başlat**

Ana session'da `run_in_background=true` ile sürekli tsc + vitest loop:

```bash
while true; do
  echo "=== $(date '+%H:%M:%S') ===" >> /tmp/sprint-136-verify.log
  npx tsc --noEmit 2>&1 | tail -5 >> /tmp/sprint-136-verify.log
  npx vitest run --reporter=basic 2>&1 | tail -5 >> /tmp/sprint-136-verify.log
  sleep 180
done
```

Run: `Bash` tool with `run_in_background: true`

Not: Bu loop 3 dakikada bir koşar, 6 saatlik sprint'te ~120 iterasyon. Her iterasyon 90-120 saniye, overhead kabul edilebilir.

- [ ] **Step 2: Layer 2 — Watchdog Explore subagent dispatch**

`Agent` tool ile `subagent_type=Explore` dispatch, 40-cycle polling watchdog:

```
Prompt:
"Sprint 136 execution monitoring watchdog. 40 cycle polling, her döngü:
1. Read .deckent/sprint-136.pid (var mı?)
2. Run `deckent_status` MCP tool, status JSON'ını yaz
3. Run `git status --short | head -10`, değişen dosya sayısını kaydet
4. Run `ls .tasks/task-136-*.hb 2>/dev/null | wc -l`, active worker sayısı
5. Run `tail -3 .deckent/metrics.jsonl`, son 3 metric event
6. Eğer alert: worker >2dk stale, lock >5dk, phase > expected → raporla
7. Sleep 90 saniye (subagent leading sleep yasak, ama iterasyon arası OK)

40 cycle * 90s = 60 dk. Timeout'a ulaşırsa bitirebilirsin, ana session başka watchdog spawn eder.
Ana session'a her critical alert'te raporla; normal status 10 cycle'da 1 özet.
Rapor Türkçe, <200 kelime per cycle."
```

Run: `Agent` tool (background=false, ana session akışında wait eder ama ilk raporda ilerler)

**Not:** Eğer `Agent` tool background subagent desteği varsa background=true; yoksa subagent döngü sonu tek batch rapor döner, bu sırada ana session Layer 3 ve Shell Watchdog koşar.
