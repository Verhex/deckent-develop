## Top-3 Governance Wins (357–364)

**1. The "466-family" timeout/exit-marker parity ratchet — one fix pattern propagated across three
independent execution backends and then generalized into a lint-enforced convention.**
`born-466` (a docker-backend fix predating this series, `\|\| echo WORKER_TIMEOUT`-style exit-marker
handling) was ported to the tmux backend in `359-003` (TMUX-TIMEOUT-PARITY): "tmux.ts:150 aynı
`\|\| echo WORKER_TIMEOUT` deseni — docker'daki born-466 fix'inin paritesi" — landed `GO_WITH_TECH_DEBT`
with matching `selfAssessment`/`brainEvaluation` (honest, not silently downgraded). Sprint 360 then ran an
**independent second-opinion audit** of both backends post-fix (`360-015`/`360-015-fix`,
CODEX-DOGFOOD-B → `docs/analysis/wrapper-posix-audit-360.md`), explicitly scoped to verify "born-466/467/473
fix'lerinin doğrulaması," both resolving `DONE`. By sprint 362 the same fix-then-verify shape had matured into
a *general enforcement mechanism*: `362-012` (D004-SHIM-REGISTRY) builds a ratchet lint (`lint-layer-shims.mjs`)
for ADR-D-004 layer-crossing exceptions explicitly modeled on this precedent — "kayıtlı-crossing OK,
kayıtsız-yeni-crossing FAIL (ratchet-deseni; **466-emsali**)" — resolving `DONE`. Evidence: a point-fix
(`359-003`) generalized into cross-backend parity, then an independent audit (`360-015`), then a reusable
governance primitive citing it by name (`362-012`).

**2. The "honest-DEBT ceiling" (EVAL-DEBT-CEILING) — three successive evaluator fast-path bypasses closed
across the series, culminating in a same-sprint hand-fix.** The evaluator (`result-evaluator.ts`) has
multiple fast paths that can short-circuit straight to `DONE` without applying the full rubric — a real risk
because a fast path can silently *override* a worker's own honest `GO_WITH_TECH_DEBT` self-assessment. The
sprint-364 commit (`874c7b6b`) closes the third and final known bypass, with the commit message itself
naming the lineage: "CC el-fix born-482: dürüst-DEBT tavanının 3. bypass'ı (`isVerificationTask`+
`isDocTask` fast-path'leri) kapatıldı + regresyon — **born-450/459/482 ailesi TAM**." The concrete diff
(`src/orchestra/result-evaluator.ts`) changes both `isDocTask` and `isVerificationTask` fast paths from an
unconditional `return DONE` to `result.selfAssessment === 'GO_WITH_TECH_DEBT' ? GO_WITH_TECH_DEBT : DONE`,
with an inline comment marking it "third bypass variant of EVAL-DEBT-CEILING after ladder+rubric." A
companion `debt-manager.ts` fix in the same commit adds an honest `timeout-partial` debt classification
(distinct from `standard`) so a killed-mid-execution worker's reconciled partial diff is no longer
mis-recorded as a generic tech-debt note that would otherwise respawn a no-op fix task every sprint. Evidence:
this is the rare case where the fix is verifiable directly in `git show 874c7b6b -- src/orchestra/result-evaluator.ts`
against the code comment naming its own place in a 3-generation bypass-closure lineage.

**3. Dependency-ref normalization (`born-465`) — landed honestly as tech debt, then wired to closure
within the same sprint instead of leaking into the next one.** `359-001` (DEP-NORMALIZE) added
`normalizeStructuredTaskDependencies` to `task-builder.ts`, fixing `born-465` (three runtime layers handling
unresolved dependency refs three different ways: wave-path resolves, scheduler drops, `planContinuous` hangs
forever). The worker self-declared `GO_WITH_TECH_DEBT` and named the exact gap in its own notes: the new
function existed and was unit-proven (10 new tests + 3 pre-existing suites green, `tsc` clean) but its call
site — `sprint-planner.ts`'s structured-plan branch — was outside the task's write scope, so it was not yet
invoked from the real disk-write path. Rather than this debt surfacing as a follow-up task in sprint 360 or
later (the more common pattern per `worker-quality-357-359.md` §4's "planning-side root cause" finding), the
same sprint-359 commit (`06947b09`, confirmed via `git log -S "normalizeStructuredTaskDependencies(tasks)"`)
closes the loop with a hand-wired call to `normalizeStructuredTaskDependencies(tasks)` in
`sprint-planner.ts`, which remains in place in the current tree. Evidence: the fix is *disk-verifiable today*
— `src/orchestra/sprint-planner.ts` imports and calls `normalizeStructuredTaskDependencies` — closing a debt
inside its own sprint rather than letting it decay into the next one's backlog.
