## What this report is

`scripts/beta-launch-precheck.mjs` is a single-shot pre-flight check that audits every gate in
[`beta-tracker.md`](../archive/beta-tracker.md) and prints a PASS / FAIL / WARN table. It is intended to
run on each of the four packaging days (28-31 May 2026) immediately before `npm pack` so any
late regression in the 20-gate matrix is caught before the GA tag.

The script is intentionally cheap: only `tsc`, `vitest`, `npm pack`, and `deckent --help / help`
spawn real processes (each with a bounded timeout). Static milestones (cross-platform smoke,
Sprint 148 multi-provider, Sprint 150A `deckent_style`, …) are emitted as PASS with a tracked
source reference rather than being re-run, because re-running them would not change the result
in the four-day window and would waste subscription quota.

---

## Usage

```bash
# Full pre-check (human table)
node scripts/beta-launch-precheck.mjs

# Machine-readable
node scripts/beta-launch-precheck.mjs --json

# Internal parser sanity (no spawns — safe inside a sprint)
node scripts/beta-launch-precheck.mjs --self-test

# Run against a different checkout
node scripts/beta-launch-precheck.mjs --root /path/to/deckent
```

Exit codes:

| Code | Meaning |
|------|---------|
| 0    | All required gates PASS or WARN (WARN does not block) |
| 1    | At least one required gate FAIL — investigate before publish |
| 2    | Script itself crashed (filesystem / spawn error) |

## Self-test guarantee

Re-runs the parsing helpers in isolation (no spawn, no filesystem mutation):

```bash
node scripts/beta-launch-precheck.mjs --self-test
```

Asserts:

1. `parseVitestOutput` extracts passed/failed/ratio from the standard reporter line.
2. `parseHelpToolCount` deduplicates `deckent_*` tokens and returns 0 on empty input.
3. `parseCliCommandCount` recognises commander.js indented command lists.
4. `parseAcceptedAdrCount` counts only `**Status:** accepted` markers (skips proposed/deprecated).
5. `parseCriticalHighDebt` walks only the *Active* debt table (ignores Resolved rows).
6. `staticGate` returns `status: 'PASS'` and preserves `required`.

Exit 0 = all parsers behave as documented. Exit 1 = a parser regressed; **do not publish until
the self-test is green**.

## How to refresh this report

1. Land all Sprint 198 wave-0/1 tasks.
2. Re-run `node scripts/beta-launch-precheck.mjs --json > .deckent/precheck-<date>.json`.
3. Diff the new JSON against the table above; flip any gate whose state changed.
4. Update the **Status** line in the snapshot section.
5. Commit on the same branch as the underlying gate fixes — do not rebase this report
   away from its supporting evidence.

The script is idempotent and side-effect free outside of `--json` stdout, so it is safe to
run repeatedly inside a live sprint.
