## Root Cause: RC-C (Path Normalization Gap)

`detectScopeCollisions` (conflict-resolver.ts:173) compares `scope.filesWrite` entries
with `file.trim()` — string equality after whitespace trim. It fails to recognize that
the following entries refer to the same logical file:

| Variant A             | Variant B                | Currently treated as |
|----------------------|--------------------------|----------------------|
| `src/foo.ts`         | `./src/foo.ts`           | Different (BUG)      |
| `src/foo.ts`         | `src//foo.ts`            | Different (BUG)      |
| `src/foo.ts`         | `src/foo.ts/` *(trailing)* | Different (BUG)    |
| `src/foo.ts`         | `  src/foo.ts  `           | Same (handled by trim) |

Equivalence classes that should collide are split into separate keys in `fileWriters`,
each with `length === 1`, so none meet the `>= 2` threshold. The result: PENDING tasks
that *do* write the same file proceed to spawn → runtime lock contention, last-writer-
wins corruption, regressions observed in Sprint 167 retro.

### Why Sprint 169 Events Still Emitted BLOCKED

Both 169-003 and 169-004 declared the file under *both* variant strings
(`src/core/memory-store.ts` + `memory-store.ts`). Each variant accumulated 2 writers,
hitting the threshold *twice*. The block fired by accident — duplicate variants masked
the underlying bug. Tasks that declare only one variant per side (the realistic case)
silently pass through.

### Five Whys

1. Why did Sprint 168 smoke spawn collide-at-runtime? → `detectScopeCollisions` did not
   detect the plan-time collision.
2. Why? → The two task entries used different path strings for the same file.
3. Why does `detectScopeCollisions` not normalize? → It calls `file.trim()` only.
4. Why is that not enough? → JavaScript string `===` cannot recognize `./a/b` and `a/b`
   as the same path; this is a domain-specific equivalence that the comparator must
   enforce.
5. Why was this missed at design time? → `normalizeScopePath` exists in `sprint-spawner.ts`
   for `buildAllowedWriteTargets`, but it serves a different purpose (rejecting bare
   extensions / ADR-013 paths) and is not applied before collision detection.

## Fix Proposal — Minimal, Targeted

### Change 1 — Add `normalizeScopeFiles` helper to `sprint-spawner.ts`

Pure, exported, idempotent. Used by collision detection (and available for any future
consumer that needs path equivalence).

```ts
// src/orchestra/sprint-spawner.ts
export function normalizeScopeFiles(files: readonly string[]): string[] {
  const out: string[] = [];
  for (const raw of files) {
    const trimmed = raw.trim();
    if (!trimmed) continue;
    let p = trimmed.replace(/^\.\//, '');   // strip leading ./
    p = p.replace(/\/{2,}/g, '/');           // collapse double slashes
    p = p.replace(/\/$/, '');                 // strip trailing slash
    if (!p) continue;
    out.push(p);
  }
  return out;
}
```

### Change 2 — Wire into `spawnWorkers` collision pre-pass

Before invoking `detectScopeCollisions`, deep-clone the pending tasks with normalized
`scope.filesWrite`. We do *not* mutate the originals (they may be written back to
`task.json` later by other wires).

```ts
// src/orchestra/sprint-spawner.ts (spawnWorkers)
const pendingTasks = sprint.tasks.filter(t => t.status === TaskStatus.PENDING);
const pendingTasksNormalized = pendingTasks.map(t => ({
  ...t,
  scope: { ...t.scope, filesWrite: normalizeScopeFiles(t.scope?.filesWrite ?? []) },
}));
const collisionResult = detectScopeCollisions(pendingTasksNormalized);
```

### Why Not Touch `conflict-resolver.ts`

Task scope explicitly restricts writes to `sprint-spawner.ts`, `decision-engine.ts`,
and the new test file. `conflict-resolver.ts` is out-of-scope. Pre-normalizing at the
call site is equally correct and keeps `detectScopeCollisions` as a pure
string-compare primitive (its current contract).
