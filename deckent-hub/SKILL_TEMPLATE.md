# Skill Template — Deckent Hub

Use this template when creating a new skill for Deckent Hub. This is a single reference
document — create `skills/<your-skill-name>/` yourself (`mkdir -p`), author the files
below following these templates, and fill in the placeholders.

> **Schema status (HUB-P0):** this template defines the TARGET public-marketplace
> manifest schema (`author`, `tags`, `secrets`, `scope`, `deckentVersionMin`, `license`).
> The 20 existing catalog manifests still use deckent's internal `SkillDefinition`
> shape and will be migrated to this schema as part of HUB-P0 — new submissions
> should follow THIS template, plus the required `entrypoint` field.

## Directory Structure

```
skills/
  my-skill/
    SKILL.md          ← This file (skill definition — required)
    manifest.json     ← Skill metadata (required)
    signature.ed25519 ← Ed25519 signature (generated by deckent skill publish)
    README.md         ← User-facing documentation (optional but recommended)
    examples/         ← Usage examples (optional)
      basic.md
```

## SKILL.md Template

Create `skills/<your-skill>/SKILL.md` with the following content:

```markdown
# Skill: <Skill Name>

## Trigger Patterns
<!-- List the phrases / keywords that activate this skill -->
- "check spotify"
- "play song on spotify"
- "what's playing"
- "pause music"

## Capabilities
<!-- What this skill enables a Deckent worker to do -->
- Control Spotify playback (play, pause, skip, volume)
- Search for tracks, albums, artists
- Manage playlists (create, add tracks, list)
- Get current playing track info

## Required Secrets (.deck)
<!-- List secrets the user must configure in their .deck file -->
| Secret Key | Description | How to Get |
|-----------|-------------|------------|
| `SPOTIFY_CLIENT_ID` | Spotify app client ID | https://developer.spotify.com/dashboard |
| `SPOTIFY_CLIENT_SECRET` | Spotify app client secret | Same dashboard |
| `SPOTIFY_REFRESH_TOKEN` | OAuth refresh token | Run `deckent skill setup spotify-control` |

## Dependencies
<!-- npm packages this skill requires — will be installed by deckent -->
- `spotify-web-api-node@^5.0.0`

## Environment Variables
<!-- Any env vars the skill reads at runtime -->
| Variable | Source | Description |
|----------|--------|-------------|
| `SPOTIFY_CLIENT_ID` | `.deck` via `$DECK:SPOTIFY_CLIENT_ID` | OAuth client ID |
| `SPOTIFY_CLIENT_SECRET` | `.deck` via `$DECK:SPOTIFY_CLIENT_SECRET` | OAuth client secret |

## Scope Declaration
<!-- File system and network access this skill requires -->
shell-commands: false
network-domains:
  - api.spotify.com
  - accounts.spotify.com
file-read: []
file-write: []

## Example Prompts
<!-- Show how a user would invoke this skill via Deckent -->

### Example 1: Get current track
```
User: What's playing on Spotify?
Deckent: [uses spotify-control skill] Currently playing: "Song Name" by Artist — 2:34 / 3:45
```

### Example 2: Queue a song
```
User: Queue "Bohemian Rhapsody" on Spotify
Deckent: [uses spotify-control skill] Added "Bohemian Rhapsody" by Queen to queue.
```

## Error Handling
<!-- Common errors and how this skill handles them -->
| Error | Cause | Resolution |
|-------|-------|------------|
| `SPOTIFY_NOT_AUTHENTICATED` | No valid refresh token | Run `deckent skill setup spotify-control` |
| `SPOTIFY_NO_ACTIVE_DEVICE` | No Spotify client open | Open Spotify on any device first |
| `SPOTIFY_RATE_LIMITED` | Too many requests | Skill auto-retries with backoff |
```

## manifest.json Template

Create `skills/<your-skill>/manifest.json`:

```json
{
  "manifestVersion": 2,
  "id": "your-skill-name",
  "name": "Your Skill Display Name",
  "version": "1.0.0",
  "description": "One-line description of what this skill does",
  "author": {
    "name": "Your Name",
    "email": "you@example.com",
    "github": "your-github-username",
    "publicKey": "ed25519:<your-public-key-hex>"
  },
  "category": "integration | analysis | generation | automation | devops | data | communication | utility",
  "tags": ["tag1", "tag2"],
  "triggers": [
    "keyword1",
    "keyword2"
  ],
  "dependencies": {
    "npm": {
      "package-name": "^1.0.0"
    }
  },
  "secrets": [
    {
      "key": "SECRET_NAME",
      "description": "What this secret is for",
      "required": true
    }
  ],
  "scope": {
    "shellCommands": false,
    "networkDomains": ["api.example.com"],
    "fileRead": [],
    "fileWrite": []
  },
  "deckentVersionMin": "1.0.0-beta.1",
  "license": "MIT"
}
```

## Field Reference

| Field | Required | Description |
|-------|----------|-------------|
| `manifestVersion` | Yes | Always `2` for Deckent Hub skills |
| `id` | Yes | Unique kebab-case identifier (no spaces) |
| `name` | Yes | Human-readable display name |
| `version` | Yes | Semver (start at `1.0.0`) |
| `description` | Yes | One-line description (<100 chars) |
| `author.publicKey` | Yes | Ed25519 public key for signature verification |
| `category` | Yes | One of the listed categories |
| `triggers` | Yes | Keywords that activate this skill (min 2) |
| `scope.shellCommands` | Yes | `true` only if absolutely necessary |
| `scope.networkDomains` | Yes | Explicit domain allowlist (empty = no network) |
| `deckentVersionMin` | Yes | Minimum Deckent version required |

## Publication Checklist

Before submitting your PR, verify:

- [ ] `SKILL.md` has at least 2 trigger patterns
- [ ] `manifest.json` passes schema validation (`deckent skill validate ./skills/my-skill`)
- [ ] All required secrets are documented with setup instructions
- [ ] AST sandbox scan passes (`deckent skill sandbox ./skills/my-skill`)
- [ ] Ed25519 signature generated (`deckent skill publish ./skills/my-skill`)
- [ ] `signature.ed25519` committed alongside the skill files
- [ ] At least one usage example in SKILL.md
- [ ] `README.md` created with user-facing documentation
- [ ] License is MIT or compatible

## Getting Your Ed25519 Keys

On first publish, Deckent generates a keypair automatically:

```bash
deckent skill publish ./skills/my-skill
# Generated keypair at ~/.deckent/keys/
# Public key: ab12cd34ef56... (copy this to your manifest.json author.publicKey)
# Signed: ./skills/my-skill/signature.ed25519
```

Store your private key safely — it is stored at `~/.deckent/keys/private.hex` with `0600` permissions.
