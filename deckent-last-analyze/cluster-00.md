## Findings

- [root-cause|critical] ADR-037 RBAC enforcement is unconditionally soft — `src/orchestra/authority-enforcer.ts:246` — every `checkAuthority` return path hardcodes `mode: 'soft'` and denials emit `level: 'warn'` (representative denied path `:287-292` `{ allowed: false, level: 'warn', mode: 'soft' }`; also `:331-336`, `:393-398`). Header `:5-7` states violations "do NOT block the action". The two live callers — `src/agents/worker.ts:592`+`:606` and `src/monitor/auditor.ts:588`+`:607` — only `console.warn` + `emitAuthorityViolation`, then proceed. The authority matrix is therefore advisory; no path can refuse an action. This is the exact line family that makes the RBAC guarantee soft.

- [root-cause|critical] `enforceAdrCompliance` fails open on any internal error — `src/orchestra/authority-enforcer.ts:654` — the outer `catch` returns `{ pass: true, violations: [] }` with the comment `// Fail-safe: do not block the task` (`:655`). Any throw inside the ADR-006/008/010 scan silently yields a PASS. Combined with its zero live callers (below), the Layer-4 ADR-compliance gate can never produce a NO_GO.

- [unwired|high] `enforceAdrCompliance` has zero production callers — `src/orchestra/authority-enforcer.ts:573` — repo-grep: the only importer is `src/agents/auditor.ts:9` (a bare re-export stub) and `tests/orchestra/layer4-runtime.test.ts`. The live auditor (`src/monitor/auditor.ts:28`) imports only `checkAuthority` + `emitAuthorityViolation`, never `enforceAdrCompliance`. No EVALUATE/verify path invokes it → ADR-006/008/010 worker-output enforcement is dead code. (Cross-checks Phase-1 UNW-036 / UNW-A064 / RC-A034.)

- [dormant|high] `EnforcementMode` `'hard'` value is never produced — `src/orchestra/authority-enforcer.ts:22` (`export type EnforcementMode = 'soft' | 'hard'`) + header `:7` ("Sprint 140+: Hard enforcement (planned)"). Grep of the file shows every `mode:` literal is `'soft'`; no code path ever returns `'hard'`. The entire hard-enforcement half of the type is a planned-but-unlanded knob — dormant since Sprint 139.

- [inconsistent|medium] `normalizeAdrId` collapses `adr-022` and `adr-022-v2` into one key — `src/orchestra/adr-selector.ts:271` (regex `/adr-?0*(\d+)/i` extracts only the first digit-run, dropping the `-v2` suffix → both ids → `'adr-022'`) consumed at `:326-329` (`poolByNormId.set(normalizeAdrId(adr.id), adr)`). Both ids are real seeded ADRs (`src/core/adr-seed.ts:247` `id: 'adr-022'`, `:302` `id: 'adr-022-v2'`). The map is last-write-wins, so an explicit "ADR-022" reference (`extractExplicitAdrRefs:282` → normalize → `'adr-022'` → `poolByNormId.get`) resolves to whichever was inserted last and force-suppresses the other from the scored pool (`:374-375` `!forcedIds.has(normalizeAdrId(adr.id))`). Two distinct ADRs cannot coexist in selection.

Effect: every ADR with `sprint_num > 146` hits `age <= 0 → 0` (no penalty) and the penalty curve is frozen — the age signal is effectively semi-dormant.

Borderline: state files are small JSON.

## Summary
The orchestra#1 cluster is the seam where deckent's two flagship guarantees — ADR-governance (RBAC + ADR-compliance) and the autonomous engine — are wired, and the audit shows both guarantees are deliberately soft at exactly the lines that matter: `checkAuthority` returns `mode:'soft'` on every path (never blocks) and `enforceAdrCompliance` is both unreferenced in production and fail-open, so the entire Layer-4 ADR-006/008/010 gate is dead. The autonomous adapters (action/approval/audit/artifact-ref) and `runAutonomousCycle`/`withNervousObserver` are all genuinely wired (no unwired adapters), contradicting the file's own "skeleton/Sprint-220-pending" header — a documentation-drift signal that the engine matured past its comments. The sharpest latent bug is `normalizeAdrId` collapsing `adr-022`/`adr-022-v2` to one key, which silently makes two distinct seeded ADRs mutually exclusive in prompt injection; the stale `currentSprintNum=146` default freezes the age-penalty signal. Net: deckent enforces architecture by emitting breadcrumbs, not by refusing actions — the "hard-flip post-GA" promised in headers (ADR-037 V1.0 Layer-2, EnforcementMode `'hard'`) has not landed.
