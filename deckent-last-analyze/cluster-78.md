## Summary
This cluster is the `deckent doctor` health-check stack plus a band of small standalone commands (evolve, explain, features, finalize, flow, heartbeat, help, history, image) and the three `init` helper modules (steps/templates/wizard). The small commands are mostly clean and correctly wired into `src/cli/index.ts` (registerEvolve/Image/Flow/Heartbeat/Help/Features all present), and the init helpers' exports (writeProviderConfig, clearStaleCaches, writeI18nFiles, formatWelcomeBanner, formatRecommendations) are all consumed by `init.ts`. The structural rot is concentrated in the doctor subsystem: `doctor-format.ts` is a 359-LoC "God Object Split" extraction that was never wired — the live command keeps inline copies of every function, the two copies have since DIVERGED (the wired doctor.ts gained PSL-6 auth-probe, worker-image and worker-resources rendering that the extracted module lacks), and the only test file covers the dead copy, producing green-but-meaningless coverage. doctor.ts additionally re-defines `runPreFlightHealthCheck`/`PreFlightResult` already living in doctor-checks.ts, and its `formatProviderHealthSection` "legacy fallback" is unreachable because the sole caller always supplies `connectorHealthResults`. The sharpest correctness gap is the Node floor: doctor still passes/READYs Node 18–23 while `package.json` engines and ADR-001 require Node 24+, so the health gate is softer than the install gate. Lower-severity divergences: two `parseSprintLog` parsers, two local TR/EN i18n tables bypassing `getMessage` (one self-flagged as deferred debt), a banned `spawnSync` on the async init path (ADR-087), a silent pre-flight fallback, and perpetually-empty token/call history columns. No findings required source edits — this is a read-only audit.
