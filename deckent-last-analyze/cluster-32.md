## Summary
core#10 exposes deckent's recurring pattern of **fully-built-but-unwired infrastructure**: an entire `global-config.ts` module duplicated by config.ts, a worker-time O_EXCL lock API whose acquire/check half is never called, an instrumented `claimTaskLock` whose `lock.wait` metric is therefore always silent, and several symmetric helpers (checkSpawnLock, releaseSpawnLocks, FlowRegistry.forCurrentTenant, PRE_EXECUTION_STATUSES) added for completeness but never consumed. Two correctness hazards stand out: the flow RBAC gate is dormant because `role` is an optional argument that no caller passes (permission checks never execute), and the event-trigger dispatch path is dead because the only runtime tick hardcodes empty trigger/event arrays. A name-collision (`suggestMaxWorkers` defined twice in core/ with divergent signatures) and divergent config-merge semantics round out the maintenance risk — the live behavior is correct, but the parallel dead copies are a trap for the next editor.
