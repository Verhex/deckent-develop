Code-only audit. Each finding carries `file:line` + proving-snippet. Zero-caller claims grep-verified across `src/**` (def + test excluded). Source unchanged (read-only).

## Findings

- [unwired|none] No zero-caller public export in this cluster — `src/agent/session.ts:48`, `src/agent/tools/registry.ts:13`, `src/agent/tools/types.ts:36`, `src/agent/trace-recorder.ts:35`, `src/agent/transcript.ts:10` — grep-proven consumers: `createAgentSession`→`src/cli/repl/native-agent-bridge.ts` + `tests/agent/session.test.ts`; `ToolRegistry.toNativeSchemas`→`src/agent/loop.ts:74`; `validateToolDefinition`→`src/agent/tools/registry.ts:18`; `toTrainingExample`/`appendTrace`→`src/cli/repl/trace-wire.ts:24`; `Transcript`→`src/agent/loop.ts:117,153`+`session.ts:49`; type exports `TraceMeta`/`OpenAiMessage`/`TrainingExample`→`src/training/cc-trace-extractor.ts:8` — every surface is wired; nothing dormant-by-zero-caller. (Negative finding, reported for completeness.)

- [dormant|medium] `ToolResult.meta` is a write-only contract field — never read — `src/agent/tools/types.ts:12` — `meta?: Record<string, unknown>;` — the loop consumes only `ok`+`output` (`src/agent/loop.ts:152` `yield { ... ok: result.ok, output: result.output }`; `:153` `transcript.appendToolResult(call.id, result.output)`). grep `\.meta\b` over `src/**` returns zero reads against any `ToolResult` (only `import.meta`, training `TrainingExample.meta`, and unrelated session/debt `meta`). A handler that populates `meta` has it silently dropped — the field is dormant.

- [inconsistent|medium] Duplicate ProviderMessage→OpenAI-shape mapper, two divergent return types — `src/agent/trace-recorder.ts:22` vs `src/agent/provider-tooluse/openai.ts:19` — `function toOpenAiMessage(m: ProviderMessage): OpenAiMessage` (typed) vs `function toOpenAIMessage(m: ProviderMessage): Record<string, unknown>` (untyped) — both translate the same `ProviderMessage` (role/content/toolCalls→tool_calls{function,arguments:JSON.stringify}) into the OpenAI messages shape from independent code. The tool-call JSON shape is duplicated; a future change to the OpenAI tool_call envelope must be made in two places or the training-trace shape silently diverges from what the live adapter actually sends.

- [inconsistent|low] Divergent defensive-copy discipline across the two "registry of truth → consumer" surfaces — `src/agent/transcript.ts:29` vs `src/agent/tools/registry.ts:33-37` — `Transcript.toProviderMessages` returns `this.messages.map((m) => ({ ...m }))` (copies the wrapper) while `ToolRegistry.toNativeSchemas` returns `input_schema: t.inputSchema` by **shared reference** (no spread). Same architectural role (hand out the internal source-of-truth to a consumer), opposite copy policy. A consumer mutating an emitted `input_schema` aliases the registered `ToolDefinition.inputSchema`.

- [dead-test|medium] `transcript` immutability test over-claims — only top-level primitive is verified, nested objects are aliased — `tests/agent/transcript.test.ts:27` — `it('toProviderMessages returns copies (callers cannot mutate internal state)' ...)` mutates only `a[0]!.content = 'MUTATED'` (a string). The actual copy is shallow (`{ ...m }`, `transcript.ts:29`), so `toProviderMessages()[1].toolCalls` and `…toolCalls[0].args` remain the **same object refs** as internal state — a caller CAN mutate internal state via `msgs[1].toolCalls[0].args.x = …`. The test name asserts full immutability it does not prove.

- [dead-test|low] `session` transcript-copy test repeats the same shallow-only assertion — `tests/agent/session.test.ts:101` — `t[0]!.content = 'MUT'; ... expect(s.transcript()[0]!.content).toBe('hi')` — `session.transcript()` delegates to `Transcript.toProviderMessages()` (`session.ts:107`), so it inherits the shallow copy; the test mutates only the top-level `content` string and never exercises nested `toolCalls`/`args` aliasing. Same false deep-immutability confidence as the transcript-suite case.

- [root-cause|medium] Synchronous blocking fs on the per-turn hot path — `src/agent/trace-recorder.ts:41-42` — `mkdirSync(dirname(filePath), { recursive: true });` then `appendFileSync(filePath, JSON.stringify(example) + '\n', 'utf-8');` — `appendTrace` is invoked once per turn via `recordTurn` (`src/cli/repl/native-agent-bridge.ts:122` `deps.recordTurn(session.transcript())`), wired through `buildTurnRecorder` (`trace-wire.ts:20`) which is **default-on** (`trace-wire.ts:4-5` "Opt-out via DECKENT_TRACE=0"). Every REPL turn blocks the event loop on a `mkdir`+`append` syscall pair — in tension with ADR-087 (Async I/O & Test Hermeticity Standard).

- [root-cause|medium] Silent cross-source tool shadowing — `register()` is last-write-wins and ignores `source` on name collision — `src/agent/tools/registry.ts:17-21` — `register(def) { const violation = validateToolDefinition(def); if (violation) throw ...; this.tools.set(def.name, def); }` — `ToolDefinition.source` exists "for telemetry + guard policy" (`tools/types.ts:26`) and spans untrusted origins (`'mcp' | 'user' | 'package'`, `tools/types.ts:7`), yet a later `source:'mcp'`/`'user'` registration silently replaces a `source:'builtin'` tool of the same name — no precedence, no warn, no emit. The behavior is documented+tested as intentional (`tests/agent/tool-registry.test.ts:27` "last-write-wins") but provides zero signal when an untrusted source overrides a builtin handler.

- [root-cause|low] `toNativeSchemas` leaks the registry's source-of-truth by reference (no defensive copy) — `src/agent/tools/registry.ts:36` — `input_schema: t.inputSchema` — the provider request (`loop.ts:74` `tools: deps.registry.toNativeSchemas()`) receives the live `ToolDefinition.inputSchema` object; any downstream mutation aliases the registered tool. This exact "minor" was flagged in the design spec (`docs/superpowers/specs/2026-06-13-sp1-native-terminal-agent-core-design.md:159`, "consumer mutate ederse kayıtlı tool alias'lanır; opsiyonel shallow-spread hardening") and remains unhardened. Root cause of the [inconsistent|low] divergence above.

## Summary
5 source files fully read; source unchanged. **unwired: 0** — every public export is grep-proven wired (negative finding reported). **dormant: 1** — `ToolResult.meta` has no reader. **inconsistent: 2** — duplicate/divergent OpenAI mapper (trace-recorder vs openai adapter) + split defensive-copy discipline (Transcript copies, registry shares ref). **dead-test: 2** — transcript + session "returns copies" tests assert only top-level-primitive immutability while the copy is shallow, leaving nested `toolCalls`/`args` aliased (false deep-immutability confidence). **root-cause: 3** — (a) sync `mkdirSync`+`appendFileSync` per turn on the default-on trace path vs ADR-087; (b) silent cross-source tool shadowing in `register()` ignoring the `source` field; (c) `toNativeSchemas` shared-reference schema leak (spec-flagged, unfixed). Highest-priority: the per-turn sync I/O (latency on every REPL turn) and silent cross-source shadowing (untrusted MCP/user tool can replace a builtin handler with no signal).
