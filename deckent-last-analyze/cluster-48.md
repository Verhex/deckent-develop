- [root-cause|high] The shared cause: lifecycle/event-driven detectors are wired to inputs the runtime never delivers — `src/nervous/detectors/token-spike.ts:55` (representative) — three independent breaks each, alone, makes the lifecycle-gated detectors (token-spike, scope-collision-rate) dormant: (1) the only `newPhase`-bearing emit goes to `eventBus.emit('deckent-event', …)` (`sprint-controller.ts:248`) which has zero listeners; (2) the observer-reachable SPRINT_PHASE_CHANGE uses `fromPhase`/`toPhase` (`sprint-finalizer.ts:635`), not `newPhase`; (3) even with matched keys, the observer's `DETECTOR_ACTIVE_PHASE='EXECUTE'` guard (`observer.ts:246/276`) drops any dispatch when the sprint has already transitioned to `RETRO`/`EVALUATE`. The detector files themselves are internally correct; they are reading a contract (event name + payload key + active-phase) that the emitting side of the system does not honor.

## Summary
nervous#3 covers six built-in detectors, and the dominant signal is **dormancy by producer-mismatch**: four of the six (`notification-delivery-health`, `task-mode-idle`, `scope-collision-rate`, and the lifecycle half of `token-spike`) can never fire in the current runtime because the event types and payload keys they read (`NOTIFICATION_DELIVERY`, `notificationsSent`, `SCOPE_COLLISION`, `sprintCollisionCount`, `lastUserActivity`, `newPhase`, `averageCostUsd`) have **no producer anywhere in `src/`** — each verified by repo-grep returning only the detector file plus its test. The cron producer emits `{intervalMs}` only (`observer.ts:383`), the lifecycle producer that reaches the observer emits `fromPhase`/`toPhase` (`sprint-finalizer.ts:635`), and the one emit that does carry `newPhase` is published on `'deckent-event'`, an event name with zero listeners (`sprint-controller.ts:248` vs the observer's `on('event')` at `observer.ts:298`). Layered on top, the observer only dispatches detectors during `EXECUTE` (`observer.ts:246/276`), so any RETRO/EVALUATE-gated detector is doubly blocked. Of the two genuinely-live detectors, `stale-worker` works but its alert message reports the base timeout while the stale test uses the per-scope adaptive threshold (`stale-worker.ts:76` vs `:89`), and `scope-collision` works only in EXECUTE (its declared `PLAN` phase is unreachable) and its `canAutoApply` predicate is never registered in the executor map (`bootstrap.ts:210-213` omits `SCOPE_COLLISION_REORDER`). The test suites compound the picture: every dormant path has a passing test built on a hand-crafted payload the runtime never produces — the strongest dead-test signal in this cluster. None of these are source bugs inside the six files in isolation; the defect is a contract drift between the detector inputs and the observer/event-bus/finalizer that feed them.
