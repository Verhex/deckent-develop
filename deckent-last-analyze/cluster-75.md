- [root-cause|high] Risk classifier auto-approves a risky action whose name merely CONTAINS a safe substring — `src/cli/commands/agentic-confirm.ts:33` — `if (SAFE_KEYWORDS.some((kw) => lower.includes(kw))) return 'safe';` (checked BEFORE `:34` `if (RISKY_KEYWORDS.some((kw) => lower.includes(kw))) return 'risky';`) — SAFE is `substring`-matched and evaluated first, so a tool named e.g. `get_and_reset` / `list-and-kill` / `review_and_run` matches `get`/`list`/`review` (SAFE_KEYWORDS, `:24`) and returns `'safe'` even though it also contains `reset`/`kill`/`run` (RISKY_KEYWORDS, `:23`). `requireConfirmIfRisky` (`:65` `if (classifyActionRisk(action) === 'safe') return true;`) then SKIPS the y/N gate. The fail-safe `return 'risky'` default (`:36`) is undermined by safe-substring-wins. This gate fronts agentic dispatch in the REPL (`chat-native.ts:693,749`) and the messaging bot (`chat-bridge.ts:53`), so an unsafe action can execute without human confirmation.

- [root-cause|high] `agent stats` fabricates / mis-attributes per-agent performance from whole-sprint markdown — `src/cli/commands/agent.ts:189` — `const taskLineRegex = /\|\s*([^|]+)\s*\|\s*([^|]+)\s*\|\s*(GO|NO_GO|GO_WITH_TECH_DEBT)\s*\|/g; … while ((match = taskLineRegex.exec(content)) !== null) { tasks++; if (match[3] !== 'NO_GO') success++; }` — a sprint file is included merely because `content.match(new RegExp(agentName,'gi'))` finds ≥1 mention (`:184-186`), then EVERY task row in that file is counted as the agent's, though the rows are not agent-scoped — one name mention attributes the whole sprint's GO/NO_GO outcomes to the agent. The fallback is worse: `:198` `if (tasks === 0) { tasks = mentions; success = mentions; }` sets `success === tasks` → an unconditional 100% `successRate` (`:209`). `deckent agent stats <name>` therefore reports trust-without-verify proxy numbers as real per-sprint performance. (The `new RegExp(agentName, …)` at `:184` is also raw-input-compiled, mitigated only by the prior `existsSync(agent.json)` gate at `:358`.)

- [inconsistent|low] `audit-verify` double-casts `MemoryStore` to a phantom `never[]`-returning shape, masking the real chain row type — `src/cli/commands/audit-verify.ts:38` — `const result = verifyAuditChain({ store: store as unknown as { queryAuditChain: () => never[] }, secret });` — `MemoryStore` structurally satisfies the consumer: it declares `queryAuditChain(): Array<…>` (`core/memory-store.ts:1083`) and `verifyAuditChain` expects `{ queryAuditChain(): AuditChainRow[] }` (`api/terminal/audit-integrity.ts:42,106`).
