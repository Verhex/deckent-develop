## Findings

- [unwired|high] Entire module has zero production callers — `src/training/cc-trace-extractor.ts:51` — `export function extractFromSession(lines: string[], system: string): ExtractResult {` — grep of `src/**/*.ts` for `extractFromSession`, `mapToolName`, `cc-trace-extractor`, `ExtractResult` returns zero hits outside the file itself; the only consumer is `tests/training/cc-trace-extractor.test.ts:3` (`import { mapToolName, extractFromSession } from '../../src/training/cc-trace-extractor.js'`). The SP-2 Phase 2 parser has no CLI command, MCP tool, batch-job, or production pipeline caller. The sibling SP-2 module `trace-recorder.ts` IS wired (`src/cli/repl/trace-wire.ts:8` `import { appendTrace, toTrainingExample } from '../../agent/trace-recorder.js'`), but the CC JSONL extractor is not — it is an unwired island.

- [unwired|high] `mapToolName` exported but zero external production callers — `src/training/cc-trace-extractor.ts:20` — `export function mapToolName(ccName: string): string | null {` — the only external caller is the test file (`:3`); its only internal use is at `:133` (`const mapped = mapToolName(ccName)`). Not imported by any production module.

- [unwired|medium] `ExtractResult` interface exported with zero production consumers — `src/training/cc-trace-extractor.ts:29` — `export interface ExtractResult { aligned: MsgExample[]; general: MsgExample[]; }` — serves only as the return type annotation of `extractFromSession`; no production module references this type.

- [dormant|medium] `flush()` silent discard gate fires with no-op and zero diagnostic — `src/training/cc-trace-extractor.ts:58` — `if (current === null || current.messages.length < 2) return; // need user + at least one assistant msg` — a segment containing only a user message (no assistant reply) is silently dropped. No counter, no warning, no metric surfaces how many training examples were discarded. Any session transcript that ends mid-turn or contains a user-only exchange produces a silent data-loss event.

- [inconsistent|medium] Shared-reference aliasing between `aligned` and `general` corpora — `src/training/cc-trace-extractor.ts:59` — `const example: MsgExample = { messages: [{ role: 'system', content: system }, ...current.messages] }; general.push(example); if (!current.hasNonMappable) aligned.push(example);` — the SAME object reference is pushed to both `general` and `aligned`. Any downstream mutation of a `general[i]` entry (e.g. post-processing messages) silently corrupts the corresponding `aligned[i]` entry. No defensive copy is made.

- [inconsistent|low] Content array walked twice for user-text extraction — `src/training/cc-trace-extractor.ts:86` — `const hasText = (content as unknown[]).some((b) => ... (b as Record<string, unknown>)['type'] === 'text',);` followed at `:95` by `.filter((b) => ... (b as Record<string, unknown>)['type'] === 'text').map(...)` — the same content array is scanned twice (once with `.some()`, once with `.filter().map()`). The second scan is redundant given the `hasText` guard; the combined extraction could be done in one pass. Contrast the tool-result branch at `:103` which uses a single imperative `for` loop — inconsistent approach for the same content-array type.

- [inconsistent|low] Type/role double-check is asymmetric after the outer filter — `src/training/cc-trace-extractor.ts:84` — `if (type === 'user' && role === 'user') {` — the outer loop already filtered `type` to `'user'|'assistant'` at `:74` (`if (type !== 'user' && type !== 'assistant') continue`), so `type === 'user'` in the inner check is guaranteed but redundant. More critically, entries where `type === 'user'` but `role !== 'user'` (e.g. a CC JSONL entry with `type: 'user'` and `role: 'tool'` in the message envelope) hit neither branch at `:84` nor `:118` and are silently dropped with no continue or diagnostic — the silent-drop is structurally invisible.

- [dead-test|none] No dead tests found — all 4 tests in `tests/training/cc-trace-extractor.test.ts` assert real extracted behavior (tool-name remapping, aligned/general split, multi-segment boundary, malformed-skip); no `.skip`, no tautological fixture, no mock-only test.

- [root-cause|high] Trust-without-verify: `tool_result.content` cast to `string` without type guard — `src/training/cc-trace-extractor.ts:111` — `content: (b['content'] as string) ?? '',` — CC JSONL `tool_result.content` can be a plain string OR an array of content blocks (e.g. `[{type:'text',text:'...'},{type:'image',...}]`) when tools return rich output. The `as string` cast does not convert; the `?? ''` null-coalescer only triggers on `null`/`undefined`, NOT on arrays. An array value passes through as the `content` field, silently violating the `OpenAiMessage.content: string` contract defined in `trace-recorder.ts:16` (`content: string`). Training data is corrupted without any error — the serialised line will contain a JSON array where a string is expected.

- [root-cause|medium] Silent fallback: missing `tool_use.input` serialised as `'{}'` with no diagnostic — `src/training/cc-trace-extractor.ts:145` — `arguments: JSON.stringify(b['input'] ?? {}),` — if a `tool_use` block has no `input` field (malformed CC JSONL), the fallback `{}` is silently serialised to `'{}'`. The caller has no way to distinguish a legitimate empty-args call from a corrupt/missing-args entry. Training data is silently produced with vacuous argument strings.

- [root-cause|medium] Silent fallback: missing `tool_use_id` silently becomes empty string — `src/training/cc-trace-extractor.ts:109` — `tool_call_id: (b['tool_use_id'] as string) ?? '',` — a `tool_result` block without a `tool_use_id` field (malformed JSONL) produces `tool_call_id: ''`. An empty-string id will fail to match any `tool_calls[].id` reference in the training example, producing unresolvable tool-call linkage. No diagnostic is emitted; the example is pushed to `general` (and potentially `aligned`) anyway.

- [root-cause|low] Silent fallback: every malformed-input skip has zero counter — `src/training/cc-trace-extractor.ts:68` — `try { parsed = JSON.parse(raw); } catch { continue; }` — five distinct skip paths exist in the loop (bad JSON `:68`, non-object `:70`, wrong type `:74`, no message `:77`, non-array content `:81`). None increment any counter. The `ExtractResult` return type carries only the produced examples; callers cannot determine how many input lines were rejected. A session that yields `{aligned:[],general:[]}` is indistinguishable from a fully-empty session.

## Summary
1 source file read in full; 11 findings. The single dominant issue is that the **entire module is unwired** — `extractFromSession`, `mapToolName`, and `ExtractResult` have zero production callers in `src/`. The sibling SP-2 module `trace-recorder.ts` is live (wired via `src/cli/repl/trace-wire.ts`), but this CC JSONL batch-extractor has no CLI command, MCP tool, or production pipeline caller — it is an isolated test-only island. Secondary issues: (1) **trust-without-verify on `tool_result.content`** — cast to `string` silently passes arrays, corrupting training data when tools return rich multi-block output; (2) **shared-reference aliasing** between `general` and `aligned` corpora — downstream mutation of one silently corrupts the other; (3) **silent discards across 5 distinct code paths** (bad JSON, type/role mismatch, `< 2` messages flush guard, missing `tool_use_id`, missing `input`) with zero counters returned to the caller, making data-loss invisible; (4) `flush()` no-op gate drops incomplete segments silently. The `inconsistent` category surfaces a double content-array scan and an asymmetric type/role guard that silently swallows mismatched entries. No dead tests — the 4 existing tests are clean and meaningful. No source modified (read-only audit).
