### root-cause
- [root-cause|high] Residual ADR-008 violation: `core/` imports `orchestra/` — `src/core/routing-engine.ts:30` — `import { analyzeSkillInMemory } from '../orchestra/ecosystem-intelligence.js';` (consumed at `:945` inside `getSkillActivation`). ADR-008 (and its 2026-06-11 amendment) forbid `core/ → orchestra/`; `authority-enforcer.ts` flags this exact direction but per ADR-037 V1.0 the check is advisory/soft (warn+emit, no hard-block), so the one tracked breach (ADR-008-W) persists. The architectural guarantee "`core/` depends on nothing above it" is unenforced precisely here — `core`'s central routing module reaches up into the orchestra layer.
- [root-cause|medium] Context-overflow guard is advisory-only and unenforced — `src/core/routing-engine.ts:1085-1091` — on `utilization > 0.90` it does `reasoning.push('… Consider splitting the task.')` + `debugLog('… SPLIT recommended')` + `return 'overflow'`; nothing splits, blocks, or downgrades the task, and (see dormant) no caller ever reads `decision.contextFit`. A task that overflows the model's context window is routed and spawned anyway — the "SPLIT recommended" guarantee is a log line with no teeth.
- [root-cause|medium] RBAC enforcement is NO_OP-by-default even where wired — `src/core/rbac.ts:127` — `if (!rbacConfig?.enabled) return true;`; the sole enforcement gate (already unwired, see above) defaults to allow-all when `rbac.enabled` is absent (the shipped default), so `enforceRbac` returns `true` for a `viewer` requesting `ADMIN`. Combined with the dormant denial audit-trail, RBAC in this module neither blocks nor records denials under any default config — the guarantee is opt-in AND off.
- [root-cause|low] Silent stack-detect fallback reintroduces the TS-shaped default it exists to prevent — `src/core/rule-generator.ts:525-531` — `try { … workerPaths = resolveWorkerPaths(stack?.language); } catch { workerPaths = undefined; }`; an `undefined` resolves to `['src/**','tests/**']` (`:97`). - [root-cause|low] User `excludeAgents` override is silently bypassed for surface owners — `src/core/routing-engine.ts:507-514` — `if (excludeAgents.includes(id)) { if (surfaceBonus > 0) { reasoning.push('… surface exclude bypass …') } else { … continue } }`; `excludeAgents` includes the user's authoritative `resolveOverrides().excludeAgents` (priority task>sprint>project per `routing-types.ts:164`), yet a surface-owner agent on its own surface overrides that explicit user exclude. ## Summary
This cluster is the routing + RBAC + autonomous-dispatch seam of `core`, and it carries a consistent pattern: enterprise/autonomy features were built, unit-tested, then left unwired or made advisory-soft. RBAC is the starkest case — `enforceRbac` has zero production callers (shadowed by local `enforce_rbac` consts), defaults to NO_OP even if reached, and its `can()` denial audit-trail is dormant because no caller ever passes `auditCtx`; the whole module neither blocks nor records under any shipped config. The autonomous human-approval safeguard (`PendingDispatchQueue`, `createSelfDispatchCallback`) is similarly test-only — the "Alperen onayı" gate is never instantiated. The routing engine itself harbors the tracked ADR-008 breach (`core/ → orchestra/` at line 30, advisory-soft and thus persistent) and a context-overflow guard that logs "SPLIT recommended" but enforces nothing (the `contextFit` field is write-only). Rounding it out are accreted duplications — three divergent `redactSensitive` implementations (two byte-identical, pinned by a cross-check test), a `routingVersion` taxonomy that stamps 'v3' on the wire but persists 'v2' in meta, and dead V3 scaffolding (`subIntent` populated-never-read, `ALL_SUB_INTENT_TYPES` referenced nowhere).
