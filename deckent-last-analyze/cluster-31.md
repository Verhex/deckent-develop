## Summary
The ERP sub-cluster (factory/handler/index + the three drivers + the read-only connector SSOT) is genuinely wired and well-guarded: `buildErpConnectorFromConfig` is consumed by `runtime-loop`, `process-runtime`, and `erp-connector`, and `installErpHandler`→`capability-runtime` installs the live `erp.read` path — so no ERP unwired/dead-code findings, only thin type/dialect softness (`as Capability` cast, SAP-v2 `like`). The real rot is concentrated in `event-stream.ts`: three substantial exports built for headline guarantees — crash-recovery state reconstruction (ADR-043/044), fix-resolves-dependency signalling (Bug A, Sprint 179), and SOC2/ISO audit-lineage (ENT-3) — are **all production-dead**, alive only in unit/e2e tests, with docstrings asserting result-collector/plugin-hooks wirings that grep proves absent. The pattern this cluster reveals about deckent: feature scaffolding (typed APIs + green tests + confident comments) repeatedly outruns the last wiring step, so the test suite reports "covered" for capabilities the running orchestrator never exercises. A minor but user-facing drift (E010 still says "Node 18" while ADR-001/engines mandate Node 24+) confirms stale-baseline references survive because the advisory ADR sweep is not enforced.
