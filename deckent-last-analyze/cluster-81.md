## Summary
cli#7 is dominated by **test-only / orphaned surface**: a whole module (`agent-templates.ts` — 4 exports) plus two reporter classes (`AgentPerformanceFormatter`, `ChangeCategorizer`) and five standalone functions (`getFileGitDate`, `runSync`, `buildProviderSyncMap`, `reprovisionWorkerImageAfterUpgrade`, `buildEntryArgv`) are exercised only by tests with zero production callers — several superseded by a live sibling (`getFileGitDateAsync`, inline `sync` action logic, `ensureDeckentImport`, `launchDefaultRepl`). A second theme is **no-op / divergent gates**: `start.ts`'s provider-cache freshness check skips no work; `status.ts`'s `readSprintMeta` ignores its sprintId; `watch.ts` resolves "current sprint" from a non-canonical `last_sprint_id` (one of three divergent implementations) and silently misroutes a worker to claude on a read error; `upgrade.ts` never fires its docker re-provision hook after an actual upgrade. The riskiest *latent* bug is `appendDeckentSection`'s dedup marker (`# Deckent Integration`) not matching the `# AGENTS.md — Deckent Integration` / `# GEMINI.md — Deckent Integration` headers its own generators emit — kept invisible by tests that only feed the matching synthetic fixture. `ansi.ts` and `usage.ts` are clean (all ansi exports consumed by status-renderer/status; usage even has an explicit loud unknown-model guard).
