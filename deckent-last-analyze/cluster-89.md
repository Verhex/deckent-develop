# dashboard#3 — sprint/worker/terminal components + shadcn UI primitives

Scope: `src/dashboard/src/components/SprintPhaseTimeline.tsx`, `SprintSummary.tsx`, `TaskCard.tsx`, `ThemeProvider.tsx`, `WorkerCard.tsx`, `WorkerGrid.tsx`, `WorkerLogPanel.tsx`, `terminal/TerminalPanel.tsx`, `terminal/TerminalTabs.tsx`, `terminal/TerminalView.tsx`, `terminal/useTerminalSocket.ts`, `ui/{badge,button,card,dialog,input,label,progress}.tsx`.
Method: full read of all 18 files + repo-grep of every exported symbol over `src/` (production) vs `tests/` (test-only). Code-only; no source changed.

Production consumers verified (wired): `WorkerCardGrid` (DashboardPage:450, WorkersPage:179, SprintControlPanel:179), `SprintPhaseTimeline` (DashboardPage:436, SprintControlPanel:128), `SprintSummary` (StatusPage:62), `WorkerLogPanel` (WorkersPage:190), `TerminalPanel` (Layout:245), `ThemeProvider`/`useTheme` (App:28, SettingsPage:8, AppShell:61, Layout:84), `DialogFooter` (NewSprintModal, ManualTokenInput), `Card`/`CardHeader`/`CardContent`/`CardTitle`, `Badge`, `Progress`, `Button`, `Input`, `Label` — all have live callers.

## Findings

- [unwired|high] `WorkerGrid` component is exported but imported by **zero** production pages — `src/dashboard/src/components/WorkerGrid.tsx:16` — `export function WorkerGrid({ onSelect, onKill }: WorkerGridProps)`. grep `WorkerGrid`/`<WorkerGrid`/`from "./WorkerGrid"` over `src/` → no importer; every page that shows workers imports `WorkerCardGrid` **directly** from `./WorkerCard` (DashboardPage.tsx:7, WorkersPage.tsx:4, SprintControlPanel.tsx:7), bypassing this wrapper. Its self-contained SSE-polling source (`useLiveData<DashboardState>("/api/status", { pollIntervalMs: 3000 })`, `:17`) and the `isStale && status === "reconnecting"` banner (`:25-27`) therefore never run in production; live worker data reaches `WorkerCardGrid` through DashboardPage's own data layer. Sole caller is `tests/dashboard/worker-grid-live.test.tsx` (source-grep, see dead-test below). Corroborates prior audit UNW-A059 (`deckent-last-standing.md:1749`).

- [unwired|med] Four `SprintSummary` status helpers have zero production callers — `src/dashboard/src/components/SprintSummary.tsx:46,65,84,103` — `export function getTaskStatusColor` / `getTaskStatusBg` / `getStatusIcon` / `getStatusLabel`. grep over `src/` returns only the definitions; the `SprintSummary` component body (`:201-403`) renders tasks via `<TaskCard>` and draws icons/badges with lucide + `<Badge>`/`<Progress>` directly, calling none of them. Only consumers: `tests/dashboard/SprintSummary.test.tsx:8-11`. `getStatusLabel` (`:103-128`) additionally hardcodes English (`return "Done"` / `"Active"` / `"Writing code"` …) — a dead, non-i18n status map kept alive solely by its test.

- [unwired|med] TaskCard `describeCurrentAction` + `getBadgeLabel` are dead hardcoded-English twins of the component's inline i18n logic — `src/dashboard/src/components/TaskCard.tsx:101,157` — `export function describeCurrentAction(...)` (`:101-134`, returns `"Completed"`/`"Working..."`/…) and `export function getBadgeLabel(...)` (`:157-182`, returns `"Done"`/`"No-Go"`/…). The live component never calls them; it uses the inline `getTranslatedAction()` (`:202-234`) and `getTranslatedBadge()` (`:237-262`) which route through `t('task_card.*')`. grep: zero `src/` callers, only `tests/dashboard/TaskCard.test.tsx:127,208`. (By contrast `getCardColor`/`getCardIcon`/`getCardIconColor`/`getBadgeVariant` ARE used at `:190-192,304`.)

- [unwired|low] `CardDescription` primitive is exported but never rendered in production — `src/dashboard/src/components/ui/card.tsx:29,43` — `const CardDescription = forwardRef(...)` … `export { Card, CardHeader, CardTitle, CardDescription, CardContent }`. grep `CardDescription`/`<CardDescription` over `src/` → only this definition/export; the only reference is `tests/dashboard/scaffold.test.ts:153` asserting the source `toContain("CardDescription")`. Unused export-surface.

- [unwired|low] `DialogTrigger` is exported with zero production callers — `src/dashboard/src/components/ui/dialog.tsx:51,175` — `function DialogTrigger({...})` … exported at `:175`. No `<DialogTrigger` exists in `src/`; the two real modals open via the controlled `open` prop (`NewSprintModal`/`ManualTokenInput` use `<Dialog open=…>` + `DialogContent`/`DialogFooter`), so the uncontrolled trigger path is unused. Only `tests/dashboard/dashboard-page.test.ts:252` source-greps it. (`DialogOverlay` and `useDialogContext` are also exported at `:180,181` but at least run internally — `DialogContent` calls them at `:126` and `:56/:86`; their *external* export surface is unused.)

- [dormant|low] Live docker-log tail is a no-op gate for non-docker backends — `src/dashboard/src/components/WorkerCard.tsx:167-170` — `const liveLog = useLiveLogTail(agent.taskId, agent.status === "EXECUTING" && agent.backend === "docker")`. For `tmux`/`subprocess` workers the `enabled` flag is permanently false, so the SSE subscription to `/api/output-stream` (`useLiveLogTail`, `:118-157`) returns `[]` and the live-log `<pre data-testid="worker-live-log">` (`:236-243`) never renders. Intentional (docker-only output-stream) but the feature is silently dormant for 2 of 3 backends with no UI affordance.

- [inconsistent|med] Badge `critical` and `destructive` variants are byte-identical, and sibling cards diverge on which to use for the same status — `src/dashboard/src/components/ui/badge.tsx:12,16` — `destructive: "border-transparent bg-red-900 text-red-100"` and `critical: "border-transparent bg-red-900 text-red-100"` (identical class string). `WorkerCard` maps `NO_GO`/`ERROR` → `"critical"` (`WorkerCard.tsx:23-24` STATUS_BADGE) while `TaskCard` maps the same `NO_GO`/`ERROR` → `"destructive"` (`TaskCard.tsx:147-149` getBadgeVariant). Same semantics, two variant names, identical pixels → duplicate variant + divergent caller convention.

- [inconsistent|low] Duplicate task-shape interfaces bridged by a hand cast — `src/dashboard/src/components/SprintSummary.tsx:20-37` (`TaskInfo`) vs `src/dashboard/src/components/TaskCard.tsx:19-36` (`TaskCardData`) — field-for-field identical records; `SprintSummary` renders `<TaskCard key={task.id} task={task as TaskCardData} />` (`SprintSummary.tsx:343`), casting one interface to the other instead of importing a single shared type. Two parallel definitions kept in sync manually.

- [inconsistent|low] Hardcoded English in i18n-first component surfaces — `src/dashboard/src/components/terminal/TerminalPanel.tsx:68` (`<div …>Open a session ↗</div>`), `src/dashboard/src/components/terminal/TerminalTabs.tsx:54` (`aria-label={`close ${t.id}`}`), `src/dashboard/src/components/WorkerGrid.tsx:26` (`⚠ reconnecting…`) — bare literals not routed through `t()`, diverging from the same components' use of `useTranslation()` elsewhere. TerminalPanel/TerminalTabs are live (Layout:245); the WorkerGrid literal is moot because the component is unwired (see first finding).

- [dead-test|high] `worker-grid-live.test.tsx` is pure source-string inspection of an unwired component — `tests/dashboard/worker-grid-live.test.tsx:14,23,30,43,55,78` — `const src = () => readFileSync(GRID_PATH, "utf-8")`; every `it` asserts on the `.tsx` **text**: `expect(content).toContain("useLiveData")` (`:30`), `toContain('"/api/status"')` (`:36`), `toContain("data?.agents ?? []")` (`:78`), `toContain("agents={workers}")` (`:58`). Header self-declares "No DOM render, no SSE mock, no network". It would pass even if `WorkerGrid` threw at runtime, and it pins a component no page imports — verifying source presence, not behavior or wiring.

- [dead-test|med] `worker-log-panel.test.tsx` asserts source substrings, not rendered behavior — `src/dashboard/src/__tests__/worker-log-panel.test.tsx:19,40,53-55,66,170` — `const panel = () => readFileSync(panelPath, "utf-8")`; the ring-buffer "test" is `expect(src).toContain("MAX_LOG_LINES")` + `toContain("500")` (`:51-56`), SSE wiring is `toContain("logs/stream")` (`:40`), integration is `toContain("<WorkerLogPanel")` (`:170`). No render, no `EventSource` mock — the 500-line cap, auto-scroll, reconnect-on-error, and unavailable-state are never executed. The component IS wired (WorkersPage:190) so severity is below the WorkerGrid case, but the suite checks that the source contains strings rather than that the panel works.

- [root-cause|med] Theme preference is silently not persisted — every reload resets to hardcoded `"dark"` — `src/dashboard/src/components/ThemeProvider.tsx:16` — `const [theme, setTheme] = useState<Theme>("dark")`. There is no `localStorage` read/write anywhere for theme (grep `localStorage`/`getItem`/`setItem` over `src/dashboard/src` → only `lib/oidc-flow.ts`/`lib/session.ts` `sessionStorage` for auth; `lib/theme.ts` is a static design-token table, not persistence). `SettingsPage` exposes `setTheme('dark')`/`setTheme('light')` toggles (`SettingsPage.tsx:63,76`) and `Layout`/`AppShell` toggle too (`Layout.tsx:87`, `AppShell.tsx:64`), but on refresh the hardcoded default wins and the user's choice is lost with zero signal. Hardcoded-default-wins / state-loss.

- [root-cause|low] SprintPhaseTimeline silent-fallback: an unrecognized phase renders an all-grey timeline with no active marker — `src/dashboard/src/components/SprintPhaseTimeline.tsx:21,29-31` — `const currentIndex = PHASES.indexOf(currentPhase as (typeof PHASES)[number])`. If `currentPhase` is empty or drifts from the 8 hardcoded labels (`PHASES`, `:3-12`), `indexOf` returns `-1`, so for every node `isCompleted = currentIndex >= 0 && … = false`, `isActive = index === -1 = false`, `isFuture = currentIndex < 0 || … = true` (`:31`). The mismatch degrades silently to "nothing in progress" instead of surfacing that the backend phase label is unknown.

## Summary

18 files, ~1,250 LoC: the shadcn UI primitives (`badge`/`button`/`card`/`dialog`/`input`/`label`/`progress`) and the live worker/terminal components are mostly genuinely wired (`WorkerCardGrid`, `SprintPhaseTimeline`, `SprintSummary`, `WorkerLogPanel`, `TerminalPanel`, `ThemeProvider`, `DialogFooter` all have production callers). The issues are dead surface-area, honesty-of-tests, and a few real UX/state bugs:

- **Unwired (5):** `WorkerGrid` whole component (**high** — every page bypasses it for `WorkerCardGrid`, so its bespoke SSE-polling layer is dead); four `SprintSummary` status helpers + TaskCard `describeCurrentAction`/`getBadgeLabel` (**med** — dead hardcoded-English maps superseded by inline `t()` logic, alive only via tests); `CardDescription` and `DialogTrigger` (**low** — exported primitives nothing renders).
- **Dormant (1):** `useLiveLogTail` docker-only gate makes the live-log `<pre>` a no-op for tmux/subprocess workers (low).
- **Inconsistent (3):** identical `critical`≡`destructive` Badge variants with sibling cards picking different names for the same status (med); duplicate `TaskInfo`/`TaskCardData` interfaces joined by a cast (low); hardcoded English in TerminalPanel/TerminalTabs/WorkerGrid against i18n-first (low).
- **Dead-test (2):** `worker-grid-live.test.tsx` (**high** — readFileSync `toContain` over an unwired component; passes even if it crashes) and `worker-log-panel.test.tsx` (med — source-substring assertions, no render/behavior) verify text, not function.
- **Root-cause (2):** `ThemeProvider.tsx:16` hardcoded `"dark"` default with no persistence silently discards the user's theme on reload (**med**); `SprintPhaseTimeline.tsx:21` `indexOf → -1` silent-fallback renders an all-grey timeline on any phase-label drift (low).

Highest-value follow-ups: (1) delete `WorkerGrid` (and its source-grep test) or actually route pages through it; (2) drop the dead hardcoded-English helpers (`getStatusLabel`/`describeCurrentAction`/`getBadgeLabel`/`getTaskStatusColor`/`getTaskStatusBg`/`getStatusIcon`) — they only exist to satisfy the i18n-lint's exported-helper exemption while shielding non-i18n strings; (3) persist theme to `localStorage` so the Settings toggle survives a reload; (4) collapse the `critical`/`destructive` Badge variants to one and standardize callers.
