## Summary
This cluster is the F8 capability subsystem (broker + reference/data/extended handlers + audited composition root) plus two standalone safety/auth primitives (`SessionStore`, `CascadeDetector`). The broker itself is well-engineered (graceful never-throw results, fail-safe availability probes) and is genuinely wired through `createAuditedCapabilityRegistry` into both the autonomous runtime-loop and the process controller. The material weaknesses are guarantee-softening and dead wiring: the least-privilege gate and its denial-audit are never enabled by any live caller (the `enforce_least_privilege` config knob has no reader that reaches the factory), so capability access is unconditionally permissive in production; and even if it were enabled, the handler `requiredCapability` names (`db.read`, `mail.read`, `net.read`, `env.read`, `shell.exec`) are not in the `Capability` union and are granted by no role, so those five handlers would deny for everyone — two divergent naming schemes that have never been reconciled. The audit-wrap loop (which always runs, since both call sites pass an emit) collapses multi-backend selection and drops `priority`/`isAvailable`, structurally defeating F8-002. Separately, `CascadeDetector` (the Sprint-140 $42 cost-cascade guard) and `SessionStore` (an SSO session store) and `invokeFromRequest` (the non-code execution entry) are all complete-and-tested yet have zero production callers — confirming Phase-1's UNW-018/UNW-A034/RC-A071. No test file sits in this cluster's read-scope, so the dead-test category is legitimately empty.
