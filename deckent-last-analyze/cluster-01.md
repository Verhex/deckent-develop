### root-cause
- [root-cause|high] Auditor verdict is advisory — boundary / ADR / functional violations never gate task completion — `src/orchestra/autonomous/execute-dispatcher.ts:448` — `ok = finalEval.decision !== 'NO_GO';`. The `verdict` from `auditBacklogResult` (boundary violations, ADR violations, `functional: 'fail'`) is computed (:435) and persisted into `richResult.audit` (:456-460) but is NEVER read into `ok`. Mirrors `backlog-eval.ts:100` ("post-execution Auditor verdict (advisory only — never flips the Brain decision, per ADR-037 V1.0)"). Result: an autonomous task that writes files OUTSIDE scope, violates an ADR, or fails functional verify still finalizes as `'done'` whenever the Brain rubric passed — the architectural scope/ADR guarantee is soft by construction.
- [root-cause|medium] `reconcileWithAudit` can upgrade a Brain NO_GO to GO_WITH_TECH_DEBT on a *trivial* functional pass — `src/orchestra/autonomous/backlog-eval.ts:169` — gate condition `verdict.functional === 'pass'`. The function's own docblock (:158-159) admits "`functional: 'pass'` can be a trivial pass-by-default for a source change lacking a co-located test", and `auditBacklogResult` (:133-140) returns `'pass'` whenever `verifyWorkerResult` does not return `FAIL`. So a worker NO_GO that is schema-rejected (e.g. missing coverage) is laundered to GO_WITH_TECH_DEBT on a weak/absent test signal. Bounded by the `schemaRejected===true` guard and a GO_WITH_TECH_DEBT ceiling, but the trust rests on an under-verified `functional` signal.
- [root-cause|medium] Authority adapter grants `brain`-level role to the literal string `system` with no verification — `src/orchestra/autonomous/authority-adapter.ts:21` — `ROLE_MAP = { ..., system: 'brain' }`. Any `requestedBy` of `system` / `system:<tenant>` is mapped to the highest-authority role; `backlog-trigger.ts:27,98` sets `requestedBy: 'system'` / `system:${tenant}` literally. Trust-by-string-prefix: a forged `system:` subject reaching this path would receive brain authority. Default-deny (:70) only catches *unknown* roles, not over-privilege of the trusted-internal string.
- [root-cause|low] Unknown action string defaults to a permission class (`event_emit`), not deny — `src/orchestra/autonomous/authority-adapter.ts:47` — `return 'event_emit';` is the terminal fallback of `resolveActionType`'s substring matching. An unrecognized symbolic action is classified as `event_emit` (a real ActionType the matrix may permit) rather than being denied. Asymmetric with the role path's explicit default-deny — actions fail *open* into a permission bucket.
- [root-cause|low] JIT-detail failure is swallowed by a fully-silent empty catch (degrade with no signal) — `src/orchestra/autonomous/execute-dispatcher.ts:254` — `} catch { /* JIT failure → fall back to the title-only description below */ }`. Inconsistent with every other catch in this file (which `console.warn`, e.g. :179,:186,:202,:421): a planned entry whose JIT detail generation throws runs the worker with a degraded title-only prompt and emits no warning, so a silently under-specified task looks identical to a normal run.

- [inconsistent|low] `TriggerSource.next()` returns sync in one factory, async in its siblings — `src/orchestra/autonomous/backlog-trigger.ts:19` — `makeBacklogTriggerSource` returns `AutonomousTrigger | null` synchronously, while `makeFlowBacklogBridge` (:62) and `makeHybridTriggerSource` (:108) return `Promise<...>`. The interface union (`autonomous-runtime.ts:111`) permits both, so it type-checks, but a consumer that treats `next()` as synchronous would silently receive a `Promise` (always truthy) from the bridge/hybrid. Latent footgun; current callers `await` defensively.

## Summary
The autonomous-execution slice is a clean DI/kernel design, but it carries two whole capabilities built ahead of use that are inert in production: the dispatcher-internal policy/risk-gate block (`execute-dispatcher.ts:260`) and the ExecutionPool concurrency seam (`:525`, `makeSerialPool`/`makeBoundedPool`) — neither is ever injected by `runtime-loop.ts` or `process-controller.ts`, so the risk-gate never parks high-risk capability work and execution is always serial. The deeper pattern is advisory-by-design enforcement: the Auditor's boundary/ADR/functional verdict is persisted but never gates `ok` (`:448`), the Brain⇄Auditor reconcile can upgrade a NO_GO on an under-verified `functional:'pass'`, and the authority adapter trusts the literal string `system` for brain-level access — together these make deckent's own scope/ADR/risk guarantees soft on the autonomous path (consistent with ADR-037 V1.0's intentional advisory posture). Minor hygiene debt: a duplicated `correlationId` type alias, a diverging on-disk audit type, and one fully-silent JIT catch that breaks the file's otherwise-uniform warn-on-fallback pattern.
