### root-cause
- [root-cause|medium] silent-fallback — a DB read failure is rendered identical to "no data" — `src/mcp/resources/debt.ts:43` (`} catch { /* DB error — return empty */ }` → falls through to `:47` `text: '[]'`) and `src/mcp/resources/memory.ts:29` (`} catch { /* DB error — return empty */ }` → `:33` `text: ''`). A corrupt/locked `memory.db`, a `MemoryStore` ctor throw, or a `getByType` failure all collapse to an empty array / empty string with no log, no `error` field, no signal — indistinguishable from a genuinely empty debt ledger or memory set. The consumer (and the human reading the MCP resource) cannot tell "DB broken" from "nothing recorded". The adjacent `dashboard` resource proves the better pattern exists in-tree (`dashboard.ts:19` debugLog), making the omission a deliberate-looking inconsistency rather than an oversight.
- [root-cause|medium] trust-without-verify — unchecked enum cast on a free-form DB string — `src/mcp/resources/debt.ts:34` (`priority: (d.priority?.toUpperCase() ?? 'NORMAL') as DebtItem['priority']`) — `d.priority` is an arbitrary stored string; `.toUpperCase()` then an `as DebtItem['priority']` (= `DebtPriority`, `sprint-types.ts:77-81`) ASSERTS membership in `NORMAL|HIGH|CRITICAL` without validating it. The `?? 'NORMAL'` default only fires on `null`/`undefined` — any non-null but out-of-enum value (e.g. a legacy/imported `'low'`/`'medium'` from `core/memory-import.ts:266`) sails through as `'LOW'`/`'MEDIUM'` and is type-laundered into the `DebtItem` output. The cast buys compile-time silence at the cost of an unenforced runtime invariant.
- [root-cause|low] silent-skip — malformed/unreadable agent files vanish from the pool with no signal — `src/mcp/resources/agents.ts:30` (`} catch { /* empty on read error */ }`) and `:38` (`} catch { /* skip malformed files */ }`) — a `readdirSync` failure yields an empty agent list, and any single corrupt `agent.json` is dropped from the `agents` array silently. The resource that exists to expose the agent pool will under-report it (or report it empty) without ever indicating that a file was skipped or which one.
- [root-cause|low] trust-without-verify — raw `agent.json` admitted to the resource output with zero schema validation — `src/mcp/resources/agents.ts:37` (`agents.push(JSON.parse(content));`) — whatever JSON parses (any shape, any keys, arbitrary size) is pushed straight into the `{ agents }` payload returned to the MCP client. The only gate is "is it parseable JSON" (`:35-38`); there is no agent-manifest shape check, so a structurally-wrong file is exposed as if it were a valid agent descriptor.

## Summary
This cluster is the MCP **read surface** — response decoration (`enrich`/`format`) plus six read-only `deckent://` resources — and it is mostly thin, honest glue, but the seams tell a consistent story: *promises advertised wider than they are wired, and failures rendered as emptiness*. The enrich layer threads a `response` payload through `generateSummary`/`generateHints` that not one of its 36 entries ever reads (dead plumbing), and — more materially — emits **hard-coded Turkish hints to every locale** while its summaries are dutifully bilingual, a straight i18n-FIRST violation living one function below the code that already resolves `lang`. The `helpers/index.ts` barrel is doubly off: zero production callers route through it, and it silently omits the `formatExplainResponse`/`ExplainData` pair, so the one tool that needs them reaches past it. On the resource side the DB-backed pair (`debt`, `memory`) swallow every store error into an empty result with no log — indistinguishable from "nothing recorded" — directly contradicting the sibling `dashboard` resource that debugLogs the same class of failure; and `debt` additionally launders an unvalidated lowercase DB `priority` string into the UPPERCASE `DebtPriority` enum via an unchecked `as` cast (the storage layer writes `'normal'`, the type system declares `'NORMAL'`, and the resource is the only place the two are reconciled — by assertion, not validation). None of these are runtime-fatal — the resources fail closed to empty/raw output — but several of the strongest-sounding contracts (i18n-clean output, a complete barrel, a typed `DebtPriority`, "no data means no data") are the least enforced.
