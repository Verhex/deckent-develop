# agents#4 — worker lifecycle / IPC / log / rollback / verify + specialization-drift

Scope: `src/agents/specialization-drift.ts`, `src/agents/worker-ipc.ts`, `src/agents/worker-lifecycle.ts`, `src/agents/worker-log.ts`, `src/agents/worker-rollback.ts`, `src/agents/worker-verify.ts`. Read-only structural audit (all 6 files read in full). Every finding is grep-verified against `src/` (def + re-export + test occurrences excluded from the zero-caller count).

## Findings

### worker-verify.ts

- [dormant|critical] Node verify-gate (tsc/vitest retry loops) has zero production callers — `src/agents/worker-verify.ts:163,271,454` — `runTestVerifyLoop`/`runCompilationLoop`/`enforceVerifyLoop` appear in `src/` only as defs + the pure re-export block `worker.ts:85,89,91` + a JSDoc at `worker.ts:392` (`* **Verify Loop Gate:** Callers MUST run \`enforceVerifyLoop()\` before calling this function.`). `grep -rn 'enforceVerifyLoop(\|runTestVerifyLoop(\|runCompilationLoop(' src/` returns no real call-site. Only tests invoke them (`tests/agents/worker-feedback.test.ts`, `tests/agents/worker-doc-skip.test.ts`). The programmatic build/test gate is structurally unreachable — verification happens via worker prompt/shell instead (ADR-037 V1.0 advisory). ~220 LoC dead gate.
- [unwired|high] `runCoverageVerify` is fully isolated — `src/agents/worker-verify.ts:384` — `export function runCoverageVerify(...)`; `grep -rn 'runCoverageVerify' src/` returns only this definition: **no caller and not even re-exported via `worker.ts`**. The Sprint 180 W4-1 coverage-parse chain `parseCoverageSummary` (`:329`) → `validateCoverageNumber` (`:363`) → `runCoverageVerify` (`:384`) was added but never wired into the worker path.
- [root-cause|high] `.verify-ran` honesty marker is never produced — `src/agents/worker-verify.ts:498-508` — `const markerPath = join(projectRoot, TASKS_DIR, \`task-${taskId}.verify-ran\`); ... renameSync(tmpPath, markerPath);` is reachable only from `enforceVerifyLoop`, which has 0 callers (above). Any downstream honesty check keyed on the `.verify-ran` marker is therefore inert (the marker file is never written in production).
- [root-cause|medium] Unquoted `scope` interpolated straight into `execSync` command strings — `src/agents/worker-verify.ts:121-124,398-399,481` — e.g. `const scopeArgs = scope && scope.length > 0 ? \` ${scope.join(' ')}\` : ''; const command = testCmd.includes('vitest') ? \`${testCmd} --reporter=verbose${scopeArgs}\` : ...`. `scope` flows from task JSON / DIRECTIVES; spaces/`;`/`&&` in a scope path become shell metacharacters → injection / parse failure. Violates the ADR-006 spawn-security spirit (string command vs argv array). Severity bounded only because the callers are themselves dormant.
- [inconsistent|low] Heartbeat-writing asymmetry across the loops — `src/agents/worker-verify.ts:286-295` (`runCompilationLoop` calls `createHeartbeat(... AgentStatus.VERIFYING ...)` + `writeHeartbeat` each attempt) vs `runTestVerifyLoop` (`:163`) and `runCoverageVerify` (`:384`) which write no heartbeat. Same loop family, divergent observability.
- [inconsistent|low] Three hardcoded, non-configurable timeouts — `src/agents/worker-verify.ts:130` (`timeout: 120_000` in `verifyTests`), `:407` (`timeout: 180_000` in `runCoverageVerify`), `:435` (`VERIFY_LOOP_TIMEOUT_MS = 300_000`). No single source / no config knob.
- [dead-test|medium] Mock-only tests keep the dormant gate green — `tests/agents/worker-feedback.test.ts:289-431,616-817`, `tests/agents/worker-doc-skip.test.ts:150-163` — these mock `execSync` and exercise `runTestVerifyLoop`/`runCompilationLoop`/`verifyTests`/`verifyCompilation`, producing coverage/“liveness” for functions with 0 production callers (false-confidence). Tests themselves are valid (not skipped/tautological); the issue is they mask production dormancy.

### worker-rollback.ts

- [root-cause|low] `snapshotWorkerScope` cannot distinguish "empty scope" from a real stash failure — `src/agents/worker-rollback.ts:146-154` — `try { execFileSync('git', args, ...) } catch { /* Empty scope can cause stash to fail ... fall through */ }`; on any failure it falls through to `resolveStashRefByMessage`, which returns the `stash@{NOSTASH}` sentinel (`:353`) when no entry matches. A genuine git error is therefore silently treated as "nothing to stash" → a later rollback becomes a no-op without signal.
- [inconsistent|low] Mixed `execSync` / `execFileSync` usage — `src/agents/worker-rollback.ts:70,340` use `execSync` (string command, e.g. `git status --porcelain --untracked-files=all`, `git stash list --format=...`) while the mutating git calls use `execFileSync` (argv). Both are static (no user interpolation, so not an injection bug), but the style split is divergent within one module. (Module is otherwise fully wired & sound: `snapshotWorkerScope`/`writeStashRef` at `worker.ts:281-282`; `rollbackWorkerScope`/`dropWorkerSnapshot`/`readStashRef`/`clearStashRef` at `result-evaluator.ts:289-303`; `revertFilesToHead` at `sprint-phases.ts:1319`.)

## Summary

Highest-impact cluster is the **worker verification + honest-assessment machinery**, which is broadly defined-and-tested but production-dead:
- `worker-verify.ts` — the entire tsc/vitest verify gate (`runTestVerifyLoop`/`runCompilationLoop`/`enforceVerifyLoop`, plus the fully-isolated `runCoverageVerify`) has **0 production callers**; the `.verify-ran` honesty marker is consequently never written. Verification is prompt/shell-driven (ADR-037 V1.0 advisory), so this is expected-but-undocumented dead code, not a regression.
- `worker-lifecycle.ts` — FeedbackLoop tracking and verify-delta calibration are likewise re-export-and-test-only; and `calculateSelfHealingRate` is a divergent duplicate of `sprint-metrics.ts` (number vs `SelfHealingRate|null`), with the lifecycle copy unused.
- `worker-ipc.ts` — the typed `process.send` channels (`WorkerChannel`/`WorkerSideChannel`) are never instantiated in production; only the file-based `askBrain` path is live.
- `worker-log.ts` — log **writer** (`appendWorkerLog` + formatters) is dormant while the **reader** (`readWorkerLog`) is wired into the API (write/read asymmetry).

Live & sound: `worker-rollback.ts` (full snapshot/rollback/drop/revert path wired) and the `WorkerStateMachine` registry in `worker-lifecycle.ts` (consumed by `sprint-spawner.ts`). `specialization-drift.ts` is wired via `sprint-reporter.ts`.

Cross-cutting root-cause: the recurring pattern is **"feature implemented + unit-tested + re-exported through `worker.ts`, but never invoked on the live worker execution path"** — the mock-only tests grant coverage that masks production dormancy. Secondary root-cause: unquoted `scope` interpolation into `execSync` in `worker-verify.ts` (latent injection, currently shielded only by the functions' dormancy).

Counts: unwired 3 · dormant 6 · inconsistent 5 · dead-test 1 · root-cause 5. No source modified (read-only audit).
