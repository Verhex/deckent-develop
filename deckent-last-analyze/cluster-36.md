## Summary
This cluster exposes deckent's recurring "built, tested, never wired" pattern: an entire external-notifications stack (notifications.ts `NotificationDispatcher` + DiscordNotificationProvider + notification-config validation) is exercised only by tests while production runs a *second*, separately-named dispatcher (`NotifyDispatcher`), so the user-configurable `notifications.discord/slack/webhook` knobs are honored by nothing live — the highest-signal root cause here. Type modules carry definition-only debt: `NervousSystemConfig` is declared twice with conflicting optionality (critical drift risk), `Alert.acknowledged`/`SkillMeta` are inert, and `ModelDefinition.provider` is forced to hold `'ollama'` through an unsafe double-cast outside its declared union. The model-registry shows duplication rot (dead `bootstrapFromCatalog`/`unregister`, tier-ordering re-implemented in mode-presets despite a "delegate here" contract), and the live `NotifyDispatcher` has a real latent bug — its throttle queue drains one item per timer and never self-reschedules, stranding extra non-critical notifications. multi-ide is the clean counter-example (genuinely wired; only a minor ADR-087 sync-I/O deviation), confirming the audit distinguished dead code from working code rather than flagging by surface shape.
