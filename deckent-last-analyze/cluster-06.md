### src/orchestra/backlog-trigger.ts
- [root-cause|high] RBAC backlog gate is advisory-soft by default (ADR-037 V1.0) — `backlog-trigger.ts:31` `const enforceRbac = (config as ConfigWithRbac).enforce_rbac === true;` → when `enforce_rbac` is absent/false (the default), `checkWorkerAuthority(req, { enforceRbac:false })` warn-only-returns `allowed:true`. It IS wired into the live autonomous dispatch (runtime-loop.ts:277 via `enforceEntryRbac` called at runtime-loop.ts:430), but the default-off flag means a role-denied backlog entry still proceeds — the authority guarantee is soft until an operator hand-sets the knob.
- [inconsistent|low] Stale "not-yet-declared" comment + redundant type-bypass cast — `backlog-trigger.ts:10-12` `// `enforce_rbac` is not yet declared on ResolvedConfig (MASTER-PLAN backlog). … type ConfigWithRbac = ResolvedConfig & { enforce_rbac?: boolean };`. The field is in fact declared on `ResolvedConfig` (`config-types.ts:814`, interface at `config-types.ts:788`), so the cast at `backlog-trigger.ts:31` is dead/redundant and the justifying comment is false.

### src/orchestra/baseline-tracker.ts
- [root-cause|high] `spawnSync` freezes the Brain event loop in two live orchestrator paths — `baseline-tracker.ts:85` `spawnSync('npx', ['vitest','run','--reporter=verbose'], { timeout: timeoutMs })` (default 180_000ms). Synchronously invoked from `sprint-controller.ts:1040` (sprint-start baseline) and `sprint-finalizer.ts:351` (finalize honesty check, 180s). Blocks the whole orchestrator process for up to 3 minutes — contradicts ADR-087 (Async I/O Standard) and the project's explicit "No spawnSync for subprocesses" rule.
- [inconsistent|high] `parseVitestOutput` mis-parses fail/skip counts — `pass` is anchored (`baseline-tracker.ts:109` `/Tests\s+(\d+)\s+passed/i`) but `fail`/`skip` are unanchored (`baseline-tracker.ts:111` `const failMatch = output.match(/(\d+)\s+failed/i);` + skipMatch). `.match` returns the FIRST occurrence, which in real vitest output is the `Test Files  N failed | …` line preceding `Tests  M failed`. So `baseline.fail` can capture the **file-fail** count, not the **test-fail** count — and that value feeds the honesty comparison `current.fail - baseline.fail` (`baseline-tracker.ts:198`), corrupting the very metric the module exists to compute.
- [inconsistent|medium] Canonical `checkWorkerHonesty` is unwired while its logic is duplicated divergently — `baseline-tracker.ts:220` `export function checkWorkerHonesty(...)` is the full structured pipeline (returns `HonestyCheckResult`), but it has NO production caller (only re-exported at `result-evaluator.ts:1936` + tests). The one consumer that needs it, `sprint-finalizer.ts:348-355`, hand-rolls the check (`containsHonestyTrigger` + `readBaseline` + `captureVitestBaseline` + raw `currentCapture.fail > taskBaseline.fail`), diverging from `compareBaseline` semantics (`baseline-tracker.ts:201` `claimValid: newFailures <= 0`) and discarding the structured reason/comparison.

## Summary
This cluster sits on the Brain↔reporting seam and is dominated by **build-but-never-wire** decay: three substantial modules — `batch-stats.ts`, `brain-context.ts`, and the `capability-realizer.ts` (AS4) layer — are fully implemented and tested yet have zero production callers, and `ci-reporter.ts`'s entire CI-Health/Learning surface is re-exported but never invoked in a real sprint. ADR-038 explicitly dispositioned two of them as Remove/Dead in Sprint 139, but the cleanup never ran, leaving stale tests that green-light the dead code. The genuinely-live code carries two real correctness risks: `baseline-tracker.parseVitestOutput` mis-anchors its fail/skip regex (corrupting the honesty-violation metric it feeds), and `captureVitestBaseline` blocks the orchestrator event loop via `spawnSync` (≤180s) on the live sprint-start and finalize paths. The recurring shape is soft-by-default guarantees (RBAC flag off, store-absent silent no-op) plus duplicate-divergent honesty logic — deckent's evaluation/CI-insight machinery is largely scaffolding the runtime never reaches.
