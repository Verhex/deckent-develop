### root-cause
- [root-cause|high] AST security scan silently disabled in production installs — `src/core/marketplace/skill-sandbox.ts:78` — `// TypeScript not available at runtime — skip AST scanning` / `return [];` (try/catch at :73-79 around `esmRequire('typescript')`) — `typescript` is a devDependency, so a production `npm install --omit=dev` makes the require throw and `scanCodeAST` returns `[]`. The obfuscation-detection guarantee (bracket-access `global['eval']`, `'ev'+'al'`, dynamic `import('child_process')`) collapses to a no-op exactly where untrusted marketplace code runs; only the coarse regex pass (`SUSPICIOUS_PATTERNS`) survives. The `return [];` at :78 is the line that makes the guarantee soft.
- [root-cause|high] CLI export still reaches the wipe path the guard was built to block — `src/cli/commands/memory.ts:107` — `writeFileSync(join(exportsDir, 'decisions.md'), exportDecisionsMd(store));` — `writeGuardedExports` (`memory-export.ts:414`, refuses to overwrite when "DB has N entries but render collapsed to the empty marker", added Sprint-227 after decisions.md was wiped 8518→2 lines) is wired ONLY into `sprint-finalizer.ts:1486`. The user-facing `deckent memory export` (memory.ts:106-109) and `runMemoryExport` (`identity-generator.ts:269-273`) bypass it, calling raw `export*Md(store)` + `writeFileSync`. Same renderers, two writers — one guarded, one not — so the catastrophic wipe remains reachable from the CLI/identity path.
- [root-cause|medium] `login()` stores a token without enforcing its own validator — `src/core/marketplace/marketplace-auth.ts:69` — `if (!token || typeof token !== 'string' || !token.trim()) {` — the only gate is non-empty; `validateToken()` (≥8 chars, no whitespace, :131) is never invoked, so a 3-char or whitespace-containing token is persisted to `marketplace.json` (0o600). Trust-without-verify: the format policy exists but the write gate does not apply it.
- [root-cause|medium] Version conflicts resolved by stripped-numeric "highest", never verified — `src/core/marketplace/dependency-resolver.ts:260` — `const partsA = a.replace(/[^0-9.]/g, '').split('.').map(Number);` — `resolveConflicts()` (:113-124) sorts with `_compareSemver` and picks the top, never throwing `DependencyConflictError`; `_compareSemver` discards every non-numeric char, so range operators (`^`,`~`) and prerelease tags are dropped and no version range is ever checked for actual satisfaction. Silent-fallback compatibility (mitigated today only because the whole resolver is unwired).
- [root-cause|medium] `exportAdrsToFs` skip-on-mtime can silently drop a fresh DB write — `src/core/memory-export.ts:353` — `if (fileMtime > dbUpdatedAt) {` `result.skipped++; continue;` — SQLite `updated_at` is second-precision (`datetime('now')`, parsed at :348-351) while FS `mtimeMs` is millisecond-precision, so a just-written ADR file can register `fileMtime > dbUpdatedAt` and be skipped under the "manual-edit-wins" heuristic. Combined with the function being unwired, the DB→FS reverse-sync guarantee is doubly soft.

## Summary
core#12 splits cleanly into a **wired memory subsystem** and a **largely-dormant marketplace subsystem**. The memory export/import/normalize core is live, but its safety/repair edges are weak: the Sprint-227 wipe-guard protects only the sprint-finalizer path while the user-facing `memory export` CLI and identity-generator still write unguarded (the documented 8518→2 catastrophe is still reachable), and a cluster of relation-backup/backfill migration helpers plus the ADR reverse-sync (`exportAdrsToFs`) are stranded with test-only callers. The marketplace is mostly facade: `RatingSystem` and `DependencyResolver` (with its never-thrown `DependencyConflictError`) have zero production callers, the `SkillSandbox` trust set and `quarantine` remediation are inert, `validateToken` is never enforced (login trusts any non-empty string), and — most serious — `scanCodeAST` silently returns `[]` when the `typescript` devDependency is absent, disabling obfuscation detection precisely on production installs that run untrusted skill code. The dominant deckent signal here is **guarantees that exist in code but aren't on the live path** (opt-in guard, advisory trust/quarantine, soft AST scan), reinforcing the project's known advisory-soft-enforcement pattern.
