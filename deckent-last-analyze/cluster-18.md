### spawn-coordinator.ts

The Sprint 195/196 OOM-postmortem safety cap (`<8GB→1 … 32GB+→4`) therefore only changes a `doctor --memory` readout — actual worker count is decided by a different formula that never consults the tier cap, so the OOM guarantee is soft.

## Summary
This cluster is the sprint-lifecycle spine, and the dominant pattern is **written-but-never-read**: an entire estimator module, the Task-030 dependency-graph resume-restore (`restoreDepGraph`), two checkpoint resume helpers, the adaptive-timeout helpers + their config knobs, and four sprint-doc maintenance functions are all zero-caller — many landed as "to be wired in a follow-up" that never came. The higher-risk findings are guarantees made soft by their wiring: the WSL2 OOM worker-cap is bypassed by the real spawn path, the self-audit honesty gate can never trip under default config, and `deckent finalize` re-grades through the explicitly-deprecated `evaluateResult` copy that lacks the reconciliation the rest of the codebase uses. Finalize also still runs tsc+vitest via `spawnSync`, contradicting the project's own ADR-087 async-I/O standard. Net: deckent accretes capability faster than it wires it, and several "enterprise" safety/quality gates are present in code but inert at runtime.
