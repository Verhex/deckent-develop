- [inconsistent|low] webhook durable inbox grows unbounded and is fully re-read every poll — `src/orchestra/autonomous/webhook-reactive-source.ts:92,102` — `const lines = read(deps.inboxPath).split('\n').filter(...)` then `offset = lines.length; writeOffset(offsetPath, offset);`. The "durable atomic-append inbox" design (header `:5-12`) has no compaction counterpart, so a long-running engine pays O(n) per poll and the inbox file size is monotonic.

- [root-cause|high] authority gate is bypassed by an unverified string-prefix on the autonomous execute path — `src/orchestra/autonomous/runtime-loop.ts:364-368` — `check(action, requestedBy) { if (action === AUTONOMOUS_EXECUTE_ACTION && requestedBy.startsWith('system')) { return { outcome: 'allowed', reason: 'trusted internal engine trigger (policy gate governs)' }; } return baseAuthority.check(...); }`. Any trigger whose `requestedBy` merely *begins with the literal string* `'system'` is granted authority with no identity verification. `work-generator-source.ts:40` sets exactly that: `requestedBy: entry.tenant ? \`system:${entry.tenant}\` : 'system'`. ADR-037's default-deny authority is thus softened to a naming convention — the comment itself concedes "the per-task policy gate become[s] the real governance layer," i.e. the authority check is no longer the guarantee it claims to be for the most powerful action (execute task/sprint).

- [root-cause|high] role-based EXECUTE permission is checked only behind an opt-in flag (default-off → advisory) — `src/orchestra/autonomous/runtime-loop.ts:419,438-449` — `const rbacPolicy = opts.config.autonomous?.rbac_policy;` ... `if (rbacPolicy?.enabled) { const verdict = evaluatePolicy({ rbac: { role: rbacPolicy.role ?? When `autonomous.rbac_policy` is absent/disabled (the default) the `Permission.EXECUTE` check is skipped entirely. The sibling `enforceEntryRbac` layer (`:430`) is likewise flag-gated — its own doc at `:256-261` states "when `config.enforce_rbac` is off they soft-warn + audit but return `allowed:true`." So by default both role gates permit every machine-initiated dispatch; the architectural RBAC rule (ADR-037) is unenforced unless an operator opts in — guarantee-soft by design.

- [root-cause|medium] repo-watch failure is swallowed into a permanent silent no-op (no log/emit) — `src/orchestra/autonomous/reactive/repo-watch-reactive-source.ts:44-51` — `try { const watcher = fsWatch(projectRoot, { recursive: true }, ...); return { close: () => watcher.close() }; } catch { return { close: () => {} }; }`. The catch converts *any* watcher-construction error (recursive-watch platform limitation, EMFILE fd exhaustion, permission denial) into a handle whose `onChange` never fires — the entire repo-watch reactive trigger goes dead with zero diagnostics. Because the source is started fire-and-forget (`autonomous.ts:635,642` → `source.start()`), an operator who enabled `reactive.repo_watch` gets a silently inert feature and no signal that working-tree changes are no longer being observed.

- [root-cause|medium] multi-tenant audit silently collapses a missing tenant to a shared 'local' bucket — `src/orchestra/autonomous/runtime-loop.ts:316-320` — `writeAuditEvent(opts.projectRoot, 'autonomous', { tenantId: record.actor?.tenantId ?? sessionTenantId ?? 'local', actor: record.actor?.id ?? opts.actor?.id ?? 'system', ... })`. When neither the per-record actor nor the session actor carries a `tenantId`, every capability-invocation audit event is attributed to the literal tenant `'local'`. For the ENT-2/ENT-3 enterprise tenant-isolation story this is a silent-fallback: events from distinct unauthenticated/legacy paths are co-mingled under one tenant id in the audit hash-chain, with no error surfaced — tenant isolation degrades quietly rather than failing closed.

- [root-cause|low] corrupt or non-webhook inbox events are silently dropped while the offset advances past them — `src/orchestra/autonomous/webhook-reactive-source.ts:95-103` — `try { const ev = JSON.parse(line); if (isReactiveEvent(ev)) deps.ingester.ingest(ev); } catch { /* skip a corrupt line */ } ... offset = lines.length; writeOffset(offsetPath, offset);`. A malformed JSON line is dropped, and a well-formed but non-`webhook` event silently fails the `isReactiveEvent` guard (`:53-57`, `:97`); in both cases the line is permanently skipped because `offset` jumps to `lines.length`. The "no loss of events" durability promise (header `:10-12`) holds only for valid `webhook` events — invalid ones vanish with no audit/log entry.

- [root-cause|low] work-generator error paths suppress failures with no telemetry — `src/orchestra/autonomous/work-generator-source.ts:31-33,84-88` — `try { candidates = opts.generate(); } catch { return null; }` and `try { items = loadDebt(); } catch { return []; /* fail-safe: debt store unavailable must never break the loop */ }`. The fail-safe design is deliberate, but every failure mode (a throwing generator, an unavailable/locked SQLite debt store) is converted to "no work this tick" with zero log/emit. A persistently broken debt store therefore looks identical to "no active debt" — the autonomous engine appears healthy while silently producing nothing, and there is no signal an operator can act on.

## Summary
orchestra#6 is the live wiring spine of the autonomous engine, and the audit confirms the headline functions (`buildEngineRuntime`, `runAutonomousLoop`, both reactive sources, `makeDebtWorkGenerator`) are genuinely wired through `cli/commands/autonomous.ts`, `api/reactive-endpoint.ts`, and `process-runtime.ts` — there are no false "unwired big functions." The real risks are governance-softness root-causes: the authority gate is bypassed by an unverified `requestedBy.startsWith('system')` prefix (`runtime-loop.ts:364`), and role-based EXECUTE/RBAC is enforced only behind opt-in flags that default off (`:419,438` + `:256-261`), so ADR-037's guarantees are advisory on the very path that runs tasks and sprints autonomously. A recurring silent-fallback pattern (repo-watch no-op on watcher failure, audit tenant→'local', webhook corrupt-line drop, work-generator catch→empty) means several failure modes degrade quietly with no operator-visible signal. Secondary debt: `scheduled-flow.ts` is a test-only re-export shim, the TODO/FIXME work-generation half is dormant (no production scanner), and `deriveEntryCapabilities` is duplicated across `runtime-loop.ts` and `execute-dispatcher.ts` with only a comment guarding against drift.
