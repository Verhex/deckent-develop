## Summary
core#5 is a cost-safety + secrets cluster where the **safety machinery is real but partly unwired or built on unverifiable inputs**. The single biggest signal is dead security infrastructure: the entire AES-256-GCM credential store (`credentials.ts` + `credential-encryption.ts`) has zero production callers and is exercised only by its own tests — an enterprise-grade secret-store that no auth path uses (independently confirmed by the Phase-1 UNW-019/UNW-A035 findings). The cost subsystem is mostly live (`evaluateCostGate`, `estimateSprintCost`, `buildLedgerPrices` are all wired through CLI+MCP `start`), but its richest contracts are dormant: the per-request `budget` ceiling (`maxUsd`/`maxTokens`, WM-1/ENT-5) is never supplied by any caller, and config knobs `rate_limits` + `alert_thresholds` are shipped-and-validated yet never read. Where the gate does run, its protective number rests on a fabricated subscription-quota heuristic and a silent-$0-on-missing-price path, so the "shield" can quietly under-report. Coverage/criteria modules are healthy except for a few zero-caller exports (`wroteTestsForStack`, `getCoverageAdapter`, `isNonBuildKind`, `cleanProofLine`) and a stale docstring whose named caller does not exist — classic export-surface-without-consumer drift.
