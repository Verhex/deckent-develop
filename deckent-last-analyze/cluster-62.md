# api#2 — HTTP API endpoints (evolution / live-events / memory-search / token-mw / missions / nervous / oidc / output-stream)

Code-only audit of 8 modules. Every finding is grep-verified and carries file:line + a proving snippet. Cross-referenced `src/api/server.ts` (route wiring) and `src/api/auth.ts` (auth model) read-only. Source UNCHANGED.

## Findings

- [root-cause/hardcoded-0-metric|high] `/api/nervous/status` returns a permanently empty detector list — `src/api/nervous-endpoint.ts:133` — `detectors: [] as Array<{ id: string; name: string; enabled: boolean; triggerCount: number }>,` is a literal; the file imports nothing from the nervous detector-registry (`src/nervous/detector-registry`). The dashboard NervousPage can therefore NEVER show a real detector or triggerCount — the metric is hard-zeroed at the source. A real registry exists in `src/nervous/` but is never consulted by this endpoint.

- [root-cause/trust-without-verify|medium] `/api/nervous/status` reports `panicGuard: true` unconditionally — `src/api/nervous-endpoint.ts:132` — `panicGuard: true,` is a hardcoded literal; the handler reads no toggle/config/runtime state before claiming the panic-guard is enabled. Every caller (dashboard, status) is told the guard is on regardless of the actual nervous-system state.

- [dead-test/tautological|medium] nervous-status test asserts TYPE, not VALUE — locks in the hardcoded metric — `tests/api/nervous-endpoint.test.ts:26-27` — `expect(typeof body.panicGuard).toBe('boolean'); expect(Array.isArray(body.detectors)).toBe(true);`. Against the hardcoded `panicGuard: true` / `detectors: []` (findings above) these assertions can never fail and never verify that detectors reflect real state. The test rubber-stamps the hard-zeroed metric instead of catching it.

- [inconsistent/dormant|high] `/api/output-stream` SSE is excluded from `queryTokenPaths`, so an `EventSource` client cannot authenticate to it — `src/api/output-stream.ts:143` + `src/api/server.ts:685,1297-1298` — server.ts:1298 `queryTokenPaths: ['/api/events', '/api/chat/stream']` omits `/api/output-stream`; the route is dispatched at server.ts:685 AFTER the blanket auth gate (server.ts:452-453). `auth.ts:243` only honors a `?token=` fallback for `queryTokenEligible(path)` paths, and output-stream is in NEITHER `queryTokenPaths` (server.ts:1298) NOR `queryTokenPrefixes` (server.ts:1303). The one loopback auto-inject bypass (auth.ts:200-208) is opt-in and DEFAULT-OFF: `serve`'s auth config omits `allowLocalhostAutoInject` (server.ts:1291-1305) and `DECKENT_API_LOCALHOST_AUTO` is unset, so `allowLocalhostAuto` is false (auth.ts:176-178) and a loopback `EventSource` is NOT waved through. Browser `EventSource` cannot set an `Authorization` header (cf. the chat/stream comment server.ts:694-695 and token.ts:11-14). Because server.ts:1242-1244 AUTO-MINTS a localhost token by default, the dashboard's worker-output stream gets 401 in the default config — the feature is dormant out-of-the-box, inconsistent with the two sibling SSE endpoints that ARE query-token eligible.

- [unwired|low] `resolveBootstrapApiToken` has zero production callers — `src/api/middleware/token.ts:37` — grep('resolveBootstrapApiToken') hits only the definition (token.ts:37), the file's own doc-comment (token.ts:5), and `tests/api/auth-bootstrap.test.ts`. The actual inject path in server.ts resolves the token via `resolveAuthToken(resolvedToken)` directly (server.ts:1224) and never calls this wrapper. The module doc advertises it as step 1 of the "Wire (Sprint 191 Task 191-010)" (token.ts:5-6) but the wire bypasses it — it is an exact-equivalent dead re-export of `resolveAuthToken`.

- [inconsistent|medium] evolution-endpoint has no fail-safe error handling — diverges from sibling read endpoints — `src/api/evolution-endpoint.ts:41-55` — `buildFamilyTree()` (l.27), `listRetired()` (l.35), `collectMetrics(...)` (l.51) are all called with no try/catch and no existsSync guard. Compare `missions-route.ts:44` (fail-safe empty list on missing db) and `memory-search-endpoint.ts:35,44` (existsSync guard + `finally { store.close() }`). A throw here propagates to the server IIFE catch (server.ts:1600-1601) which returns `500` with the raw `err.message` — an inconsistent error contract plus a mild internal-message leak relative to the honest empty/`finally` siblings.

- [inconsistent|low] output-stream hardcodes wildcard CORS, diverging from the server's computed origin policy — `src/api/output-stream.ts:94` — `writeSseHeaders` sets `'Access-Control-Allow-Origin': '*'` whereas the main server computes a per-request `allowedOrigin` and appends `SECURITY_HEADERS` (server.ts:442-445). The worker-output SSE stream is readable cross-origin regardless of the server-wide CORS decision.

- [inconsistent/dormant|low] nervous `pending` union is eager-computed on every call, including mutating POSTs that never read it — `src/api/nervous-endpoint.ts:121` — `const pending = [...listPendingPanicEvents(projectRoot).map(toPendingApproval), ...readNervousPendingApprovals(projectRoot)];` runs before any route match. POST `/accept`, `/reject`, and `/recommendations/dismiss` (l.150-178) never reference `pending`, yet each pays the dir-scan (`listPendingPanicEvents`) + file-read (`readNervousPendingApprovals`) I/O. Dead compute on the write paths.

- [inconsistent|low] `extractTokenFromQuery` hand-rolls query parsing instead of `URLSearchParams` — `src/api/middleware/token.ts:62-76` — manual `indexOf('?')` / `split('&')` / `decodeURIComponent` loop, while every other module in this cluster parses the same query shape via the URL API: `memory-search-endpoint.ts:25`, `nervous-endpoint.ts:115`, `missions-route.ts:40` use `new URL(url,'http://localhost')`, and `output-stream.ts:112` uses `new URLSearchParams`. Divergent parsing of the same `?token=` input (behaviour-equivalent, but a duplicate hand-rolled parser).

## Summary
8 modules audited. **0 unwired route handlers** — every `register*Route`/SSE export is wired in `server.ts` (evolution:814, memory-search:818, nervous:819+860 [both GET+POST, intentional — handler is method-aware], missions:821, oidc:867, output-stream:685, live-events bridge:1354). Highest-impact findings cluster in two places: (1) **`/api/nervous/status` hard-zeros `detectors` and hard-trues `panicGuard`** (nervous-endpoint.ts:132-133), and a **tautological test** (nervous-endpoint.test.ts:26-27) locks that in; (2) **`/api/output-stream` is unauthenticatable via `EventSource`** under the default auto-minted localhost token (excluded from `queryTokenPaths`; auth has no loopback bypass) — a dormant-by-default user-surface feature. One genuine unwired dead export (`resolveBootstrapApiToken`). Remaining findings are divergent-pattern inconsistencies (evolution missing fail-safe vs siblings; wildcard CORS; eager pending compute on POST; hand-rolled query parser). `live-events.ts`, `oidc-callback-endpoint.ts`, and `missions-route.ts` are clean — strong fail-safe/fail-closed design with real (non-mock-only) hermetic tests.
