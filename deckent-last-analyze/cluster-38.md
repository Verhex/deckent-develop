## Summary
core#16 is the lifecycle "side-channel" cluster (notifications, observability, output capture, cleanup) and it shows deckent's recurring dogfood pattern: machinery is built, unit-tested, and exported, then never wired into the live sprint path. Two findings are high-severity and user-visible: PanicGuard is structurally hard-wired to BLOCK (its only caller passes `undefined` opts, so the approval/notify workflow is unreachable and stuck workers get a silent synthetic NO_GO), and the live worker-output pipeline (`OutputCollector.collect()`) is never invoked in production, so the `/api/output-stream` SSE feature always returns empty. Supporting these are a cluster of test-only exports (`notifyProgress`, `getEmoji`, `shouldRotate/readArchivedMetrics/listArchives`, `getObservabilitySprintId`, `preflightOrphanCleanup`, `cleanOrphanIpcDirsLegacy`, `followDockerOutput`, `buildNotification`), latent root-causes (spawnSync in the would-be polling loop violating ADR-087; corrupt-task-file-archived-as-terminal silent fallback), type-soundness debt (`'ollama' as unknown as RegistryProviderName` double-cast), and two genuinely tautological tests (the regex-as-literal-string network guard and the hard-coded-constant assertion). Net signal: the gap between "implemented + green tests" and "actually reachable at runtime" is the dominant defect class here.
