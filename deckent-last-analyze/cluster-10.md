## Findings

- [root-cause|high] EventBus's documented synchronous in-process delivery path does not exist — `src/orchestra/event-bus.ts:54` — proof: class doc says `eventBus.publish(event);  // called automatically by writeEvent()` and the `publish` param doc `@param sprintId - Sprint context for filtering (passed by writeEvent)` (`event-bus.ts:75`), but `writeEvent` now lives in `core/event-stream.ts` and that file has **zero** reference to `eventBus`/`publish` (verified: `grep eventBus\|publish src/core/event-stream.ts` → none; ADR-008 forbids `core/ → orchestra/`). The only real `publish()` callers are `src/connectors/incoming-router.ts:185` and the `watchFile` self-republish at `event-bus.ts:218`. So in-process subscribers receive sprint events **only** if someone explicitly starts `watchFile()` (fs.watch); the writer never notifies the bus. The comment promises a wiring the layering makes impossible.

- [dormant|medium] `publish()` `sprintId` subscriber-filter is never exercised at runtime — `src/orchestra/event-bus.ts:78` — proof: the guard `if (sprintId && sub.sprintId !== '*' && sub.sprintId !== sprintId) continue;` only fires when `sprintId` is truthy, but **both** real callers pass no sprintId: `incoming-router.ts:185` (`eventBus.publish(event)`) and `event-bus.ts:218` (`this.publish(event)`). A subscriber that scoped itself to one sprint via `subscribe('sprint-145', …)` (`status.ts:363`) therefore receives events from any watched sprint file — the per-sprint isolation the filter advertises is dead code.

- [root-cause|medium] Handoff "ready" gate is existence-only (trust-without-verify) — `src/orchestra/handoff-protocol.ts:78` — proof: `executeHandoff` promotes status to `'ready'` when every artifact passes `if (!existsSync(fullPath)) missing.push(artifact)` (`:76-86`) — no size/content/freshness check, so a zero-byte or stale artifact satisfies the gate. The downstream consumer `src/orchestra/task-builder.ts:1324` (`for (const h of protocol.listHandoffs())`) treats these as verified inputs to the worker prompt. Compounding: the sole caller `src/orchestra/sprint-controller.ts:659` (`handoffProtocol.executeHandoff(handoff.id);`) **discards** the `{success, missingArtifacts}` return, so a `success:false` (missing-artifact) result triggers no failHandoff/cascade.

- [root-cause|high] `core/ → orchestra/` reverse import keeps an architectural-rule (ADR-008) soft — `src/orchestra/ecosystem-intelligence.ts:178` — proof: `export function analyzeSkillInMemory(...)` is imported by `src/core/routing-engine.ts:30` (`import { analyzeSkillInMemory } from '../orchestra/ecosystem-intelligence.js'`) and called at `routing-engine.ts:945`. `core/` consuming an `orchestra/` function violates ADR-008's one-way dependency; the ADR-008 lint (`authority-enforcer.ts`) is advisory/soft per ADR-037 V1.0 so the violation persists (also tracked in `.brain/exports/decisions.md:212`). The orchestra-side symbol is the consumed end of the breach.

- [inconsistent|medium] Re-export shim diverges from the module it shims — `src/orchestra/event-stream.ts:19` — proof: the shim adds `export const SCOPE_INSUFFICIENT_CHANNEL = 'WORKER→BRAIN:SCOPE_INSUFFICIENT';` which is **absent** from the canonical `core/event-stream.ts` (verified: `grep SCOPE_INSUFFICIENT src/core/event-stream.ts` → none). This contradicts the same file's own header: "Behavior is byte-for-byte identical" (`:13`) and "New code should import from `../core/event-stream.js` directly" (`:15`). Code that follows that instruction and imports the channel from `core/` fails; both live consumers (`agentic-worker-runner.ts:38`, `sprint-phases.ts:148`) must import from the shim, defeating the migration the shim exists to enable.

- [inconsistent|medium] Intent-scoring logic duplicated verbatim across two exported functions — `src/orchestra/ecosystem-intelligence.ts:121` — proof: `analyzeNewSkill` steps 4–6 (score map `:121-135`, top-3 rule build `:137-155`, exclusion build `:157-162`) are byte-identical to `analyzeSkillInMemory` (`:196-207`, `:209-225`, `:227-231`); only the input-gathering differs (filesystem read + `contentKeywords` vs in-memory fields). The score thresholds (`count >= 3 ? 10 : count >= 2 ? 8 : 5`), fallback rule (`score:3`) and `minScore:5` are copied, not shared — any tuning must be applied in two places or the two routing paths silently drift.

- [inconsistent|low] Stale module header marks a wired module as un-wired — `src/orchestra/evaluation-audit-trail.ts:8` — proof: header states "Wire-up (calling writeEvaluationAudit from result-evaluator / sprint-phases) is intentionally out of scope for Task 1 — it lives in Sprint 157 T-004." But `writeEvaluationAudit` is wired live in `src/orchestra/sprint-phases.ts:1495` (EVALUATE phase) and `:1900`/`:1902` (FIX phase). A reader trusting the header would treat an active forensic-audit writer as dead code.

- [inconsistent|low] Defaults applied twice with unclear ownership — `src/orchestra/execution-request-builder.ts:144` — proof: `buildExecutionRequest` already defaults `effort: input.effort ?? - [unwired|low] `BusEvent` interface exported but has no consumer — `src/orchestra/event-bus.ts:27` — proof: repo-grep for `\bBusEvent\b` returns only the definition here; `publish()` takes `DeckentEvent` + `sprintId` as separate params, never a `BusEvent`. Exported dead type.

## Summary
orchestra#11 is mostly live wiring (handoff protocol, execution-request builder, doc-updater types, and the evaluation-audit writer are all really consumed), so the cluster's weak points are not dead modules but **soft guarantees and layering scars**. The sharpest is the event subsystem: ADR-008's `core/→orchestra/` prohibition means `core/event-stream.writeEvent` cannot notify `orchestra/event-bus`, so the bus's headline "publish() is called automatically by writeEvent()" promise is impossible and its `sprintId` subscriber-filter is never fed — in-process delivery silently degrades to fs.watch polling. The same one-way rule is actively breached the other direction (`routing-engine → ecosystem-intelligence`) and tolerated only because ADR-037 keeps enforcement advisory. Documentation rot (a "byte-for-byte identical" shim that isn't, a "not wired yet" header on a wired writer) plus verbatim-duplicated scoring logic show the cluster's trust-without-verify and copy-not-share habits that let drift accumulate. No test files were in scope, so the dead-test category is N/A.
