### output.ts
- [inconsistent|medium] `--follow` slices a decoded string by a BYTE offset → multi-byte output desyncs — `src/cli/commands/output.ts:111` (`const newContent = content.slice(lastSize);`) where `lastSize = stat.size` (`:118`, `:100` — file size in BYTES from `statSync`) but `content` is a UTF-8-decoded string and `String.slice` indexes UTF-16 code units. For any non-ASCII tail (Turkish text, emoji) `stat.size` ≠ `content.length`, so the "new lines" slice starts at the wrong character and prints garbage/duplicates. The parallel tailer in `nervous.ts` does it correctly — `showLog` uses `lastSize = readFileSync(...).length` (string length) with `content.slice(lastSize)` (`nervous.ts:488-495`); the two follow implementations diverge on the byte-vs-char unit.

## Summary
This cluster is **command-surface debt**: most files are live and well-formed, but a recurring pattern is **flags/options/branches that are wired into commander but dead in the body**. Three commands have a *broken headline behavior* hidden behind a green-looking surface: (1) `onboard`'s "run init" step spawns `deckent init --mode … --language …` against an `init` that defines neither option, so commander rejects it and every confirmed onboarding silently "skips" init (`onboard.ts:189-202`); (2) `plugin update` just calls `installPlugin`, which throws "already installed", so it can never update an existing plugin (`plugin.ts:64` + `core/plugin.ts:342`); and (3) `rbac grant`/`revoke` write a process-local Map that `can()` never consults and the OS discards at exit, so RBAC grants are pure theater (`rbac.ts:15,77` — the matching `rbac-grant.test.ts` only asserts the in-memory write, masking it). A second cluster is **audit-integrity / trust-without-verify in the nervous surface**: CLI `nervous edit` writes an `'accepted'` history record with no executor and no IPC routing — the exact "audit lie" the adjacent `handleAccept` documents and guards against, and a divergence from the already-fixed chat edit path (`nervous.ts:388-392`). Lower-severity but real: `init`'s `--upgrade` (never read) and `--repair` (`failedSteps` never populated) advertise recovery features that don't exist; `mcp add/remove` strips the Claude-standard `mcpServers` envelope on write-back; `memory`'s error paths print-then-exit-0 (divergent from every sibling command); `output --follow` slices a decoded string by a byte offset (breaks on multi-byte tails); `plan`'s sprint-size note is unreachable behind a frozen `size:'full'`; `models` mis-pads the STATUS column after coloring; `mode global process` is accepted while its help claims only `sprint|task`; and `quick-start.readDirectivesContent` is dead test-only surface. Highest-value fixes: wire (or delete) the `onboard→init` `--mode`/`--language` contract, give `plugin update` a real remove-then-install, and either implement `rbac` persistence+lookup or stop printing GRANTED for a no-op.
