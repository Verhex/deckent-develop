## Findings

- [unwired|medium] `createStreamOutputHandler` + `StreamOutputHandler` have zero production callers — `src/cli/repl/native-transport.ts:101` — `export function createStreamOutputHandler(emit: (seg: Segment) => void): StreamOutputHandler {` (and iface at `:84`) — grep of `src/` shows the ONLY importer is the test `tests/cli/repl/native-transport.test.ts:11`; no production module imports it. The whole "stream output handler" seam (`:84`–`:108`) is dead in prod.

- [inconsistent|medium] Module doc-comment claims a consumer that does not exist — `src/cli/repl/native-transport.ts:8` — `// consumers of the native transport layer use createStreamOutputHandler() to` — the header (`:7`–`:10`) asserts this is "the canonical streaming seam" used by transport consumers, but no consumer uses it (see finding above). - [dormant|low] Re-exports of the segmenter from native-transport are never imported through this path — `src/cli/repl/native-transport.ts:77` — `export type { Segment } from './stream-segmenter.js';` / `:78 export { createStreamSegmenter } from './stream-segmenter.js';` — every prod consumer imports `Segment`/`createStreamSegmenter` straight from `./stream-segmenter.js` (`app.tsx:20`), not via native-transport. - [dormant|low] `LEGACY_TIER` `confirm`/`always` branches are unreachable from the only callsite — `src/cli/repl/native-tool-registry.ts:99` — `const tier = LEGACY_TIER[classifyTool(name, {})];` — the registered CLI tools are all read-only (`:98` `['deckent_status','deckent_history','deckent_retro','deckent_doctor','deckent_models','deckent_review']`). `classifyTool` returns `'read'` for every one of them (none are in `ALWAYS_CONFIRM`/`CONFIRM_TOOLS`, `tool-permissions.ts:43`–`:64`), so the lookup is the constant `'silent'`; `LEGACY_TIER.confirm`/`.always` (`:32`–`:33`) and the per-name `classifyTool(...)` call are effectively dead/no-op here.

- [inconsistent|medium] Native-agent path exposes a strictly narrower CLI tool surface than the legacy dispatcher — `src/cli/repl/native-tool-registry.ts:98` — only 6 read-only CLI tools are registered, whereas the legacy default path (`run.tsx:91 createCliToolDispatcher()` → `run.tsx:137 cliDispatcher.dispatch`) can dispatch the full set including confirm/`always` tools (`deckent_plan`/`sync`/`kill`/`cleanup`, per `tool-permissions.ts:18`–`:31`). ## Summary
8 source files read in full; 16 findings. The dominant issue is a **dead public streaming seam**: `createStreamOutputHandler`/`StreamOutputHandler` in `native-transport.ts` is exported, doc-blessed as "canonical", and tested — yet has zero production callers (`app.tsx` uses `createStreamSegmenter` directly), and the module header still claims consumers use it. Secondary: the native-agent path diverges from the legacy path in tool surface (read-only 6-tool CLI registry vs full dispatcher) and pins model-id defaults as raw literals divergent from the model-registry SSOT (stale-id risk). The exec-tool name list is duplicated in 3 places. Root-cause cluster is silent-fallback / trust-without-verify: hardcoded `alwaysApprove → true` for MCP confirm, string-prefix success detection, swallowed teardown/MCP/config errors, and `n/a`-collapsing version probes — none block, all degrade quietly. Dead-test: one tautological `tmux` label assertion; `resolveNativeProvider` coverage duplicated across `tests/cli/` and `tests/cli/repl/`. No source modified (read-only audit).
