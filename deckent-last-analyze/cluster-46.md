## Findings

- [dormant|high] `DecisionEngine.decide()` risk-gate is unreachable in production — the `request` arg is never passed — `src/nervous/decision-engine.ts:83` — the entire F10-002/WM-6 governance block `if (request && this.isRiskGateEnabled()) { … riskClass === 'high' → policy: 'approve' }` (`:83-96`) only fires when a `RiskGateRequest` is supplied as the 2nd arg of `decide(detectorResult, request?)` (`:50`). Repo-grep of `.decide(`: the SOLE live caller is `src/nervous/bootstrap.ts:282` `const decisions = decisionEngine.decide(result)` — one arg, no request. The other two hits are unrelated: `src/orchestra/autonomous-runtime.ts:227` is `deps.policyGate.decide(trigger)` (a different object) and `src/orchestra/decision-replay.ts:39` `engine.decide(task)` runs against `DecisionOrchestrator` (a `@deprecated`, test-only module — `decision-replay.ts:2-9`). So the nervous risk-gate can never park a high-risk action at runtime; the whole high-risk-→-approve governance path is dead.

- [root-cause|medium] `isRiskGateEnabled()` reads an undeclared config field via a structural cast — `src/nervous/decision-engine.ts:110` — `return (this.config as NervousSystemConfig & { risk_gate_enabled?: boolean }).risk_gate_enabled === true`. The comment (`:101-109`) admits `risk_gate_enabled` is NOT on `NervousSystemConfig` ("Declaring it on NervousSystemConfig (core/) is a typed follow-up — out of this task's scope"). Effect: the flag is untyped (no compile-time guard against a renamed/misspelled key) and absent → `false` → silent no-gating. Compounds the dormant risk-gate above: even if a `request` were threaded through, the gate is off unless an untyped config key is hand-set.

- [unwired|medium] `authorizeExecution` (ENT-1 / ADR-037 V2 bridge) has zero production callers — `src/nervous/authority-matrix.ts:413` — repo-grep for `authorizeExecution`: only the definition here, `tests/nervous/authority-matrix.test.ts:111/412/423/435`, and docs (`docs/CHANGELOG.md:545`, `docs/reference/enterprise-depth.md:40/51`, `docs/SPRINT-LOG.md:7072`). The doc-comment claims it is "suitable for direct consumption in spawn-path callers" (`:386`) but no spawn-path file imports it — the two live RBAC entry points (`src/orchestra/backlog-trigger.ts:32`, `src/orchestra/sprint-runtime.ts:31`) call `checkWorkerAuthority` directly, bypassing the bridge. A built-and-tested wrapper that production never reaches.

- [unwired|medium] `DecisionEngine.shouldDelay()` (quiet-hours suppression) is never called in production — `src/nervous/decision-engine.ts:124` — repo-grep `shouldDelay` over `src/`: the only hit is the method definition. The bootstrap pipeline `runPipeline` (`src/nervous/bootstrap.ts:273-306`) routes `decide → propose → dispatch/execute` and never consults `shouldDelay`, so `quietHours` config + `isInQuietHours` (`:143`) cannot defer any info/warning notification at runtime. The quiet-hours feature is fully built (and tested, see dead-test below) but dormant.

- [inconsistent|medium] Name collision: two unrelated `checkWorkerAuthority` functions with divergent signatures — `src/nervous/authority-matrix.ts:316` vs `src/agents/worker.ts:584` — the nervous one is `(req: Pick<ExecutionRequest,'actor'|'requirements'>, opts) => WorkerAuthorityResult` (capability/role RBAC). Both are branded "ADR-037 soft" and both only `console.warn` on violation (`authority-matrix.ts:377`, `worker.ts:603`), yet they are entirely separate code with the same name — a reader grepping `checkWorkerAuthority` cannot tell which authority model is in play at a callsite.

- [inconsistent|low] Divergent duplicate `ROLE_CAPABILITY_MAP` — `src/nervous/authority-matrix.ts:213` vs `src/core/capability-broker.ts:33` — nervous declares `Readonly<Record<WorkerRole, ReadonlySet<Capability>>>` over a fixed 4-role taxonomy (`admin|engineer|operator|viewer`); core declares `Record<string, Capability[]>` (open-string roles, array values, `:33-50`). Two role→capability authorities of record with different key spaces and value types; `config-types.ts:818` references the core one while ENT-1 enforcement uses the nervous one — no single source of truth for "what a role may do".

- [dormant|low] WORKER_RESPAWN direct kill+spawn branch is inert in the default/standalone path — `src/nervous/action-handlers.ts:137` — `if (deps.canRespawn) { deps.killWorker(taskId); deps.spawnWorker(taskId); … }` is gated on `canRespawn`, whose default is `false` (`:288`); the default `killWorker`/`spawnWorker` deps are explicit no-op placeholders (`:246-254`, "Inert placeholder"). Documented 3-tier design, but the tier-1 branch + its placeholder deps are dead at every current callsite.

- [dormant|low] `idleThrottleMultiplier` is hard-wired to the literal `1`, self-labelled unwired — `src/nervous/bootstrap.ts:193` — `1, // idleThrottleMultiplier (unwired here — preserves current default)` passed positionally into `new NervousObserver(...)`. - [dead-test|medium] The risk-gate test suite exercises a production-unreachable path — `tests/nervous/f10-002-risk-gate.test.ts:89` + `tests/nervous/decision-engine.test.ts:43-49` — both build a `RiskGateConfig = NervousSystemConfig & { risk_gate_enabled?: boolean }` and call `decide(detectorResult, request)` with the 2nd arg, asserting high-risk → `approve`. - [dead-test|low] Full test coverage over zero-caller methods — `tests/nervous/decision-engine.test.ts:316-388` (7 `shouldDelay()` cases), `tests/nervous/action-registry.test.ts:80` (`getActionsByCategory`), `tests/nervous/authority-matrix.test.ts:409-435` (`authorizeExecution`) — each thoroughly tests a function with no production caller (see unwired findings). The tests pass and inflate the module's coverage number while the exercised code is unreachable in the live pipeline.

- [root-cause|low] `checkWorkerAuthority` is advisory-soft at the decisive line — `src/nervous/authority-matrix.ts:352` — `const enforced = opts.enforceRbac === true;` then on a real role violation `:377-378` `console.warn(...)` + `return { allowed: true, level: 'warn', … }`. Unless the opt-in `enforce_rbac` flag is passed, a role denied a capability still proceeds (`allowed:true`). This is the documented ADR-037 V1.0 default, but it is the exact pair of lines that make role-based authority non-blocking; the only HARD-deny path (`:373-374`) requires the flag, which the live callers (`backlog-trigger.ts:32`, `sprint-runtime.ts:31`) thread from config but defaults false.

- [inconsistent|low] `DetectorRegistry.runAll` is `async` but performs no `await` — `src/nervous/detector-registry.ts:177` — `async runAll(ctx): Promise<DetectorResult[]>` calls `detector.detect(ctx)` synchronously (`:181`, no await; `IDetector.detect` returns `DetectorResult | null`, `:86`). The Promise wrapper is gratuitous (every detector is sync). Harmless, but the async signature implies an I/O cost that does not exist and forces the caller (`observer.ts`) to await a pre-resolved value.

## Summary
nervous#1 holds the policy core of the proactive meta-orchestrator — the action registry, the authority matrix, and the decide→propose→dispatch bootstrap — and the audit shows the *governance escalations* in this cluster are built and tested but not wired into the live path. The risk-gate (`DecisionEngine.decide`'s high-risk→approve block) is genuinely dormant because the sole production caller (`bootstrap.ts:282`) never passes the `request` arg, and its enabling flag is read off an untyped config cast; the ENT-1 `authorizeExecution` bridge and `shouldDelay` quiet-hours suppression are both zero-caller despite full test suites, so a non-trivial slice of green coverage certifies unreachable code (the strongest dead-test signal). RBAC remains advisory by design — `checkWorkerAuthority` returns `allowed:true,level:'warn'` on violation unless the opt-in `enforce_rbac` flag is set — consistent with ADR-037 V1.0, but the soft line is explicit at `authority-matrix.ts:352/377`. The most actionable hygiene issues are the triple-duplication of authority primitives: two `isSafetyFloorAction` impls over two safety-floor constants, two same-named `checkWorkerAuthority` functions with incompatible signatures, and two divergent `ROLE_CAPABILITY_MAP`s across `nervous/` and `core/` — none currently broken, but each is a future divergence waiting to happen. The detector registry itself (`DetectorRegistry`) is correctly wired into `observer.ts:159`, so the detection-side plumbing is live; the gaps are concentrated in the approval/governance escalation layer, which today proposes and warns rather than gates.
