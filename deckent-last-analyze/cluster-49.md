## Findings

- [unwired|medium] `NervousHistory.markUndone()` has zero production callers — `src/nervous/history.ts:67` — `async markUndone(originalId, compensationDetail)` is referenced only by `tests/nervous/history.test.ts:110`; the live CLI `nervous undo` (`src/cli/commands/nervous.ts:741`) reimplements the compensation inline (`src/cli/commands/nervous.ts:418-430`: builds `id: undo-${target.id}`, `payload: { undoOf: target.id }`, then `appendHistoryRecord(root, undoRecord)`) and never calls the class method. `grep markUndone src/` → only history.ts (def+doc). The class undo method is dead in production; its passing test gives false confidence the canonical path is exercised.

- [inconsistent|medium] Duplicate undo-compensation implementations diverge — `src/nervous/history.ts:67-86` vs `src/cli/commands/nervous.ts:418-430` — both construct the same `{ id: 'undo-<id>', decision:'rejected', payload:{ undoOf:<id> } }` compensation record, but only the class path does a `findById` existence-check (`history.ts:69-71` throws `Record not found`); the inline CLI path skips that guard. Two sources of truth for one audit-trail operation → drift risk (a schema change to the compensation record must be made twice).

- [unwired|medium] `NervousHistory.indexToMemory()` never invoked in production — `src/nervous/history.ts:123` — Memory-V2 (SQLite FTS5) cross-source indexing of nervous actions; `grep indexToMemory src/` returns only the definition, callers exist solely in `tests/integration/memory-nervous.test.ts` (5×). The JSONL `append()` path (`history.ts:29`) is the only wired persistence; the advertised "Index … into Memory V2 (SQLite FTS5) for cross-source search" (`history.ts:114-122`) is dormant — nervous actions are NOT searchable via `deckent recall`.

- [dormant|medium] `NervousHistory.prune()` retention never runs → unbounded history growth — `src/nervous/history.ts:93` — `async prune(retentionDays=30)` rewrites the file dropping old records; `grep '\.prune(' src/` finds no caller (only `tests/nervous/history.test.ts:134`; unrelated `store.prune` hits are `MemoryStore`). The documented "Retention via prune: rewrites file dropping old records" (`history.ts:19`) is defined + tested but never scheduled → `NERVOUS_HISTORY_FILE` (`.deckent/nervous-history.jsonl`) grows without bound for the life of the project.

- [root-cause|high] `APPROVE_TIMEOUT_MS` is frozen at module-import time via TTY/env capture — `src/nervous/executor.ts:93-95` — `export const APPROVE_TIMEOUT_MS = detectAttendedSession() ? APPROVE_TIMEOUT_ATTENDED_MS : APPROVE_TIMEOUT_UNATTENDED_MS`; `detectAttendedSession()` (`executor.ts:79-88`) reads `process.stdout.isTTY` / `SSH_CONNECTION` / `TERM` exactly once when the module is first imported. A long-running daemon (nervous bootstrap) that imports executor.ts before a terminal is attached permanently uses the 5 s unattended window (`DEFAULT_APPROVE_TIMEOUT_UNATTENDED_MS`, `config.ts:240`). Runtime config can override (`bootstrap.ts:206` `nervousConfig.approve_timeout_ms ?? APPROVE_TIMEOUT_MS`), but the fallback default is import-time-captured env, not re-evaluated per session.

- [root-cause|high] Suggest-timeout auto-apply bypasses the `canAutoApply` veto that protects the approve path — `src/nervous/executor.ts:251-286` vs `src/nervous/executor.ts:408-425` — `handleSuggestTimeout`'s timer fires `await this.actionHandler(action.id, action.payload ?? {})` directly on expiry (`executor.ts:266`) with NO predicate consultation, whereas `handleApprove` calls `this.canAutoApplyMap?.get(action.id)` and honors `ok:false` as a veto before auto-applying (`executor.ts:416-423`). `suggest-5m` / `suggest-30m` are live policies (`src/nervous/authority-matrix.ts:42,58,74` map risk→suggest), so a low/medium-risk action auto-applies unconditionally on timeout — trust-without-verify on the suggest path while the same safety predicate guards `approve`.

- [inconsistent|low] MCP→CLI fallback redefines success with a magic `>= 2` threshold — `src/nervous/dispatcher.ts:144` — after an MCP push fails and the CLI fallback succeeds, `allSuccess = deliveredChannels.length >= 2`; the main path defines success as "no attempted channel failed" (`dispatcher.ts:123,131`). The hard-coded 2 is opaque (assumes file+cli minimum) and diverges from the primary criterion — a config with only `{file,mcp}` that loses mcp can never reach `>=2` even though the operator still got the audit-log line.

- [root-cause|low] Default MCP adapter silently returns `false` — `src/nervous/dispatcher.ts:249-255` — `pushToMcp` returns `false` (no-op) when `this.mcpAdapter` is null, which is the default until the MCP server registers an adapter. If `DECKENT_MCP_ACTIVE=1` is set (`dispatcher.ts:97`) but no adapter has registered yet, every mcp channel push silently fails → `allSuccess=false`, and recovery depends on the conditional CLI fallback (`dispatcher.ts:139`). Silent-fallback acknowledged in-comment but observable as degraded delivery with no warning emitted.

- [inconsistent|low] `desktop` channel config is parsed but unroutable (no-op knob) — `src/nervous/dispatcher.ts:33,295,300` — `ChannelConfig.desktop?: boolean` is read from config (`channels.desktop ?? false`) and defaulted, but `type Channel = 'mcp' | 'cli' | 'file'` (`dispatcher.ts:25`) has no `desktop` member and `selectChannels` (`dispatcher.ts:164-187`) never pushes it. `grep desktop src/nervous` → only these 3 dispatcher lines. Setting `notifications.channels.desktop:true` has zero effect on dispatch.

- [inconsistent|low] Stale "until implemented" comment + duplicate type name `NervousHistory` — `src/nervous/executor.ts:20-25` — the local `export interface NervousHistory { append(record): Promise<void> }` carries the comment "Defined here until history.ts (Task 8) is implemented", but Task 8 is done: the `NervousHistory` class exists at `src/nervous/history.ts:21`. The name now collides (interface in executor vs class in history) and the comment is obsolete; the executor still consumes the narrow local interface instead of importing the implemented type.

- [unwired|low] `NervousIpcQueue.getBaseDir()` is a dead accessor — `src/nervous/ipc-queue.ts:137` — `grep getBaseDir` across `src/` + `tests/` returns only the definition; sibling accessors `getPendingDir()`/`getResolvedDir()` are referenced (test-only, `tests/nervous/ipc-queue.test.ts`), but `getBaseDir()` has zero callers anywhere.

- [inconsistent|low] IPC write-format SSOT bypassed by two sync reimplementations — `src/nervous/ipc-queue.ts:157` (`writeApproval`) — the canonical async producer is duplicated by `src/cli/commands/chat-nervous-bridge.ts:81` ("Replicates NervousIpcQueue.writeApproval logic with sync fs calls") and mirrored again at `src/api/nervous-endpoint.ts:85` ("Written synchronously … mirrors NervousIpcQueue.writeApproval's"). Three writers of the same pending-approval JSON shape → the filename/field contract (`ipc-queue.ts:160-172`) must be kept in lockstep across files; a format change in ipc-queue.ts alone would silently break the sync copies.

- [dormant|low] Detector pipeline gated to EXECUTE phase (intentional, documented) — `src/nervous/observer.ts:246,276` — `if (!this.activeInAnyPhase && sprintState.currentPhase !== DETECTOR_ACTIVE_PHASE) return;` (`DETECTOR_ACTIVE_PHASE = 'EXECUTE'`, `observer.ts:123`) skips ALL detector cycles outside EXECUTE; raw `observe` events still emit. By-design — the documented ~200-sprint self-feedback fix (`observer.ts:118-123`) and overridable via `activeInAnyPhase` (autonomous bootstrap). Recorded as a deliberate no-op-gate, not a defect: detectors are silent during PLAN/SPAWN/EVALUATE/FIX/RETRO/DECAY/CLEANUP of a hosted sprint.

- [dead-test|info] No skipped/tautological tests in the nervous suite — `grep '\.skip(|\.todo(|it\.skip|describe\.skip|xit(|xdescribe(' tests/nervous` → 0 hits across 56 test files. However `markUndone` / `indexToMemory` / `prune` (findings above) are exercised ONLY by tests with no production caller — green coverage on production-dead methods is a false-confidence signal, not a skipped test.

## Summary
- **dispatcher.ts** — 3 minor issues: dead `desktop` config knob (`:33,295,300`), magic `>=2` success heuristic in MCP fallback (`:144`), silent `false` from the default MCP adapter (`:249-255`). Core dispatch + dedup + bridge are wired (`bootstrap.ts:198,300`).
- **executor.ts** — 2 high-severity root-causes: import-time-frozen `APPROVE_TIMEOUT_MS` (`:93-95`) and suggest-timeout auto-apply bypassing the `canAutoApply` veto (`:251-286` vs `:408-425`); plus a stale duplicate `NervousHistory` interface (`:20-25`).
- **history.ts** — highest dead-surface concentration: `markUndone` (`:67`), `indexToMemory` (`:123`), `prune` (`:93`) are all test-only / zero production callers; the CLI duplicates undo inline (`cli/commands/nervous.ts:418-430`). Only `append`/`readAll`/`findRecentReversible` are live.
- **ipc-queue.ts** — healthiest: `writeApproval`/`startPolling`/`readPending`/`markResolved` fully wired (`bootstrap.ts:221`, cli/mcp/connectors). Lone dead accessor `getBaseDir()` (`:137`); write-format duplicated by 2 sync reimplementations outside the module.
- **maintenance-ops.ts** — clean: all 5 ops (`rotateSprintLogs`/`invalidateDocCache`/`cleanIpcDirs`/`pruneDeadEventStream`/`generateDebtTrendReport`) wired into `action-handlers.ts:264-273`. No findings.
- **observer.ts** — structurally sound; the EXECUTE-only detector gate (`:246,276`) is a documented, overridable no-op-gate (not a defect). `DirectivesProtectionDetector` singleton wired (cli/mcp/sprint-controller).

**Totals:** 14 findings — unwired 3, dormant 2, inconsistent 5, root-cause 3, dead-test 1 (info). Severity: high 2, medium 4, low 7, info 1. No source changed (read-only audit).
