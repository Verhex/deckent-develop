### root-cause
- [root-cause|high] Self-project guard turns git rollback safety into a silent no-op — `src/orchestra/rollback.ts:107-116` (and `:178-181`) — when `detectDeckentRepo(projectRoot)` is true, `createSafetyPoint` returns a synthetic `SafetyPoint` with NO backup branch created and `wasClean: true` hardcoded (never checked), and `rollback()` returns `{ success: true, message: '...git mutation skipped' }` without any `git reset`. Consequence: a NO_GO sprint in the deckent dogfood tree reports a *successful* rollback while the working tree stays fully mutated — the rollback guarantee is OFF precisely where deckent edits itself. ADR-039 makes the skip intentional, but the guarantee is soft AND silent (success=true masks the no-op).
- [root-cause|medium] "confidence" is a sample-count proxy, not statistical confidence — `src/orchestra/rule-evolver.ts:112` (and `:136`) — `const confidence = Math.min(0.5 + intentData.tasks * 0.04, 0.95)`; confidence is a pure function of sample COUNT, independent of variance/effect-size. 9 same-intent tasks → 0.86 ≥ `AUTO_APPLY_CONFIDENCE` (0.85, :32) → `status: 'auto-applied'`, and auto-applied rules are injected into live routing activation configs (`sprint-planner.ts:531-552`). Volume alone crosses the auto-apply gate — a noisy 9-task streak hard-edits routing.
- [root-cause|low] Partial-promotion gate accepts 50% test failure — `src/orchestra/result-promoter.ts:37` (gate at `:100`) — `const VITEST_MIN_PASS_RATIO = 0.5;` then `if (vitestResult.passRatio < VITEST_MIN_PASS_RATIO) return { promoted: false }`. ## Summary
This cluster shows deckent's evaluation/recovery seam carries real dead weight and a handful of guarantees that are softer than their docstrings claim. Four exports are flat-out unwired (`ResultMerger`, `rollback.getDirtyFiles`/`getCurrentBranch`, `rubric-registry.getEffectClass`+registry, `RuleEvolver.loadRules`), and two subsystems are dormant — skill-pair synergy detection emits zero rules and the proof-of-function rubric criterion is inert decoration that the Smoke gate never reads. The most consequential issue is the ADR-039 self-project guard (rollback.ts:107-181): in the dogfood tree it makes `createSafetyPoint`/`rollback` silent no-ops that still report `success: true`, so deckent has no real git-safety net exactly when it edits itself. Secondary root-causes — sample-count-as-confidence auto-applying routing rules from 9 tasks, and a 50%-pass partial-promotion gate — and a same-module task-type derivation split (`getRubric` vs `coverageOptional`) round out a picture of accreted scaffolding (ADR-055 placeholders, "PROMOTE-W2 deferred" stale headers) sitting alongside live code without enforcement.
