## Summary
This cluster shows the memory + model-registry core is functionally live but carries two classes of structural debt. (1) **Aspirational-but-unwired surface**: `buildAutoQuery`, `registerDynamicProvider`, `MemoryStore.restore`, the `min_score` query knob, and the `TaskRecord`/`SummaryExportEntry`/`Relation` types are exported/documented (often with "Brain lifecycle"/"future integration" prose) yet have zero callers — the docs over-state what is actually wired. (2) **Type↔reality and SSOT softness**: the `RegistryProviderName` union excludes the live `'ollama'`/`openai-compat`/`deepseek` providers, forcing `as`-casts that let `ModelDefinition.provider` hold forbidden values; `ModelTier` is duplicated across two files; `change_type='patch'` escapes the `ChangeType` union; and `TIER_PROVIDER_MAP` is hardcoded behind a "derived from ModelRegistry (SSOT)" claim. The single highest-risk item is `strictTenantIsolation` defaulting to `false`, which makes multi-tenant read isolation a documented, opt-in-only guarantee that leaks NULL-tenant rows by default — and the catastrophic-decay `aborted` guard whose signal the only caller discards.
