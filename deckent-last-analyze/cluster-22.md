## Summary
This cluster is dominated by **orphaned/duplicate machinery**: `timeout-watcher.ts` is a wholesale unwired Sprint-145 prototype whose every constant now contradicts the live runtime-extension path in `sprint-phases.ts:evaluateRuntimeExtension` (cap 2/3, freshness 60/90, grant 50%/5min), and `tmux.ts` carries three dead exports (`startAuditor`, `sendKeys`, `buildClaudeCommand`) plus a deprecated-but-load-bearing constant — three of them guarded by stale `@internal`/`@deprecated` docstrings that misstate reality, and two by tautological tests. The genuinely-wired code hides softer guarantees than it advertises: `tmux.ts`'s "always write `.result`" trap word-splits on unquoted project paths, `token-counter.ts` silently drops the cache-creation tokens its own docblock promises, and `worker-liveness.ts` — a gate built specifically to avoid false NO_GO — has no process-liveness signal for the non-docker backends and falls back to trusting file mtime, so a quiet but live worker can still be declared dead. (Verified-clean: the `worker-liveness.ts:46` comment "90s matches RUNTIME_EXTENSION_HEARTBEAT_FRESH_S" is accurate — both are 90.)
