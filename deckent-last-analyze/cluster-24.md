### root-cause (the exact line that makes a guarantee soft)
- [root-cause|high] Tamper-evident audit chain uses ONE process-global head across all sprints/tenants — `src/core/audit-writer.ts:20` — `let chainHead = GENESIS_HMAC` is module-global; `writeAuditEvent` reads it unconditionally (`const prevHmac = chainHead`, l.96) and advances it (l.111) regardless of `sprintId`/`tenantId`. Production calls it with many distinct partitions (`'autonomous'`, `'process'`, enterprise sprintId, `MISSION_AUDIT_PARTITION`, rbac — see enterprise-endpoint.ts/authority-matrix.ts/rbac.ts). But `verifyAuditChain` (l.127) always anchors at `GENESIS_HMAC`. So once a process writes to >1 sprint, any single sprint's stream is a non-contiguous subset whose first record's `prevHmac` ≠ GENESIS → `verifyAuditChain(readAuditEvents(root, sprintId))` returns `intact:false, brokenAt:0`. The existence of `_resetChainHead` (l.58, "testing only") confirms the design leans on shared global state. The chain integrity guarantee is effectively soft for any real multi-sprint process.
- [root-cause|medium] In-source default HMAC secret defeats tamper-evidence — `src/core/audit-export.ts:45` — `exportAuditLog(..., secret = 'deckent-audit')` and `verifyHmacChain(..., secret = 'deckent-audit')` (l.76). The default key is a public constant in the repo, so a forger who knows it can recompute a valid `hmacChain` for tampered entries — the chain only proves integrity when a caller passes a non-default secret, which nothing enforces. (Impact currently theoretical because the export is unwired, see above.)
- [root-cause|medium] Audit-query tenant isolation is opt-in / default-open — `src/core/audit-query.ts:76` — RBAC runs only when `role !== undefined` (l.76); a `role`-less call performs ZERO access control. Even with a role, `strictTenantIsolation` defaults `false` (l.77) so a missing `tenantId` silently defaults to `'local'` (l.87) and is checked against `'local'`. The tenant-scoping guarantee holds only when the caller opts into BOTH `role` AND strict mode — the safe path is non-default.
- [root-cause|medium] Audit-write failures are silently swallowed at call sites — `src/core/audit-writer.ts:110` — `writeAuditEvent` absorbs all `writeEvent` I/O failures and returns `false` (l.82,110-114, documented "fail-safe"). But production callers ignore the boolean (e.g. `api/enterprise-endpoint.ts:242` `if (sprintId) writeAuditEvent(...)`; `nervous/authority-matrix.ts:364`; `core/rbac.ts:102`), so a dropped audit record is invisible — the audit-trail completeness guarantee degrades to best-effort with no signal.
- [root-cause|low] Synchronous subprocess spawns in live analyzer path vs ADR-087 async-I/O standard — `src/core/analyzer.ts:92` — `getFileCount` (l.92), `getAuthorCount` (l.123) and `getLOCCount` (l.136) call `spawnSync('git', ...)`, blocking the event loop during project analysis (`analyzeProject` runs at init/analyze time). Counter to ADR-087 (Async I/O & Test Hermeticity) and the karpathy CUSTOM "no spawnSync" direction; acceptable today only because `analyzeProject` is intentionally synchronous.

## Summary
core#2 splits cleanly into a heavily-wired enforcement spine (audit-writer.writeAuditEvent, auth-oidc/auth-jwks verification, planRetention) and a wide belt of never-shipped surface: the entire compliance-export module, the audit-query lineage helpers, the analyzer disk-cache, and most of the Anthropic "Safety Shield" client are exported and unit-tested yet have zero production callers — "✅ DONE" roadmap items that never reached a user surface. The dangerous pattern is the audit hash-chain: a single process-global `chainHead` across all sprints means per-sprint `verifyAuditChain` cannot succeed once two partitions are written, and an in-source default HMAC secret plus opt-in/default-open tenant RBAC make the tamper-evidence and isolation guarantees soft exactly where enterprise compliance depends on them being hard. Several module headers still advertise "zero callers" and "Node ≥18", so the code's own documentation has drifted from its wired reality.
