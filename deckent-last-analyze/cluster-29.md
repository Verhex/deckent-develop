### dormant
- [dormant|medium] doc-tracking scanner is config-gated OFF by default in the only automatic (sprint-end) trigger — gate at `src/orchestra/sprint-finalizer.ts:579` — `if (config?.doc_tracking?.sync_on_finalize !== true) return { ran: false };`. `sync.ts:7` declares `runDocTrackingSync` is "Used by the sprint-finalize hook and MCP", but the hook is default-OFF, so in production the whole cluster (`scanDocs`→store) only runs on an explicit `deckent docs track` invocation (`src/cli/commands/docs.ts:25`). The ADR-090 staleness DB is therefore stale-by-default unless a user opts in — the freshness signal it computes is dormant out of the box.

### inconsistent
- [inconsistent|medium] Duplicate-divergent git-date implementation (async core copy vs untouched sync CLI original) — `src/core/doc-tracking/git-date.ts:26` vs `src/cli/commands/sync.ts:37` — both implement the same `git log -1 --format=%aI -- <file>` + mtime-fallback logic; core uses async `spawn` (`git-date.ts:11`), CLI uses blocking `spawnSync` (`sync.ts:39`). The doc-tracking design explicitly called for consolidating the CLI util into `core/git-date.ts` so CLI imports from core (DRY + ADR-008 direction) — `docs/superpowers/specs/2026-06-18-doc-tracking-design.md:42,170` — but a parallel async copy was written and the sync one left in place. Two impls of one rule can silently drift.
- [inconsistent|low] `tracks` entries resolved divergently: globs filtered by `git ls-files` (tracked only), plain paths added unconditionally — `src/core/doc-tracking/code-drift.ts:32-37` — `if (t.includes('*')) { for (const f of all) if (matchGlob(f, t)) result.add(f); } else { result.add(t); }`. A brand-new **untracked** source file matching a glob (e.g. `src/**`) produces NO code-drift, while a plain path is always counted even if untracked or nonexistent. Same field, two contradictory inclusion rules.
- [inconsistent|low] `fm.status` cast `as DocStatus` without union-membership validation — `src/core/doc-tracking/scanner.ts:64` — `const status: DocStatus = (fm.status as DocStatus) ?? (isScratch ? 'temp' : 'active');`. `parseFrontmatter` stores raw strings (`frontmatter.ts:35`), so a bogus `status: whatever` in a doc flows through typed as a valid `DocStatus`; it is neither `temp` nor a recognized exempt value (`stale-scorer.ts:16`), so it is silently scored as an active doc. Opt/cast trusted as required-validated.
- [inconsistent|low] Config merge trusts JSON value types (null-coalesce only, no schema check) — `src/core/doc-tracking/config.ts:16-22` — `defaultRank: tracking.defaultRank ?? d.defaultRank`, `scoring: { ...d.scoring, ...(tracking.scoring ?? {}) }`. A wrong-typed value in `.deckent/settings/docs.json` (e.g. `defaultRank: "high"`, `sizeCapBytes: "2mb"`) is not null, so it bypasses the `??` fallback and is used verbatim downstream (e.g. `resolveRank` returns the string, `stat.size > config.sizeCapBytes` compares against a string). `Partial<DocTrackingConfig>` is consumed as if validated.

### dead-test

The test title promises the "non-null path" but the assertion explicitly permits `null`. This is the exact "passes spuriously" risk the Phase-2 plan flagged (`docs/superpowers/plans/2026-06-18-doc-tracking-phase2.md:238`); only the `tracked_code` (`:58`) and `plain.code_drift===null` (`:59`) assertions carry weight.
- [dead-test|low] Test title over-claims coverage vs assertions — `tests/core/doc-tracking/code-drift.test.ts:17` — title `'expands globs against tracked files and keeps plain paths'`, but the body only asserts the glob branch (`:25-26` `toContain('src/core/a.ts'/'b.ts')`); the "keeps plain paths" half (the `else result.add(t)` branch at `code-drift.ts:37`) is never exercised or asserted. The named-but-unverified path reads as covered when it is not.

### root-cause
- [root-cause|medium] Silent git→mtime→fresh fallback makes the age-staleness guarantee soft — `src/core/doc-tracking/git-date.ts:26-33` + `src/core/doc-tracking/scanner.ts:71-72` — when `gitLogDate` yields 0 (no git / error / timeout) `getFileGitDateAsync` falls back to `statSync(...).mtimeMs` (`git-date.ts:30`), and scanner then sets `last_updated = gitMs > 0 ? ... : nowIso` and `age_days = gitMs > 0 ? ... : 0` (`scanner.ts:71-72`). On a fresh clone / CI (mtime = checkout time) or any non-git context, every doc is reported `age_days = 0` / updated-now → silently FRESH; the age-based staleness signal disables itself with no warning emitted.
- [root-cause|medium] Frontmatter write failure swallowed with a comment that promises a warning never emitted — `src/core/doc-tracking/scanner.ts:85` — `try { await writeFile(abs, updated, 'utf-8'); } catch { /* warn-and-continue */ }`. The catch is empty; a permission/IO failure writing managed front-matter produces no log, no `skipped` entry, no signal — the doc silently keeps stale/absent front-matter while the scan reports success.
- [root-cause|low] Malformed config silently degrades to defaults with no diagnostic — `src/core/doc-tracking/config.ts:12-13` — `} catch { // missing/invalid → defaults }`. Bad JSON or a malformed `tracking` block in `.deckent/settings/docs.json` is indistinguishable from a missing file; a user who typos their config silently gets default behavior (trust-without-verify; misconfiguration invisible).
- [root-cause|low] 5s git timeout silently nulls the code-drift signal — `src/core/doc-tracking/code-drift.ts:14` + `:50` — `const timer = setTimeout(() => { p.kill(); done([]); }, 5000);` → empty file list → `if (files.length === 0) return null;`. Transient git slowness (large repo, cold cache, lock contention) silently yields "no code-drift signal" rather than an error; the absence of drift is indistinguishable from "git was slow." Same pattern in `git-date.ts:12` (timeout → 0 → mtime).

## Summary
The doc-tracking cluster is small, pure, and well-tested at the unit level, but its correctness rests on a chain of silent fallbacks (git→mtime→now, timeout→empty, bad-config→defaults, write-fail→swallow) that quietly turn the freshness/drift guarantees into best-effort signals with no observability when they degrade — the recurring root-cause theme. Two confirmed unwired exports (`resolveTrackedFiles`, `ageThresholdDays`, matching Phase-1 UNW-A221/A222) and a duplicate-divergent git-date impl (async core vs sync CLI, against the cluster's own design intent) show the module was added without folding into existing surfaces. The whole scanner is dormant-by-default in the sprint-finalize path (`sync_on_finalize !== true`), so in production the staleness DB only updates on manual CLI runs. Test quality is mostly hermetic-real, but two tests over-claim: a tautological `boolean|null` assertion and a title that names an unverified plain-path branch.
