- [root-cause|medium] adr-file-sync trust-without-verify: the H1 ADR number is captured but never validated against the filename despite a comment claiming it is — `src/core/adr-file-sync.ts:68` (comment "Filename-based ID (authoritative — H1 number is verified against it)") — `H1_PATTERN` (`:50`) captures group 1 = the `ADR-(\d+)` number, but `parseAdrFile` uses only `h1Match[2]` (title, `:81`) and builds the id from `filenameNum` alone (`:74`, `:108`). `h1Match[1]` is never compared to `filenameNum`, so a file `092-foo.md` whose body says `# ADR-001: …` is silently stored as `adr-092` with no mismatch detection. The "verified" guarantee in the comment does not exist in code.

- [root-cause|medium] agent success-count is reconstructed from a rounded float on every update — metric drift — `src/core/agent-pool.ts:486-488` (`const prevSuccessCount = Math.round(stats.successRate * prevTotal); const newSuccessCount = prevSuccessCount + (wasSuccess ? 1 : 0); stats.successRate = ... newSuccessCount / stats.totalUses`) — the integer success count is not persisted; it is re-derived each call from the stored (lossy) `successRate`. Over many `updateAgentStats` calls the `Math.round` round-trip can accumulate error, so the reported `successRate` slowly diverges from the true DONE/GO_WITH_TECH_DEBT ratio. A persisted integer counter would make the metric exact.

- [root-cause|low] `updateAgentStats` reloads the entire agent pool from disk to fetch one agent — `src/core/agent-pool.ts:477` (`const agent = this.getAgent(id);`) → `getAgent` (`:281-284`) calls `loadAgents()` which `readdirSync`+`readJsonSafe` over every persistent and temp agent dir — invoked per-agent per-evaluation. The single-agent stat update pays an O(N) full-pool disk re-read, an avoidable trust-the-cheap-path inefficiency in the evaluation hot loop.

## Summary
This cluster is the agent-pool/activation/ADR-seed spine of `core`, and the audit shows the recurring deckent failure mode: capabilities are *built and tested in isolation but never wired into the live pipeline*. Three exports (`AgentSelectionCache`, the Sprint 212-008 `getSkillAgentAffinityBonus`/`SKILL_AGENT_MAP` affinity signal, and `suggestNewAgent`) carry green unit tests yet have zero production callers — most damningly the affinity signal whose own comment and test claim it is "wired" into agent scoring while routing-engine never calls it. Truth-source divergence is the second theme: `ADR_SEED_DATA` is a Sprint-143-frozen snapshot (≤adr-039) that contradicts the live `docs/adr/*.md` set parsed by `syncAdrFilesToDb`, and `inferIntentsFromKeywords` still emits a `'testing'` intent the taxonomy deleted. The root-cause findings (unverified H1/filename check, float-reconstructed success metric, full-pool reload per stat write) reflect "trust-without-verify" comments and lossy/eager runtime paths that quietly soften the guarantees the surrounding code advertises.
