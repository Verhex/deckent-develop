# nervous#5 — nervous (panic-gate · proposer · recommendation-log · respawn-request · runtime-scope-check)

Read-only structural code-audit of 5 `src/nervous/` modules. Every finding carries `file:line` + a proving snippet; every zero-caller / no-op claim is grep-verified against `src/` (test + self-definition excluded). Source NOT modified.

## Findings

### unwired (zero production caller — grep-verified)
- [unwired|medium] `evaluatePanicGate` has zero production callers — `src/nervous/panic-gate.ts:135` — `export function evaluatePanicGate(opts: PanicGateOptions): PanicGateDecision {` — grep of the symbol returns only tests (`tests/config/nervous-reenable-safe.test.ts:30`, `tests/nervous/panic-gate-nonblocking.test.ts:51`) + self/docs; the live wire in `executor.ts:17,409,343` uses `awaitPanicGateApproval` + `isLockedPanicAction`, never `evaluatePanicGate`. The sync primitive ships + is tested but is unreachable from any runtime path (confirms prior UNW-A165).
- [unwired|low] `Proposer.clearThrottleState()` has no `src/` caller — `src/nervous/proposer.ts:130` — `clearThrottleState(): void { this.recentGroups.clear(); }` — grep returns only the definition + comment; no production caller. Consequence: the throttle map `recentGroups` (`proposer.ts:60`, `private readonly recentGroups: Map<string, number>`) is append-only in a long-running Brain — never cleared/pruned (latent unbounded growth; confirms prior UNW-A247).

### dormant (defined-but-unreadable / no-op gate)
- [dormant|medium] Severity filter reads `severityMin` via `unknown` cast off a field absent from the config type → permanent no-op — `src/nervous/proposer.ts:144` — `const minSeverity = (this.config as unknown as Record<string, unknown>).severityMin as Severity | undefined;` — grep `severityMin` over `src/**/*.ts` returns ONLY this file (line 144 + comments 8/69); nothing in config-load or `NervousSystemConfig` populates it. So `minSeverity` is always `undefined` → defaults to `'info'` (rank 0) → `passesSeverityFilter` (line 146) always returns true. Gate 2 (`proposer.ts:84`) never filters anything in production.
- [dormant|medium] `eventBus` emit path in scope-violation handler is dead under ESM — `src/nervous/runtime-scope-check.ts:42` — `const { eventBus } = require('../orchestra/event-bus.js') as { eventBus: ... };` — `package.json` declares `"type": "module"`, so `require` is undefined in module scope → `ReferenceError` on every call → caught at line 49 → only the `process.stderr.write` fallback (lines 50-53) ever executes. The structured `deckent-event` / `NERVOUS_SCOPE_VIOLATION` emit (lines 43-48) is unreachable dead code (`event-bus.ts` exists but is never imported here; confirms prior B11).

### inconsistent (stale comment / divergent convention)
- [inconsistent|low] Stale module docblock claims the panic-gate wire is still a "follow-up task" — `src/nervous/panic-gate.ts:33` — `// Caller note: the wire into ... sprint-controller.ts / spawn-backend* is a follow-up task — this module ships the protocol primitive + tests` — but `assertNotLethalWithoutApproval` is wired into `spawn-backend.ts:108` and `awaitPanicGateApproval` into `executor.ts:409` (Sprint 279). The comment is outdated for 2 of the 3 primitives.
- [inconsistent|low] Divergent nervous-artifact directory convention between two sibling queue files — `src/nervous/respawn-request.ts:17` (`RESPAWN_REQUESTS_FILE = '.deckent/nervous-respawn-requests.jsonl'`, directly under `.deckent/`) vs `src/nervous/recommendation-log.ts:20` (`RECOMMENDATIONS_FILE = '.deckent/nervous/nervous-recommendations.jsonl'`, under `.deckent/nervous/`). Two nervous feeds, two different path layouts.
- [inconsistent|low] `awaitPanicGateApproval` docblock vs code for locked actions — `src/nervous/panic-gate.ts:175` — comment: locked safety_floor actions "keep waiting until the marker is read OR an explicit interrupt arrives" — but the deadline timer resolves `'REJECTED'` for locked actions at the SAME `timeoutMs` (lines 204-211, `finish('REJECTED')`). Locked actions are given no extended/longer wait; they hit the identical deadline and are denied auto-proceed. "keep waiting" is misleading.

### dead-test (green-without-asserting-the-real-path / injects non-production field)
- [dead-test|low] Scope-violation "emit event" test is green only via the stderr fallback; the mocked `eventBus` is never invoked — `tests/nervous/runtime-scope.test.ts:55` — assertion `expect(eventEmitted || stderrWritten).toBe(true)` (line 80). Because `require()` always throws in ESM, `mockEmit` (line 59) is never called → `eventEmitted` is permanently `false`; the test passes solely on `stderrWritten`. The `vi.doMock('.../event-bus.js')` scaffolding (lines 60-62) is inert — the test titled "should emit violation event on deckent-event channel" never actually exercises that channel.
- [dead-test|low] Proposer severity-filter tests pass only because the test injects a field production never sets — `tests/nervous/proposer.test.ts:102` — `proposer = new Proposer(makeConfig({ severityMin: 'warning' } as Record<string, unknown>));` (also line 134). Production `NervousSystemConfig` carries no `severityMin` (see dormant finding), so these cases validate a filter path that is a no-op in the real runtime — coverage of a branch that production can never enter.

### root-cause (advisory-soft / trust-without-verify / silent-fallback — the exact softening line)
- [root-cause|medium] Panic marker presence treated as approval (trust-without-verify) — `src/nervous/panic-gate.ts:110` — `// Any present marker (even without an explicit decision field) is treated as approval` → `return 'APPROVED';` (line 114). Any readable marker that is not an explicit `reject`/`rejected` resolves `APPROVED`; a `{}`-shaped or decision-less marker grants approval. Approval is inferred from file existence, not from a verified accept decision.
- [root-cause|low] Timeout auto-proceed is the line that makes the gate non-blocking for non-locked actions — `src/nervous/panic-gate.ts:217` — `finish('TIMEOUT_AUTO_PROCEED');` — intentional (ADR-040: spawn path must never block forever), but this is the exact line where a non-locked action proceeds with no human approval once `timeoutMs` elapses.
- [root-cause|low] Advisory-mode default proceeds without blocking — `src/nervous/panic-gate.ts:154` — `return 'PROCEED';` — default `mode: 'advisory'` always proceeds for non-locked actions with a visible warning only; the gate is soft-by-default. (The `'blocking-with-timeout'` branch at lines 157-162 also just warns and returns `'PROCEED'`, so the `mode` param changes only the warning text, not the control flow.)
- [root-cause|low] Severity Gate 2 is a no-op gate in production — `src/nervous/proposer.ts:146` — `return SEVERITY_RANK[severity] >= minRank;` with `minRank` pinned to `SEVERITY_RANK['info'] = 0` because `severityMin` is never populated (see dormant finding) → every severity passes; the filter advertised at `proposer.ts:84` silently drops nothing.

## Summary
- **unwired (2):** `evaluatePanicGate` (sync primitive, 0 prod callers — only `awaitPanicGateApproval`/`isLockedPanicAction` are live-wired); `Proposer.clearThrottleState()` (0 prod callers → `recentGroups` Map never pruned, latent unbounded growth).
- **dormant (2):** Proposer `severityMin` read via `unknown` cast off a non-existent config field → severity filter is a permanent no-op; `runtime-scope-check` `eventBus` emit path is ESM-dead (`require` throws → always falls to stderr).
- **inconsistent (3):** stale "wire is a follow-up task" docblock (2/3 primitives already wired); divergent `.deckent/` vs `.deckent/nervous/` path layout across two feeds; "locked actions keep waiting" comment contradicts the resolve-`REJECTED`-at-same-timeout code.
- **dead-test (2):** scope-violation emit test green only via stderr fallback (mocked `eventBus` never invoked); proposer severity tests inject a `severityMin` field production never sets.
- **root-cause (4):** marker-presence ⇒ APPROVED (trust-without-verify); `TIMEOUT_AUTO_PROCEED` + advisory `PROCEED` are the soft non-blocking lines (ADR-040 by design); severity Gate 2 no-op.
- **Wired & healthy (no findings):** `recommendation-log.ts` (`recordRecommendation`/`readRecommendations`/`dismissRecommendation` all live — `action-handlers.ts:287`, `cli/commands/nervous.ts`, `api/nervous-endpoint.ts`); `respawn-request.ts` (`requestWorkerRespawn` ← `bootstrap.ts:177`, `drainRespawnRequests` ← `result-collector.ts:875`); `assertBrainScope` (← `observer.ts:157`, `dispatcher.ts:87`).
- **Cross-cutting theme:** the load-bearing soft-points are concentrated in panic-gate (3 of 4 root-cause lines) and are ADR-040-intentional (spawn must never block); the two genuine latent defects are the **Proposer severity filter no-op** (config field never wired into the type/loader) and the **ESM-dead eventBus emit** in scope-check — both pass their tests today only because the tests compensate for (severityMin injection) or tolerate (`|| stderrWritten`) the production gap.
