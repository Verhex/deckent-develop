# nervous#2 — Nervous System detectors (cluster 47)

Code-only audit (read-only) of 6 detector modules under `src/nervous/detectors/`:
`agent-routing-anomaly.ts`, `agent-routing.ts`, `build-failure-recurrence.ts`,
`dead-event-stream.ts`, `debt-trend.ts`, `directives-protection.ts`.
Every finding carries `file:line` + a proving snippet; cross-module wiring claims
were grep-verified against `src/nervous/observer.ts`, `src/orchestra/event-bus.ts`,
`src/orchestra/sprint-controller.ts`, `src/core/event-stream.ts`,
`src/nervous/detector-registry.ts`, `src/nervous/action-handlers.ts`,
`src/nervous/action-registry.ts`. No source was modified.

## Findings

- [root-cause|high] Sprint-lifecycle detectors are unreachable on the live emit path — channel mismatch — `src/orchestra/sprint-controller.ts:248` — `emitSprintEvent` does `eventBus.emit('deckent-event', { type, ... })` but the only eventBus listener is `eventBus.on('event', this.onEventBusEvent)` (`src/nervous/observer.ts:298`); grep finds **zero** `eventBus.on('deckent-event', …)` consumers anywhere in `src/`. — `SPRINT_PHASE_CHANGE` / `SPRINT_RETRO_COMPLETE` produced by the controller are emitted on a channel no one subscribes to, so the observer never converts them to an `ObserverEvent`. The 4 lifecycle-triggered detectors below (`agent-routing`, `agent-routing-anomaly`, `build-failure-recurrence`, `debt-trend`) thus never receive their trigger event from the controller.

- [root-cause|high] Even via the JSONL/`publish()` path the lifecycle source/type never matches — `src/nervous/observer.ts:306` — `const eventType = String(deckentEvent.type ?? deckentEvent.channel ?? 'UNKNOWN');` then `SPRINT_LIFECYCLE_TYPES.has(eventType)` (`observer.ts:309`, set holds bare `'SPRINT_PHASE_CHANGE'`/`'SPRINT_RETRO_COMPLETE'` at `observer.ts:31-36`). The real wire object `DeckentEvent` has **no `type` field** (`src/core/event-stream.ts:33-45`, only `channel`), and the channel value is the full code `'BRAIN→*:SPRINT_PHASE_CHANGE'` (`src/core/event-stream.ts:104`). — So on the `publish()`→`emit('event')` path (`src/orchestra/event-bus.ts:105`), `eventType` resolves to the `'BRAIN→*:…'` string → `SPRINT_LIFECYCLE_TYPES.has(...)` is false → `source='event-bus'` (not `'sprint-lifecycle'`) AND `event.type='BRAIN→*:SPRINT_PHASE_CHANGE'` (not the bare name). Every lifecycle detector's first two guards (`ctx.event.source !== 'sprint-lifecycle'` + `ctx.event.type !== 'SPRINT_PHASE_CHANGE'`) reject it. Combined with the finding above, the controller's bare-name emit reaches no listener and the JSONL stream's events carry the wrong source/type — the lifecycle detectors are dormant on both real paths.

- [dormant|high] `agent-routing` only fires at EVALUATE, but the observer skips the detector pipeline outside EXECUTE — `src/nervous/detectors/agent-routing.ts:56-61` — `if (ctx.event.type !== 'SPRINT_PHASE_CHANGE' || ctx.event.payload['newPhase'] !== 'EVALUATE') return null;` while the observer guards `if (!this.activeInAnyPhase && sprintState.currentPhase !== DETECTOR_ACTIVE_PHASE) return;` with `DETECTOR_ACTIVE_PHASE='EXECUTE'` (`src/nervous/observer.ts:123,246,276`) and `activeInAnyPhase` defaults `false` (`observer.ts:154`). — When the phase has advanced to EVALUATE the pipeline is gated off; under the default sprint-hosted observer this detector's trigger phase is exactly a phase where dispatch is suppressed (second dormancy layer independent of the channel mismatch above).

- [dormant|high] `agent-routing-anomaly` (SPAWN/EVALUATE) blocked by the same EXECUTE-only guard — `src/nervous/detectors/agent-routing-anomaly.ts:44-45` — `const newPhase = ctx.event.payload['newPhase']; if (newPhase !== 'SPAWN' && newPhase !== 'EVALUATE') return null;` — SPAWN and EVALUATE are both non-EXECUTE phases, so the observer's `EXECUTE`-only dispatch guard (`observer.ts:246/276`) drops the cycle before this detector can run, unless `activeInAnyPhase=true` (autonomous bootstrap only).

- [dormant|high] `build-failure-recurrence` (RETRO) blocked by EXECUTE-only guard — `src/nervous/detectors/build-failure-recurrence.ts:46-50` — `if (ctx.event.type !== 'SPRINT_PHASE_CHANGE' || ctx.event.payload['newPhase'] !== 'RETRO') return null;` — RETRO ≠ EXECUTE, so the observer guard (`observer.ts:246/276`) suppresses dispatch; the detector body is unreachable in the default sprint observer.

- [dormant|high] `debt-trend` (SPRINT_RETRO_COMPLETE) blocked by EXECUTE-only guard — `src/nervous/detectors/debt-trend.ts:29-30` — `if (ctx.event.source !== 'sprint-lifecycle') return null; if (ctx.event.type !== 'SPRINT_RETRO_COMPLETE') return null;` — RETRO_COMPLETE fires after RETRO (current phase ∈ RETRO/CLEANUP), never EXECUTE, so the observer guard suppresses dispatch in addition to the channel/source mismatch.

- [root-cause|high] `debt-trend` opens a new SQLite connection every detect and never closes it — `src/nervous/detectors/debt-trend.ts:38-39` — `const store = new MemoryStore(dbPath); const allMemories = store.getByType('memory');` — `MemoryStore` exposes `close()` (`src/core/memory-store.ts:1289` → `this.db.close()`) but `debt-trend.ts` never calls it (no `close` token in the file). Each `SPRINT_RETRO_COMPLETE` would leak a `better-sqlite3` handle; under repeated triggers this is an unbounded file-descriptor leak.

- [dormant|medium] `build-failure-recurrence` proposes an action the executor can never run — `src/nervous/detectors/build-failure-recurrence.ts:95` — `id: 'BUILD_FAILURE_INVESTIGATE'` — this id is absent from `ACTION_REGISTRY` (grep: 0 hits in `src/nervous/action-registry.ts`), so `dispatchAction` hits `if (!IMPLEMENTED_ACTION_IDS.has(actionId)) return unimplemented(actionId);` (`src/nervous/action-handlers.ts:308`, set = all registry ids `:103`), and the executor maps `unimplemented → failure` (`action-handlers.ts:353`). The suggested action is structurally non-executable (notify-only at best).

- [dormant|medium] `dead-event-stream` proposes three non-executable action ids — `src/nervous/detectors/dead-event-stream.ts:81,93,99` — `id: 'INVESTIGATE_STALL'`, `id: 'FORCE_EVALUATE'`, `id: 'KILL_WORKERS'` — none appear in `ACTION_REGISTRY` (grep: 0 hits) → all resolve to `unimplemented` via `action-handlers.ts:308`. Note `dead-event-stream` itself is the one correctly-wired detector here (cron source reaches the observer and EXECUTE is its active phase), yet every remediation it offers is a dead action id.

- [inconsistent|medium] Two overlapping agent-routing detectors double-fire at EVALUATE with divergent thresholds — `src/nervous/detectors/agent-routing-anomaly.ts:16` (`DEFAULT_ANOMALY_THRESHOLD = 0.80`) vs `src/nervous/detectors/agent-routing.ts:23` (`ANOMALY_THRESHOLD_RATE = 0.40`) — both read `.tasks/*.json`, both compute per-agent share, both fire on `newPhase==='EVALUATE'` (`agent-routing.ts:58`, `agent-routing-anomaly.ts:45`), registered from independent config keys `agent_routing` / `agent_routing_anomaly` (`src/nervous/detector-registry.ts:116-119,144-149`). — Any ≥80% concentration is also ≥40%, so when both are enabled the same condition yields two alerts with distinct group keys (`agent-routing:…` vs `agent-routing-anomaly:…`, no dedupe) and the same `SKILL_ROUTING_ADJUST` action — redundant, divergent severity (`warning` vs `high`).

- [root-cause|medium] `build-failure-recurrence` orders the "most recent N sprints" by lexical filename sort — `src/nervous/detectors/build-failure-recurrence.ts:140-144` — `readdirSync(sprintsDir).filter(f => f.startsWith('sprint-') && f.endsWith('.md')).sort().reverse().slice(0, this.recurrenceThreshold)` — string sort misorders non-zero-padded sprint numbers (`sprint-99` sorts after `sprint-147`; `sprint-9` after `sprint-100`). The "consecutive sprints" window therefore picks the wrong sprints once the counter passes 9/99, silently corrupting the recurrence count that gates the warning (`build-failure-recurrence.ts:79`).

- [root-cause|medium] `directives-protection` flags any DIRECTIVES.md under a hardcoded 2 KB as a template breach — `src/nervous/detectors/directives-protection.ts:15,60-63` — `const TEMPLATE_SIZE_THRESHOLD = 2000;` … `const isTemplate = size < TEMPLATE_SIZE_THRESHOLD || SUSPICIOUS_PATTERNS.some(...)` — a legitimately short DIRECTIVES.md (<2 KB) edited during EXECUTE/FIX trips a `severity:'emergency'` alert + auto-restore proposal purely on byte count. Magic-number heuristic with false-positive risk; not derived from content semantics.

- [dormant|medium] `directives-protection`'s emergency `DIRECTIVES_WRITE` auto-restore has no executor handler — `src/nervous/detectors/directives-protection.ts:95-103` — emits `id: 'DIRECTIVES_WRITE'` with `payload.autoRestore: true`. `DIRECTIVES_WRITE` is in the registry (`src/nervous/action-registry.ts:102`) so it is not `unimplemented`, but `dispatchAction`'s switch has no `case 'DIRECTIVES_WRITE'` (`src/nervous/action-handlers.ts:317-338`) → it falls into `RECOMMENDATION_ACTION_IDS` → `handleRecommend` (Brain proposal only, `action-handlers.ts:314-315`). — The "🚨 EMERGENCY: Restore DIRECTIVES.md from task JSON files" never actually restores anything from this detector; only a proposal is logged. (`canAutoApply` IS wired — `bootstrap.ts:212` → `executor.ts:416` — so the gate is real, but it gates an action with no effecting handler.)

- [dead-test|medium] Lifecycle-detector unit tests inject a synthetic ctx the live observer never produces — `tests/nervous/detectors/agent-routing.test.ts:38-39` (`source: 'sprint-lifecycle'`, `type: 'SPRINT_PHASE_CHANGE'`) and `tests/nervous/detectors/debt-trend.test.ts:31-32` (`source: 'sprint-lifecycle'`, `type: 'SPRINT_RETRO_COMPLETE'`) — the tests hand-build the exact `{source,type}` that the observer's `onEventBusEvent` cannot emit for real events (see the two root-cause findings above). — Detectors pass their unit suites while being dormant in production; there is no end-to-end test asserting an observer-emitted event actually reaches these detectors, so green tests mask the wiring gap.

- [inconsistent|low] `debt-trend` window comment contradicts the code — `src/nervous/detectors/debt-trend.ts:42-45` — comment: `// currentSprintNum dahil, windowSize kadar geriye git` ("current sprint inclusive") but the filter is `m.sprint_num >= minSprintNum && m.sprint_num < currentSprintNum` — current sprint is excluded. Harmless to behavior, but the comment misleads maintainers about the averaging window.

## Summary

- **Files audited:** 6 (all read in full); all 6 detectors ARE registered in `detector-registry.ts` (so none are registry-unwired). The defects are at the event-wiring and action-wiring seams, not registration.
- **Severity tally:** high ×6, medium ×6, low ×1 (14 findings).
- **Dominant root cause (high):** the 4 sprint-lifecycle detectors (`agent-routing`, `agent-routing-anomaly`, `build-failure-recurrence`, `debt-trend`) are doubly dormant — (1) the controller emits lifecycle events on the `'deckent-event'` channel that has no observer listener, and the JSONL/`publish` path carries `DeckentEvent` whose `channel='BRAIN→*:…'` never matches the bare-name `SPRINT_LIFECYCLE_TYPES`/`event.type` guards; (2) even if delivered, the observer's `EXECUTE`-only dispatch guard suppresses their SPAWN/EVALUATE/RETRO trigger phases. Their green unit tests inject an idealized ctx, hiding this.
- **Live detector:** only `dead-event-stream` is correctly wired (cron source + EXECUTE active phase), but all three of its remediation action ids (`INVESTIGATE_STALL`/`FORCE_EVALUATE`/`KILL_WORKERS`) are absent from `ACTION_REGISTRY` → `unimplemented`.
- **Resource bug (high):** `debt-trend` leaks a `MemoryStore`/SQLite handle per `SPRINT_RETRO_COMPLETE` (never calls `close()`).
- **Other root-causes:** lexical sprint-filename sort in `build-failure-recurrence` (misorders ≥ sprint-100); hardcoded 2 KB template heuristic in `directives-protection`; `DIRECTIVES_WRITE` "emergency restore" is proposal-only (no effecting handler).
- **Action-coverage gap:** of the 8 distinct action ids these detectors propose, 4 are not in the registry (`BUILD_FAILURE_INVESTIGATE`, `INVESTIGATE_STALL`, `FORCE_EVALUATE`, `KILL_WORKERS`) and the rest are recommendation/proposal-only — none of these detectors can trigger an auto-remediation effect.
- Read-only audit: no source files changed.
