## Findings

### src/agents/auditor.ts
- [unwired|medium] Re-export shim has zero production importers — `src/agents/auditor.ts:8` — `export { enforceAdrCompliance, type AdrViolation, type AdrComplianceResult } from '../orchestra/authority-enforcer.js';`. `grep "from ['\"].*agents/auditor" src/**/*.ts` → **0 matches**; the real symbol is defined at `src/orchestra/authority-enforcer.ts:573` and every live consumer imports it directly from `orchestra/authority-enforcer.js`. This file is a dead indirection layer (no caller routes through `agents/auditor.js`).
- [dead-test|medium] `tests/agents/auditor.test.ts` does NOT exercise `auditor.ts` — misnamed / mis-targeted — `tests/agents/auditor.test.ts:20-26` — imports `runHeartbeat, HeartbeatDaemon, readDaemonPid, stopDaemonByPid, validateCommand from '../../src/orchestra/heartbeat-daemon.js'`; it never imports `enforceAdrCompliance` nor `agents/auditor.js`. Net effect: the in-scope re-export shim has **zero test coverage** despite a same-named test file giving the false impression of coverage.

### src/agents/cross-sprint-analyzer.ts
- [unwired|high] Entire agents `CrossSprintAnalyzer` class has zero production callers — `src/agents/cross-sprint-analyzer.ts:43` — `export class CrossSprintAnalyzer {`. The only `new CrossSprintAnalyzer(...)` in `src/` is `src/cli/commands/evolve.ts:60`, and that file imports the **orchestra** twin (`src/cli/commands/evolve.ts:6: import { CrossSprintAnalyzer } from '../../orchestra/cross-sprint-analyzer.js';`), not this one. Only `tests/agents/cross-sprint-analyzer.test.ts` consumes the agents class → runtime-dead.
- [inconsistent|high] Duplicate exported `CrossSprintAnalyzer` / `CrossSprintReport` with divergent, incompatible shapes — `src/agents/cross-sprint-analyzer.ts:17` vs `src/orchestra/cross-sprint-analyzer.ts:34` — agents `CrossSprintReport` = `{ agentId, sprintsAnalyzed, successTrend, coverageTrend, taskTypeDistribution, bestTaskType, worstTaskType, improvementSuggestions }`; orchestra `CrossSprintReport` = `{ sprints, trends, analyzedSprintCount }`. Two same-named exports with contradictory contracts = import-ambiguity / wrong-twin risk (already realized — see prior unwired finding).
- [root-cause|medium] Silent-fallback swallows readdir/JSON errors → corruption is indistinguishable from "no data" — `src/agents/cross-sprint-analyzer.ts:89-91` (`} catch { return []; }`) and `:109-111` (`} catch { // skip invalid files }`) — a corrupt or unreadable `.brain/learning/*.json` yields 0 entries → `_emptyReport()` (`:52-54`), so a data-integrity failure is reported as a clean empty trend. Compounded by `evaluation: entry.evaluation ?? 'NO_GO'` (`:102`), which coerces any missing-eval row into a failure, biasing success-rate downward without signal.
- [dormant|low] `SprintEntry.durationMs` is loaded but never read — `src/agents/cross-sprint-analyzer.ts:105` — `durationMs: entry.durationMs,` populates the field (declared `:14 durationMs?: number`), yet no method references `.durationMs` (no trend, no suggestion, no aggregation). - [inconsistent|low] `_generateSuggestions` parameter `_taskTypeDistribution` is underscore-prefixed (convention = "unused") but is used — `src/agents/cross-sprint-analyzer.ts:187` declares `_taskTypeDistribution: Record<string, number>`, and `:218` reads it (`const typeEntries = Object.entries(_taskTypeDistribution);`). Same loose semantics would let `brain.ts`→`brain` match unrelated `brain*` paths.
- [dormant|low] `PermissionGuardFS.readFileSync` is declared + injected but never invoked — `src/agents/permission-guard.ts:5` (import), `:28` (interface member), `:33` (defaultFS) — the class body never calls `this.fs.readFileSync`; the only FS calls used are `existsSync` / `mkdirSync` / `appendFileSync` (`:206-214`). ### src/agents/prompt-analytics.ts
- [unwired|medium] Unified `PromptAnalytics` class has zero callers — `src/agents/prompt-analytics.ts:406` — `export class PromptAnalytics {`. `grep "PromptAnalytics" src/**/*.ts` → only the definition; production wires the two component classes directly (`src/api/evolution-endpoint.ts:44-45` `new PromptABTester(...)` + `new PromptMetrics()`). The "single entry point" wrapper (`:400-473`) is unused indirection.
- [dormant|medium] The A/B write+analyze lifecycle is dormant — only `getActiveExperiment` is wired — `src/agents/prompt-analytics.ts:75,122,129,152,205` — production (`src/api/evolution-endpoint.ts:50`) calls only `abTester.getActiveExperiment(...)`. `createExperiment` (`:75`), `assignVariant` (`:122`), `recordResult` (`:129`), `analyzeExperiment` (`:152`), `completeExperiment` (`:205`) have **no production callers** (grep: tests only). The experiment store can be read but is never populated or evaluated at runtime → the engine reports on data nothing writes.
- [root-cause|medium] `assignVariant` ignores its `_experimentId` and returns a pure coin-flip — `src/agents/prompt-analytics.ts:122-124` — `assignVariant(_experimentId: string): 'A' | 'B' { return Math.random() < 0.5 ? 'A' : 'B'; }`. Assignment is not tied to the experiment, not balanced, not sticky, and non-deterministic; the parameter exists only for signature shape. (Moot in production since the method is dormant, but a latent correctness trap if ever wired.)
- [root-cause|medium] `confidencePercent` is a fabricated pseudo-statistic, not a significance test — `src/agents/prompt-analytics.ts:182` — `const confidencePercent = Math.min(100, Math.round(diff * 100 * Math.sqrt(sampleSize)));`. It surfaces a "confidence %" with no p-value, variance, or proper test; the number is a hand-tuned product of score-gap × √n surfaced to API consumers via `/api/evolution/prompt-metrics`. Trust-without-verify metric.
- [inconsistent|low] Winner-diff threshold `0.05` is an inline magic number while siblings are named constants — `src/agents/prompt-analytics.ts:185` — `if (diff < 0.05) { winner = 'inconclusive'; }`. The module names `MIN_SAMPLES_FOR_WINNER`, `TREND_WINDOW`, and `TREND_THRESHOLD = 0.05` (`:52-54`) but the winner cutoff is a bare literal duplicating the `0.05` value with unrelated semantics → drift risk if one is tuned and not the other.
- [dead-test|low] The `assignVariant` "50/50" test is near-tautological — `tests/agents/prompt-ab-test.test.ts:106-119` — over 100 pure-random draws it asserts only `aCount > 20 && bCount > 20`; it passes for essentially any non-degenerate RNG and cannot detect that `_experimentId` is ignored (root-cause above). Asserts the implementation's randomness rather than any contract.

## Summary
22 lines read per file confirm a cohesive picture: the `agents/` cluster is dominated by **unwired duplicates and dead re-export shims**. Five of six files contain at least one zero-caller export — `auditor.ts` (shim), `cross-sprint-analyzer.ts` (whole class; CLI uses the orchestra twin), `permission-guard.ts` (RBAC class), `prompt-ab-test.ts` (compat stub), and `prompt-analytics.ts`'s unified `PromptAnalytics` + the entire A/B create/record/analyze lifecycle. Only `prompt-analytics.ts`'s `PromptABTester.getActiveExperiment` + `PromptMetrics`, and the `index.ts` barrel, are genuinely live. Highest-severity items: the duplicate divergent `CrossSprintAnalyzer`/`CrossSprintReport` (inconsistent|high) which has already mis-routed the CLI to the orchestra copy, and the unwired RBAC `PermissionGuard` (unwired|high) — the documented-but-never-wired ADR-037 V2 enforcement vehicle. Root-cause patterns: silent error-swallowing in `cross-sprint-analyzer` (`catch { return [] }`), the over-broad `.replace('.ts','')` self-mod prefix in `permission-guard`, and two trust-without-verify constructs in `prompt-analytics` (RNG-only `assignVariant`, fabricated `confidencePercent`). One mis-targeted test (`auditor.test.ts` tests heartbeat-daemon, not the auditor shim) leaves the shim's coverage illusory. No source was modified (read-only audit).
