## Findings

### unwired (zero production caller — grep-verified)

All ctor/verify coverage is test-only (`tests/api/terminal/auth-provider-oidc.test.ts`). Reserved spec §1d slot, but no runtime path reaches it.
- [unwired|low] `COMMAND_GUARD_LOCALHOST_HOSTS` export has no non-test consumer — `src/api/terminal/command-guard.ts:64` — `export const COMMAND_GUARD_LOCALHOST_HOSTS = LOCALHOST_HOSTS;` — grep over `src/**` returns only this line; sole reader is `tests/security/command-guard.test.ts:6/67-69`. The internal `LOCALHOST_HOSTS` set is used (line 56); the re-export is dead surface.
- [unwired|low] `matchCommandPatterns` export consumed only internally + by tests — `src/api/terminal/command-guard.ts:38` — `export function matchCommandPatterns(...)` — the only `src/**` caller is its own wrapper `checkCommandGuard` (line 57); the named export is exercised only by `tests/security/command-guard.test.ts`. Not dead (reachable via `checkCommandGuard`), but the public export is test-only.

### dormant (defined but unreachable / fed by a gate that is never satisfied)
- [dormant|high] `OutboundLimiter` (per-tenant outbound byte quota, invariant I5) never wired into prod — `src/api/terminal/outbound-limiter.ts:41` / `src/api/terminal/ws-gateway.ts:140` — `if (deps.limiter) { ... }` — the only `attachTerminalGateway` prod call (`server.ts:1608-1612`) passes `{ manager, auth, audit }` and omits `limiter`; grep `new OutboundLimiter` over `src/**` matches only `tests/security/outbound-limiter.test.ts`. So `deps.limiter` is always `undefined`, the whole `track→warn/kill` branch (ws-gateway:140-183) is dead, and `outbound.warn`/`outbound.kill` audit events can never fire in production.
- [dormant|low] `OutboundLimiter.usage()` / `reset()` have zero callers — `src/api/terminal/outbound-limiter.ts:80` / `:87` — `usage(tenantId: string): number {` / `reset(tenantId?: string): void {` — with the class itself un-instantiated in prod, these accessor/teardown methods are reachable from no `src/**` site at all.
- [dormant|medium] `AuthProvider.verifyClientCert` (mTLS hook) is defined + warn-gated but never actually invoked — `src/api/terminal/auth-provider.ts:34` / `src/api/terminal/ws-gateway.ts:53-62` — the live code only checks presence and warns: `if (!deps.auth.verifyClientCert) { console.warn('mTLS configured but not implemented — sub-project #3'); }`; the real call is commented out: `// Future (sub-project #3): await deps.auth.verifyClientCert(peerCert.raw)` (ws-gateway:59). No provider in the cluster implements it (`LocalToken`/`Oidc`/`Jwks` all omit it). The method is reachable from no runtime path.
- [dormant|low] `AuditAction 'session.exit'` is declared but never emitted — `src/api/terminal/types.ts:24` (`| 'session.kill' | 'session.exit' | ...`) — the PTY exit callback only mutates status: `(code) => { sess.meta.status = 'exited'; sess.meta.exitCode = code; }` (`session-manager.ts:73-76`) and records nothing. grep `session\.exit` over `src/**` hits only the type union. Siblings `session.create`/`session.kill` ARE emitted (`server.ts:1549/1576`); `session.exit` is an orphan variant.
- [dormant|medium] Manager-level audit sink (`ManagerOpts.audit`) never wired → command-guard `guard.block` unrecorded in prod — `src/api/terminal/session-manager.ts:102` — `if (this.opts.audit) { ... record({ action: 'guard.block', ... }) }` — prod constructs the manager without an `audit` opt: `new PtySessionManager(terminalBackend, { scrollbackBytes, idleTimeoutMs, maxSessions })` (`server.ts:1451-1455`). So even on the (already-no-op, see root-cause) command-guard path, the block would kill silently with no audit row.

### inconsistent (divergent default / duplicate / conflicting)
- [inconsistent|medium] `tenantId` audit attribution diverges within `ws-gateway.bridge` — `src/api/terminal/ws-gateway.ts:219` & `:250` hardcode `tenantId: 'local'` (guard.block input path, and session.detach on close) while the same function uses the resolved `tenantOf()` for `session.attach` (`:205`) and `outbound.warn/kill` (`:146/:171`). For a non-`local` tenant, attach/outbound events carry the real tenant but guard.block/detach are mis-stamped `local`.
- [inconsistent|medium] Same `guard.block` action emitted with two different tenant sources — `src/api/terminal/ws-gateway.ts:219` uses literal `'local'`, whereas the command-guard emitter (`action: 'guard.block'` at `src/api/terminal/session-manager.ts:106`) stamps `tenantId: s.meta.tenantId` (`session-manager.ts:107`, the real session tenant). One audit action, two divergent attribution rules.
- [inconsistent|low] Tautological length re-check after the regex already guarantees it — `src/api/terminal/prompt-guard.ts:24` — `if (m[0].length >= BASE64_MIN_LEN) {` — `BASE64_RE = /[A-Za-z0-9+/]{256,}={0,2}/g` (line 6) already forces ≥256 class-chars, so `m[0].length >= 256` is always true; the guard is dead/redundant (`BASE64_MIN_LEN` only meaningfully lives in the regex literal `{256,}`).

### dead-test (tautological / mock-only / covers a never-invoked path)
- [dead-test|medium] mTLS suite validates a seam that production never calls — `tests/api/terminal/auth-provider-mtls.test.ts:13` & `:43` — `expect(typeof withMtls.verifyClientCert).toBe('function')` asserts a function-ness on object literals/classes the test itself just defined (lines 9-12, 30-40); no test drives the real gateway call path because there is none (ws-gateway:59 is a comment). The suite green-lights an interface contract with zero integration reach.
- [dead-test|low] Tautological undefined assertions in the same file — `tests/api/terminal/auth-provider-mtls.test.ts:19` & `:26` — `expect(withoutMtls.verifyClientCert).toBeUndefined()` / `expect(provider.verifyClientCert).toBeUndefined()` restate that a property the test omitted is absent — structural tautology, not behavior.

### root-cause (the exact line that makes a guard soft / silent / trust-without-verify)
- [root-cause|high] Command-guard deny-list is silently bypassed for EVERY production session — `src/api/terminal/session-manager.ts:99` passes `host: this.opts.host ?? 'localhost'` and prod never sets `opts.host` (`server.ts:1451-1455` omits it), so at `src/api/terminal/command-guard.ts:56` — `if (ctx.host !== undefined && LOCALHOST_HOSTS.has(ctx.host)) return [];` — `ctx.host === 'localhost'` ∈ LOCALHOST_HOSTS → returns `[]` unconditionally. The entire shell deny-list (`rm -rf /`, `mkfs`, `dd of=/dev/*`, fork-bomb, `authorized_keys` write — PATTERNS, command-guard.ts:26-36) never fires; the I3 "default-deny on remote host" invariant is a no-op until sub-project #3 plumbs a real peer host.
- [root-cause|medium] WS gateway silently drops PTY output under backpressure — `src/api/terminal/ws-gateway.ts:139` — `if (ws.bufferedAmount > BACKPRESSURE_LIMIT_BYTES) return;` — output is discarded with no client frame and no audit, directly contradicting the I1 "client is always notified (no silent drop)" contract honored on the guard path (ws-gateway:224-231). A slow consumer loses terminal data with zero signal.
- [root-cause|medium] mTLS cert presented → warn-and-continue instead of deny (trust-without-verify) — `src/api/terminal/ws-gateway.ts:55-61` — when a client presents a TLS client cert but no `verifyClientCert` is configured, the handler only `console.warn(...)` and falls through to token auth; the presented certificate is neither verified nor rejected. A misconfigured-mTLS deployment fails open to token auth rather than fail-closed.

## Summary
- Severity: 2 high, 8 medium, 6 low across 5 categories (16 findings).
- **Highest-impact (root-cause|high):** the shell command-guard is a production no-op — `session-manager.ts:99` defaults `host` to `localhost`, and `server.ts:1451` never overrides it, so `command-guard.ts:56` short-circuits the entire deny-list. The guard only ever executes against tests that pass an explicit non-localhost host.
- **Largest dormant subsystem (dormant|high):** `OutboundLimiter` (I5 per-tenant quota) is fully un-instantiated in prod — `attachTerminalGateway` is always called without `limiter` (`server.ts:1608`), so ws-gateway:140-183 + the `outbound.warn`/`outbound.kill` audit actions are dead. Matches prior tracking (DOR-009).
- **Audit-attribution drift:** `ws-gateway.ts:219/250` hardcode `tenantId:'local'` while sibling events in the same function resolve `tenantOf()`, and the manager's `guard.block` (session-manager.ts:106) uses the real tenant — multi-tenant audit is internally inconsistent. Compounded by the manager `audit` sink never being wired (session-manager.ts:102) and `session.exit` never emitted (types.ts:24).
- **Reserved-but-cold seams:** `OidcAuthProvider` (auth-provider.ts:109), `verifyClientCert` (auth-provider.ts:34 / ws-gateway.ts:59), and the mTLS test suite are spec §1d/#3 placeholders with no runtime reach.
- **Verified-intentional (NOT findings):** `JwksAuthProvider.verify()` always returning `false` (auth-provider.ts:210-212) is documented fail-closed, and prod correctly prefers `verifyAsync` (server.ts:1521, ws-gateway:83) — so the sync deny is never the live path. `LocalTokenAuthProvider`/`OidcAuthProvider`/`JwksAuthProvider` deliberately ignoring `DECKENT_API_AUTH_DISABLED` is the intended no-bypass security invariant. `reapIdle()` skipping `kind==='deckent'` (session-manager.ts:148) is intentional (long-running sessions); the reaper itself IS wired (server.ts:1615/1633).
