## Findings

- [unwired|medium] `isTerminalEvent()` has zero production callers — `src/agent/events.ts:27` — `export function isTerminalEvent(e: AgentEvent): boolean { return e.type === 'turn-end' || e.type === 'error'; }`. `grep -rn isTerminalEvent src/` returns **only this definition** (no production import); the only consumer is `tests/agent/events.test.ts:6-18`. The loop ends a turn by `return`-ing after `yield { type: 'turn-end' }` (loop.ts:107) and never asks the helper "is this terminal?". Exported + unit-tested but dead in the live engine.

- [unwired|medium] `RuleStore.revoke()` implemented but never called in production — `src/agent/permission-store.ts:17` (iface) + `:123-128` (impl: `revoke(rule) { ...splice... if (persisted.length !== before) persist(...) }`). `grep -rn '\.revoke(' src/` yields no RuleStore callsite (the other hits — `cli/commands/rbac.ts`, `core/auth-session.ts` — are unrelated `revoke` APIs). Every live wiring stubs it: `loop.test.ts:32,111,130`, `session.test.ts:15`, `e2e-multi-tool-turn.test.ts:13` all pass `revoke: () => {}`. The grant path is wired (loop.ts:145) but nothing ever revokes a grant — a persisted "always" rule can only be removed by hand-editing `settings.local.json`. Tested in isolation (`permission-store.test.ts:46-57`), unwired live.

- [dormant|high] `ComposeOptions.lang` accepted + threaded but never read — `src/agent/identity.ts:32-35` declares `lang?: 'en' | 'tr'`, `:42` `composeSystemPrompt(opts: ComposeOptions)` — body (`:43-57`) reads only `opts.cwd`; `opts.lang` is referenced **nowhere**. `IMMUTABLE_CORE` (`:11-16`) is a hardcoded Turkish string. Callers pass it in good faith — `loop.ts:62` `composeSystemPrompt({ cwd: deps.cwd, lang: deps.lang })` and `run.tsx:200` `composeSystemPrompt({ cwd: process.cwd(), lang: lang as 'en' | 'tr' })` — so a user on `lang:'en'` still gets a Turkish system-prompt core. `tests/agent/identity.test.ts` never references `lang`. No-op parameter.

- [dormant|medium] Entire native loop is flag-gated default-OFF — `src/cli/repl/run.tsx:170-174` — `// Native-agent engine (... flag-gated: DECKENT_NATIVE_AGENT=1 or --native). Default OFF` / `if (isNativeAgentEnabled(process.env, process.argv.slice(2))) {`. `createNativeEngine` → `createAgentSession` → `runAgentTurn` are the **only** path into this cluster (session.ts:84, native-agent-bridge.ts:81), and that path is unreachable unless the env/flag is set. The shipped default REPL never executes `loop.ts`; the whole `src/agent/` engine is dormant-by-default behind one boolean.

- [inconsistent|medium] `COST_GATE_EXCEEDED` "shared vocabulary" is actually duplicated, not shared — `src/agent/guards/cost.ts:9-10` — `/** Shared with src/core/cost-gate.ts — same reason vocabulary across surfaces. */ export const COST_GATE_EXCEEDED = 'COST_GATE_EXCEEDED';`. The comment claims sharing, but `src/core/cost-gate.ts` does **not** import this const — it re-types the raw literal `'COST_GATE_EXCEEDED'` five times (`cost-gate.ts:65,144,167,192,208`). Two independent string sources for one "shared" code; a rename in one is silently divergent from the other.

- [inconsistent|low] `DEFAULT_MAX_ITERATIONS = 25` defined twice independently — `src/agent/guards/recursion.ts:7` `export const DEFAULT_MAX_ITERATIONS = 25;` vs `src/agents/agentic-worker-runner.ts:44` `export const DEFAULT_MAX_ITERATIONS = 25;` — same name, same value, two unrelated modules, no shared source. Drift-prone: changing the native-loop cap won't change the agentic-worker cap.

- [inconsistent|low] `'always'` token triple-overloaded — `src/agent/permission-policy.ts:53` `VALID_TIERS = new Set(['silent', 'confirm', 'always'])` (a **tier**) · `src/agent/permission-store.ts:11` `GrantLifetime = 'once' | 'session' | 'always'` (a **lifetime**) · `permission-policy.ts:21-22` `alwaysFloor` (a tool-name **list**). The loop uses all three in one block — `loop.ts:123` `tier = 'always'` (tier) and `:145` `resp.decision as GrantLifetime` where `resp.decision` may be `'always'` (lifetime). One word, three axes; reads as the same concept but isn't.

- [root-cause|high] `IMMUTABLE_CORE` promises rm-rf/force-push/secret never auto-run, but the programmatic floor covers only 3 `deckent_` tools — `src/agent/identity.ts:13-15` — `'always-floor (kill/cleanup/recover, rm -rf, force-push, secret yazımı) ASLA otomatik çalışmaz —'`, yet `src/agent/permission-policy.ts:21-22` `const SAFE_FLOOR: readonly string[] = ['deckent_kill', 'deckent_cleanup', 'deckent_recover'];` — `rm -rf`, `git push --force`, and secret-writes are **not** in `SAFE_FLOOR`. Worse, the self-modifying guard's `writeTargets` (`loop.ts:53-58`) inspects only `path`/`file_path`/`files` and **ignores `command`** (which `primaryResource` at `loop.ts:48` does read), so a `bash`-tool `rm -rf` / `force-push` is invisible to both the floor and the elevation. The "değiştirilemez" (immutable) guarantee for those three operations is therefore **model-advisory prompt text only** — nothing in code enforces it (trust-without-verify).

- [root-cause|medium] Cost guard is advisory by default — never trips unless a ceiling is configured — `src/agent/guards/cost.ts:38-43` — `costExceeded(state)` returns `{ exceeded: false, spentUsd }` whenever `state.ceilingUsd === undefined` (`:40` guard `if (state.ceilingUsd !== undefined && spentUsd > state.ceilingUsd)`). The ceiling is opt-in only: `native-agent-bridge.ts:51-63 resolveCostCeilingUsd` returns `undefined` unless `DECKENT_NATIVE_COST_CEILING` env or `native_cost_ceiling_usd` config is a positive number, and `createCostGuard` spreads `ceilingUsd` only when present (`native-agent-bridge.ts:77-80`). Out of the box the loop accrues tokens (`loop.ts:84`) but the hard-stop branch (`loop.ts:86-90`) is unreachable — a runaway turn has no cost ceiling by default. (Documented design, but a silent no-op gate for any user who never sets the knob.)

- [root-cause|low] Self-modifying guard elevates but never blocks — `src/agent/guards/self-modifying.ts:5-7,23` — `// It does NOT block — it forces a confirm.` and `return hit ? { elevated: true, ... } : { elevated: false, ... }`; the loop translates this to `tier = 'always'` (`loop.ts:123`) → at most an `ask`. So a deckent-source-corrupting write is gated only by a confirm prompt, and only when `detectDeckentRepo(cwd)` is true and the target arrives as a `path`/`files` arg (not via a shell `command`, per the `writeTargets` gap above). Soft by construction.

- [dead-test|info] No skipped/tautological tests in this cluster — `grep -n '\.skip|\.todo|\.only|expect(true).toBe(true)|toBeDefined()'` over `tests/agent/{events,guard-cost,guard-recursion,guard-self-modifying,identity,loop,permission-policy,permission-store}.test.ts` → **no matches**. The unit tests assert real behavior. The caveat is coverage *targeting*, not deadness: `events.test.ts` + `permission-store.test.ts` are the **sole** callers of `isTerminalEvent` / `RuleStore.revoke` (see unwired findings) — tests that keep otherwise-dead production exports green, masking their zero live wiring.
