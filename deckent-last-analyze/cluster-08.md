## Summary
Cluster orchestra#9 is two-faced: the V1 decision pipeline (`decision-engine` + `decision-steps/*` + `decision-replay`, and the read-side of `decision-logger`) is honestly-labeled dead code — `DecisionOrchestrator` is never instantiated and its step/replay helpers are transitively unreachable, while `sprint-planner` still persists v2 decision logs that nothing ever reads back. The live machinery (`dependency-scheduler`, `disk-verify`, `handleScopeCollision`, `DecisionLogger.log`) is genuinely wired and well-tested, but carries soft-guarantee seams: disk-verify's fail-open returns "no evidence" on git failure (softening the very synthetic-NO_GO rescue it exists for), `SpawnDecision`'s replan/continue branches are dead enum members, the dependency graph's Kahn wave indices are runtime-inert for dispatch (ADR-064), and stale self-documentation (`applyResolutionUnblock`, "three call-sites", and a blanket `@deprecated` header over a live collision-block gate) invites accidental deletion of a real safety path. Net: deckent's dead-code is mostly self-disclosed, but its honesty is uneven — the riskiest items are the misleading deprecation header masking a live gate and disk-verify's git-failure fail-open.
