Alperen (2026-06-04): konuştuğumuz/planladığımız/yaptığımız **her iş** `docs/MASTER-PLAN.md`'ye kayıtlanmalı — dağınık ayrı dokümana değil. Brainstorm'lanan tasarımlar bir §-bölümü (örn. §4A AS-2 multi-provider derin tasarımı), alt-sistem decompose'u §4B Sub-System Map (AS-1…AS-6), sprint'ler §10 sequencing satırı, yeni yetenekler §4 F-ID satırı olarak girer. §11'e "MASTER-PLAN = her zaman güncel proje defteri" governance kuralı eklendi.

**Why:** MASTER-PLAN zaten "single source of truth" (§1); ama pratikte iş dağınık dokümanlara düşüp drift yaratıyordu (Top-Risk #4 doc-reality drift). Tek-defter disiplini drift'i ve "neyi konuştuk/nerede kaldık" kaybını önler. deckent'in "tamamlanmış ürün = agentic run ecosystem" tezi (DIRECTIVES 224/225/226 + AS-1…AS-6) burada izlenir.

**How to apply:** Yeni bir tasarım/karar/plan netleştiğinde, oturumu kapatmadan ÖNCE MASTER-PLAN'e işle (uygun §-bölüm + gerekirse F-ID/§10 satırı + çapraz-ref). Eski roadmap dokümanları donmuş-tarihsel; status sadece MASTER-PLAN'de güncellenir. Spec konumu sorulduğunda default `docs/superpowers/specs/` yerine MASTER-PLAN tercih edilir (kullanıcı tercihi default'u ezer).
