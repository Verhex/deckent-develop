Alperen Telegram bot deneyiminden ("ne işe yarıyor ne anlaşılır konuşuyor, iğrenç") memnun değil → **baştan-sona re-arch** istedi. Referanslar: NousResearch hermes-agent (Python, aiogram + local Bot API), openclaw (Node/TS, local-first Gateway, per-agent session, DM pairing). Mevcut deckent zaten `connector-pool`+`bot-daemon`+gated-dispatcher iskeletine sahip; asıl dert deneyim katmanı (özellikle `bot-humanizer` — her mesajı LLM ile "doğallaştırıp" non-determinism + 8s latency + ham-log-fallback üretiyor).

**Program decomposition (onaylı):** 3 faz — Faz1 Ses&Streaming · Faz2 Yetenek&UX · Faz3 Transport&Gateway. Alperen **Transport-önce + tam gateway re-arch** seçti. Gateway re-arch 3 alt-proje: **G1** daemon+session · **G2** grammY+webhook+Discord-parity · **G3** session-aware agent routing. Onaylı kararlar: project-scoped sessions (chat→deckent project), topology A (control-plane daemon + per-project spawned children), explicit `/use` binding, global `~/.deckent/gateway/` home, two-level secret (bot=gateway-global, project-secret=child-local).
