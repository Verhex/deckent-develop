### 5.2 PR merge sonucu mu, branch HEAD'i mi?

İki workflow da `pull_request` ve `push: main` ile tetikleniyor. GitHub'ın resmi event contract'ına
göre `pull_request` koşusunda `GITHUB_SHA`, `refs/pull/<n>/merge` üzerindeki son sentetik merge
commit'idir; dolayısıyla required PR checks yalnız PR branch HEAD'ini değil, base+PR birleşik tree'sini
test eder ([GitHub — Events that trigger workflows](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request)). Ruleset'teki
`strict_required_status_checks_policy=true`, PR branch'in base ile güncel tutulmasını ayrıca zorlar.

Bu tree-level entegrasyon için olumludur. Fakat validator history-sensitive'dir. Squash/rebase/merge
sonucunda tree aynı kalsa bile commit topology değişebilir; required PR checks final main SHA üzerinde
yeniden bir pre-merge gate değildir. `push: main` workflow'u merge sonrası çalışır fakat başarısızlığı
already-landed commit'i geri alamaz. Ayrıca A'daki merge-introduction açığı doğrudan sentetik/gerçek
merge history bağlamında önemlidir.
